## Found on the way (not fixed: M0 changes no verdict)

1. **A global used in an export position is invisible to the module scan (a false-clean candidate, reproduced statically on the base build).** Oxc's semantic builder flags the identifier of `export default x`, `export { x }` and `export = x` as `Read | Type` ("can reference both type and value symbols", `oxc_semantic` `builder.rs` 2069-2073, 2094-2108, 2128-2136) and an unbound one keeps the `Type` flag. `scan_module` (`solid-facts/src/module_reach.rs`, the `reference.is_type()` skip at the head of the unresolved-reference loop) drops every reference that is a possible type. So `export default globalThis;`, `export { window as default };`, `export default eval;`, `export default Function;`, `export { Buffer }` record no escape, no code-generation hazard and no unknown global (probed with the real scan: `causes {}`, `hazards []`, `protoAny false`; the parenthesized `export default (globalThis);` and `const g = globalThis; export default g;` are seen). A second package that imports the binding then writes a built-in's prototype through it, which no scan sees as a prototype write (`g.Array.prototype.at = …`: `g` is an import, not the global).
   End to end on `dba9d3cee` (`/Users/thomas/dev/sc-scratch.noindex/mac20b/probe-export-default/`, run with `node run2.mjs <checker>` after `cp -c` of an installed `scripts/fuzz/install`): `fz-win-writer` replaces `Array.prototype.at` with a function that calls a Solid action; `App.tsx` calls `x.at(0)` on an `any` array in a component body. With `fz-win-export` = `const g = globalThis; export default g;` (`ctrl`) the checker reports `App.tsx:4 package-may-call-action:reaches-solid:prototype-any-untyped-member`; with `export default globalThis;` (`bare`) line 4 has no row at all (only the import's `package-finding-at-entry` at line 1). Chrome was not run; the direct-write twin `scripts/fuzz/patterns/pkgaction/proto-anyname-any` is Chrome-confirmed. A fix is to treat a `Read | Type` reference to an unbound name in an export position as a value read; the rediscovery shape is a package pair like the probe (`pa-shapes.mjs`).

2. **A computed read of a built-in's prototype makes the file an any-name writer.** `Array.prototype[Symbol.iterator]` and `Array.prototype[k]` (a read, not a write) are `prototype-handed-on/computed-read`: the scan takes the value for the prototype escaping (`global_use` returns `Escape` for a computed key it does not decide). It is a sound over-approximation only because the read's *result* may be a constructor (`P["constructor"].prototype.x = …` is otherwise unseen); 585 occurrences in 89 roots of the corpus. M5b below measures deciding the ones whose result is not called, not handed on and has no `prototype`/`constructor` read.

3. **A root is counted once per spelling.** A package a linker spells two ways (the `node_modules` link and the `.pnpm` real directory) or a declaration package and its runtime package (`@types/chai`, `chai`) are separate roots of `prototype_writers_any`: 629 writer roots are 349 packages (app-game 197 roots, 85 packages). Nothing depends on it today, but a decision per root (a ruling, a premise, a drop list) must name every spelling.

4. **Every counted writer is non-clear** (0 of 629 are clear roots), so the clear filter of `prototype_writers_any_name` removes nothing in this corpus; and no counted writer lacks a recorded cause (629 of 629 have one).
