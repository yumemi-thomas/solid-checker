# Open work

Open items only: known misses, decisions not to build, accepted precision trades, live approximations.
A rule `tsc` reports is removed and logged in `fixtures/tsc-oracle/`. Delete an entry here when fixed or reversed.
Case ids name directories under `fixtures/runtime-oracle/`; each `oracle.json` `open` list is section 1's executable half (a listed site that stops firing fails as `stale-open`).

## 1. Known open detections

- A block-bodied or imported hook, a hook result read any other way than a static member, and a literal holder read any other way are not followed to the primitive (ADRs 0480-0482 cover destructured slots, member calls and member store roots). On rc.0-rc.6 the readonly-root exemption trusts the declared type, so a hook or alias annotated with a non-readonly type (`(): { state: { v: number } } => ({ state })`) erases TS2540 and the root write is a false clean (also for `const s2: { v: number } = state`). A store imported from another module and aliased (`const a = shared`) is not seen as a store at all.
Defects the runtime reports and the checker does not. Each is a missing violation, not a false positive; the named rule should claim it. Codes are the runtime's.

Strict read in a setup body (`strict-read-untracked`, SC1001):

- `c2d-method-tracked` (App.tsx:19, :32): a function registered from a method or helper called in tracked JSX, then run by a later component body, keeps its registrant's lexical role. Same family: c2, c2c, c3d.
- `r10-destructured` (App.tsx:12): destructuring `useParams()` in setup reads the reactive parameter proxy, which the checker does not take as a reactive read.
- `r9-b3-childrenreadinbody` (App.tsx:14): the accessor returned by `children()` is called in the component body.
- `r9-d1-mixmemoslotreadinbody` (App.tsx:7): a helper builds a memo from a callback and reads `m()` in the helper body.
- `precision-ref-callback-read` (App.tsx:4): a read in an intrinsic `ref` callback runs untracked in the apply phase; the read rule places nothing in the `DirectiveApply` role.

- `@solid-primitives/utils` helpers over a getter, beyond `access(getter)` and `accessWith(getter)` (ADR 0338): `accessArray([getter])`, `withAccess(getter, fn)`, and `access` reached through another project helper's call hop are undecided, so they stay silent or uncertifiable. An alias (`const alias = count`), a function literal (`access(() => count())`) or a props value is arity-unknown and uncertifiable. A getter passed to a helper that reads its parameter in a hoisted function it calls is silent (fixture `package-access-helper`, `MissedHoistedCallee`).

Write in an owned scope (`no-write-in-pure-computation`, SC2001):

- A named handler both attached as `onClick` and called directly in the component body hides the write in a helper it calls; the runtime warns at that call.
- A helper that calls its callback and also runs it elsewhere (`cb(); createRoot(() => cb())`, `queueMicrotask(cb)`, a store) leaves a write in that callback uncertifiable under a null owner, a disposal or `untrack` (ADR 0457; rc.17 throws in the other run). A handler literal passed to such a helper (`onClick={() => both(() => setV(3))}`) stays silent: the run in the root is not followed.
- A setter call in a component's default parameter initializer runs in the owned component scope; the write rule places nothing there.
- An `onCleanup` handle that is stored, passed, aliased or returned, or a write in a member the callback builds (`const api = { f: () => setV(1) }; api.f()`), is uncertifiable where rc.17 throws at the call (ADR 0456, `write-cleanup-handle-call`). An alias of a named callback is not followed. On releases other than rc.17 every called handle is uncertifiable: their `onCleanup` return was not read.
- A violation at a site no execution reaches is uncertifiable (ADR 0458, handle calls included). Not read as unreached: a site after a call that always throws, a `try` that cannot complete, `undefined` or a `const` as a test, a module-scope function nothing references, a site whose only proof runs through an unreached call of a function also called elsewhere, an evidence step in dead code.
- False clean (fuzzer): a write behind a nested component or slot in a handle callback (`({ slot: c => c() }).slot(Child1)`), or in an `onSettled` in a `setTimeout` rendering `<Child2/>`.
- A closure named in an `onCleanup` callback and passed by name to `createRoot` there takes the callback's lexical role: an action it calls throws (no disposal exemption; fuzzer 8a3b250077, Chrome-confirmed) and is silent. An action written directly in a cleanup did not throw in the two rc.17 triggers probed (a memo rerun, a root disposed at top level: no ambient owner).
- SC2001 in `render`/`hydrate` `code` off web rc.13/17: uncertifiable (ADR 0353). Signals rc.17: a typed-only or `let`-aliased setter is unclaimed: `createOptimistic`'s unguarded one shares its type.

Store write outside a setter (`no-store-mutation-outside-setter`, SC2003; ADR 0425):

- `delete store.path` (ADR 0461) is reported only for a bare or parenthesized static member path whose property Type Facts proves optional and not readonly and whose links past the root get the assignment form's verdict (ADR 0465): a type assertion on the operand (TS2703), an element access (`delete store.rec[k]`, an index signature), an optional chain, a cast root, a `const` alias, and a non-optional property typed `T | undefined` (TS2790 under `exactOptionalPropertyTypes`) stay silent. `Object.assign`/`Reflect.deleteProperty` on a store are not built.
- The setter window is a dynamic extent (ADR 0476). A write in a function called inside the setter and also handed on, or in a callback given to a function this does not know, is uncertifiable, not followed. Still reported though it commits: a function called only from another module's setter (windows are per file), or reached by dynamic dispatch in the setter. Unproving every exported or handed-out writer would cover them, at every exported component's cost.
- Past the root (ADR 0465, 0476): a write through a link is uncertifiable, and silent where a link may be nullish under strictNullChecks (TS18048/TS18047): a link may hold a value the store does not wrap (frozen, non-plain), which no fact excludes; a proof from the store's initializer is built only where the setter is never referenced and no proxy of the store leaves as a value (ADR 0491); a store handed out through a hook, object or tuple stays uncertifiable (ADRs 0497, 0500 prove the destructured, tuple and member-read hook forms). Known miss: a write through a hook holder that is not an ADR 0481 member alias (the holder escapes, is written, or is read by a computed key) is silent, since nothing proves its root is the store (`store-write-literal-links`). Shared premise of every SC2003 violation, root or link (review, unprobed): rc.17's `writeOverride` is one module-wide flag a projection's draft operations raise (`dist/dev.js:2294`, `:6520-6542`), so a store write run from user code during one (a getter on another projection's seed) lands; no fact places a write outside such a window. Without strictNullChecks that is an internal result where strict `tsc` would report; no tsc-oracle case can pin it (fixture `store-write-chain-links-loose`). The effective strictNullChecks follows TypeScript 7 (`strict` on unless `false`), so in a project built with TypeScript 5.x and no `strict` key a nullish link is silent though its `tsc` is loose. `createOptimisticStore` results are treated as stores (unprobed on rc.17; upstream ignores them).
- Type-correct rebinding (`count = otherAccessor`, `store = { … }` on a `let`) is silent: the accessor-binding and accessor-member (`memo.a = 1`) arms are deleted, and the cast and same-type spellings are no proven defect.

Server directives (`valid-use-server`, SC7006; ADR 0427):

- The build plugin's version is not observable, so every claim is the audited rc.17 compiler's. A wrapped module-level export (dropped on rc.0-rc.2, a compile error on rc.3) is not reported on any release. Not built: the rc.17 compile errors for a class, enum, destructured or initializer-less export.
- A call or alias export whose value the facts do not show to be a function is uncertifiable; Type Facts callability at the export could prove it.
- The `clientWrappers` regex arm is a JavaScript subset: a pattern with lookaround, backreference or `\b` compares exactly where upstream matches.

`flush` in an effect apply (`flush-in-effect-callback`, SC2008). The runtime reports these; the rule does not claim the open shapes below (ADR 0341). Positions and premises: rule page `flush-in-effect-callback`.

- `createRenderEffect` re-runs and a returned cleanup report only on some runs (its first run is outside any flush); the rule cannot tell which run a call is in, so neither is claimed. The fuzzer's six `flush()` in a `createEffect` apply's returned cleanup (warned on the rerun, rc.17) are this shape.
- A helper with a handler, timer, module-level or exported caller, an alias or an argument use is not claimed, though its call from the effect is a no-op (the claim is universal, ADR 0341). `runtime-oracle/flush-in-effect-callback` lists the exported-helper case as `open`.
- A `flush` imported through another package's `exports` conditions, an apply passed by name or in a `{ effect }` bundle, and a helper in a callback given to an unmodelled consumer are not claimed.

Async read outside a loading boundary (`async-outside-loading-boundary`, SC5003):

- `r9-b3-childrenasync` (App.tsx:15): an async memo read flows through `children()` into JSX with no `Loading`.
- A read of an async accessor in a rendered local function is only uncertifiable (ADR 0462).

Missing owner (`missing-owner`, SC4001):

- `review-r1-owner-mix` (App.tsx:5, :13): one callback invoked through `runWithOwner` and as an event handler (the owner walk refuses the literal as a whole; same shape `review-r3-owner-double-call`), and a handler returned from `createRoot`, later dispatched with no owner. Since ADR 0472 an owner operation in a function its function returns, which no owner edge reaches, is uncertifiable rather than certified: no owner edge follows a returned function (a plain factory's result, or one returned through `runWithOwner`, `createRoot`, `untrack`, a memo compute or an effect compute) to its later calls, so the violation where that call is a timer or handler (rc.17 `NO_OWNER_CLEANUP`) is not proven, and a result called under an owner, in a root or never is uncertifiable too. Open: exact transport of the returned value to its calls (fixture `owner-returned-callable`).
- `review-r5-owner-class-control`, `review-r6-owner-default-control`, `review-r6-owner-jsx-getter-control`: a call in a class field, default parameter or JSX getter, which the owner walk refuses. `review-r7-event-array`: the typed `[handler, data]` event tuple is not followed by owner seeding.
- `review-opus5-t6-rest-timer-owner` (App.tsx:8): an effect created in a timer inside a `Show` callback. `review-opus2-o15-settled-class-field-new-in-timeout` (App.tsx:5): a class constructed in a timer; the field stays an uncertifiable SC3001.
- JSX in a `createEffect` apply (no `createRoot`), or in a helper creating a render effect an apply calls, makes an unowned render effect: `NO_OWNER_EFFECT`, which the owner walk does not place (oracle `flush-in-effect-callback`).
- `oracle-behaviour-primitive-in-directive` (App.tsx:13): an effect in the apply a named factory returns (`ref={leakingTrack(count)}`) is SC6001 only. The owner walk places only a ref expression's top-level functions (ADR 0345), so a returned closure gets no owner claim; an IIFE returning one is uncertifiable for SC6001.
- Invoked literals the owner walk misses: an IIFE in an instance field initializer (`ia-module`, App.tsx:17; a generator IIFE iterated by a spread, line 19); an IIFE in an object method or a constructor run by `new`, both reached from a timer (`ib-comp`, App.tsx:54, :58); an effect after an `await` in a loop or conditional, and an IIFE invoked after an `await` in its caller (`ic-await`, App.tsx:35–52, beyond the continuation rule of ADR 0333); and an IIFE called through `.bind(null)()` or a literal run by `Reflect.apply` (`ii1`, App.tsx:61, :65; ADR 0347 models only `.call`/`.apply`, so the runtime's `NO_OWNER_EFFECT` there is a missing finding).
- `Object.entries(ns)`/`Object.values(ns)` whose values the program calls: the functions reach it unnamed, so their detached callbacks are uncertifiable; telling called from uncalled needs invocation tracking (`owner-namespace-reachable`, `viaObject`).
- `missing-owner` (SC4001), recall lost: an unmodelled callback between leaves (`forEach`, `addEventListener`) misses `NO_OWNER_CLEANUP`; at probe k5 the wrongly coded SC3001 is gone.
- `missing-owner` (SC4001), recall lost: `onSettled(wrap(() => …))` (`solid2-precision`, `WrappedSettledCleanup`): a bodiless `wrap` is no identity wrapper (ADR 0346), so the cleanup in its literal goes unreported.
- rc.17, unclaimed: `PRIMITIVE_IN_EFFECT_CALLBACK`; `lazyModule` loader reads/writes; an `onHydrationEnd` write drained by `hydrate` in a root.

Untracked reads rc.17 leaves silent (SC1001, ADR 0443), not built: the index accessor of a default `mapArray` (`(item, i) => i()`, upstream case 41) is not a source, and `indexArray` was not probed (case 42); a read through a helper a map function calls follows the helper's callers (an obligation at most); a function a compute returns that the effect's apply calls (`createEffect(() => () => v(), fn => fn())`, probe 3a-2) is a stale read on rc.17 but needs the compute's return to flow into the apply parameter, which no summary models, so it is silent; `createRoot` inside a computation was not probed; a context provider reached through a package (kobalte, router) is not an exact `createContext` binding, so its `value` is unplaced.

Possible owner suspension (ADR 0357): skippable-await cleanups retain SC4001 obligations. Call-argument-specific take/skip proofs are unimplemented; callback delivery outside the model remains open.

Missing provider (`missing-context-provider`, SC4002, ADR 0352): a context is claimed only when no provider exists in the program. Not claimed: a reader above no provider when another provider exists (needs the closed component tree), open programs, escaped contexts, package contexts (kobalte, router, query), `createContext` through an alias.

SC1002 (`after-await-open`): a handler on a promise held in a variable; a `.then` on a `Promise<T>` not proven native; `Promise.race` of helpers; an async IIFE the computation awaits; `Promise.all(x.map(async …))`; a destructured or bound loader; router `query` flights; a catch join after statements; `Math.max(count())` after a functional setter. Each fires the runtime warning unproven (ADR 0340, 0349, 0350).


Forwarded sources (ADR 0370) are SC9012 `forwarded-to-undescribed-callee` only: dead branches, killed values and no-op wrappers are not pruned, and the `package-callee` context (SC9011 before ADR 0440) needs proofs of callee currency, the value reaching the call, the call running and the final callee. Both are internal obligations: `--certify` ignores them for users and nothing disables them.

Primitive used as a value (`reactive-dispatch-unresolved`, SC9012):

- Found only through a named or namespace import. Not followed: a stored or aliased namespace object (`const NS = Solid; NS.createEffect(…)`), a namespace import of a project barrel, a computed member (`S["createEffect"]`), an `import S = require(…)` member. Fix: a census where every TypeFacts reference of a primitive's symbol that is not a primitive callee is an obligation. No corpus site has these shapes.

`runWithOwner` with a disposed owner (`RUN_WITH_DISPOSED_OWNER`, rc.13 `dist/dev-shared.js:6919-6932`) is claimed by no rule. Proof needs an owner written once from `getOwner()` in a `createRoot` body that disposes it unconditionally, and every `runWithOwner` using it running after that body. Not built: no corpus site has one.

Other:

- Synchronous DOM calls that dispatch (`focus`, `blur`, `click`, `dispatchEvent`, form `reset`/`requestSubmit`, popover and dialog toggles) are refused. Not modeled and still trusted: custom-element reactions on tree mutation and attribute writes, and focus loss when a focused element is removed (ADR 0329).
- An argument of unknown provenance handed to a callee that calls its parameter (`access(value)` over a spread, held alias, `Array.from`, `[get][0]`, `(() => get)()`, a helper's return or a store property) is an SC9012 obligation unless proven not a getter (ADR 0338, `Unproven.tsx`). A member call on a primitive result is uncertifiable even for `.toString()`; a project call's result is not proven a non-getter even when every return is a number (`access(give())`), since its returns are not followed.
- Patching the array iterator's `next` changes how tuples destructure (`const [value] = createSignal(1)`), which every tuple proof reads as slot order. ADR 0282's veto covers project tuples only, so such a patch is not seen (the access proofs share the premise, ADR 0338).
- A context-provided value read through a package hook (kui `TopicsRoute.tsx:425`) stays an uncertifiable SC9012. Only the router's own provider is proven; a project provider or an `Object.defineProperty` replacement of the location getter both type-check (ADR 0289, 0312).
- `typeof window` in solid-query source blocks the proxy proof unless a Window realm is declared (ADR 0295, 0312).

- `no-write-in-pure-computation` (SC2001), recall lost (ADR 0452): a closure named in a memo or effect compute and called there, with code in its parameter list (`const f = (x = setOpen(true)) => x; f()`, or `(x = Math.random()) => setOpen(x)`), is an uncertifiable result, not a violation. The call graph holds no call sites for a function whose parameter list is not inert (ADR 0339), so nothing places the write. A literal default keeps the violation. The same holds for a default in an anonymous callback's own list, also one its caller always omits (ADR 0454: `((x = setV(1)) => x)()`, `createMemo((prev = setV(1)) => …)`), and for a forbidden call in an IIFE's default in a leaf callback (SC3001, one obligation at the IIFE). No proof that every caller omits the argument is built. `missing-owner` (SC4001) and the SC3001 leaf walk follow the same rule (ADR 0454): a cleanup, effect or context read in a list is uncertifiable, also in the own list of an `onSettled` callback, which rc.17 calls with no arguments (a proven violation would need the arguments a primitive passes as a dialect fact). Moves: an IIFE destructuring default in a component body (SC1001) and a closure called without the argument in a leaf callback (SC3001, now SC9012) went from violation to uncertifiable. A component's own list read (`function C(props, x = count())`) is uncertifiable, where it was silent. Costs of the owner placement (ADR 0454): a function literal invoked in a rendered component's own list (`m = (() => onCleanup(…))()`) is legal and uncertifiable (the in-place invocation is an edge with no source); a module-level helper whose default reads or writes, called without the argument where that is legal (tracked, from a handler), is uncertifiable.
- `no-write-in-pure-computation` (SC2001), recall lost (ADR 0455 cleanup amendment): a root or `runWithOwner` write in a function that is named, stored, a method or handed to a call this does not read, and that a cleanup may run, is uncertifiable on rc.17 (legal when the cleanup is the only caller), so a root helper also called from a component body (rc.17 throws) is no longer reported; nothing reads the helper's other callers. The same shape on a signals release nobody read is uncertifiable too (a called `onCleanup` handle is judged at its calls, ADR 0456). Missed violation, not a false positive: a hook that writes in a root and is called only from component bodies (`function useHook() { const [v, setV] = createSignal(0); createRoot(() => setV(4)) }`) was a violation and is uncertifiable (rc.17 throws there). Likewise a write in an effect's returned cleanup, under a proven owner on rc.17, is uncertifiable always: an effect that really reruns while its owner is alive throws, and goes unreported, because the checker cannot order the owner's disposal (a memo rerun, a `Show` turned off, a removed row) against the rerun, and the cleanup runs in a disposal then, where the write is legal (Chrome-confirmed false positives of the fuzzer, `write-owner-in-cleanup`). rc.13 and earlier still report it; a release nobody read keeps the old rerun proof.
- Fuzzer mount axis (ADRs 0506-0508): a child an inert parent renders plainly, under `<Show when={true}>` or in a one-row literal `<For>`, is mounted as its parent is. Not built: a non-literal `when`/`each`, `keyed`, `fallback`, an item row, `<Switch>`/`<Index>`.
- `pending-async-unsuspendable-read` (SC5001), partly built (ADRs 0467, 0504, 0505): a render-effect apply's first read of a source pending since the body is SC5001 under a module-scope mount (ADR 0504). A `createEffect` apply's first read is SC5001 only under ADR 0505's premises: a static first mount, and nothing before it that can create a node. ADR 0510 adds module-scope memos of creation-only modules and memos a parent hands over by an exact prop or one provider. Elsewhere it stays an obligation even where rc.17 throws: dynamic JSX, components, helpers, other module code, later renders, router or `hydrate` mounts, a `<Loading>` with `on` or a non-literal fallback, a hook that runs anything but creations or returns anything but a fresh object literal (ADR 0511),  and local hooks over handed or imported sources (SC9012 first; ADR 0511 follows `const` aliases and inline literal destructurings of both). Not to build (ADR 0511): tuples of them, which ADR 0282's string-code census refuses.
- `no-write-in-pure-computation` (SC2001), recall lost (ADR 0466): a callback passed by name is placed only through one exact binding; an alias (`const g = f; createMemo(g)`), a named function expression, a binding two primitive positions name, and a `const` named in a nested function (`onClick={() => createRoot(init)}`, which could run before the initializer) stay uncertifiable where rc.17 throws, and so does a render-effect apply passed by name (ADR 0460).
- `no-write-in-pure-computation` (SC2001), recall lost (ADR 0455): a closure with a default write called in a `createRoot` or `untrack` body with the argument omitted (`f()`, an IIFE), and a write under `runWithOwner(owner, fn)` with a bound `createOwner()` result or an owner that may be null, are uncertifiable; rc.17 throws for the first and the bound owner. A closure or literal an `untrack` callback only returns or stores (`const run = untrack(() => { const f = () => setV(1); return f; })`, called later from a handler: legal) is uncertifiable, where it was silent: nothing follows the returned value.
- `strict-read-untracked` (SC1001), silent (ADR 0452, 0454): a helper whose own parameter list calls an accessor parameter (`function read(get, x = get()) {…}` called as `read(count)`) has no summary row, since the call graph enumerates no call in a list, so a component body that omits `x` is not reported; a closure the helper builds and calls whose *body* calls the accessor is silent as well (`fixtures/reactive-ir/parameter-list-owner`, `ReadBodyClosureCalled`; main is the same). A closure with the call in its *default* is uncertifiable (`calls_parameter_in_parameter_list`).

- Every rule, silent (ADR 0459): a Solid API read through a destructuring other than a `const`, static-key, bare-slot destructuring of a value namespace import binding names no primitive: a nested pattern, a default, a rest element, a `let`, an exported slot, a namespace of a project module that re-exports Solid, a namespace held in another `const` (`const N = S; const { x } = N`), a pattern inside a pattern (`const { a: { b } } = { a: S }`), and a local value read through a literal (`const { useIt } = { useIt: read }`, the misuse fuzzer's local `destructured` binding).
- Every rule, silent or SC9012 (ADR 0463): a local value reached through anything but an exact `const` alias of a module-local `const` (`const a = r`, `const { a } = { a: r }`) is not its source: a `let` or `var` alias, a conditional, a parameter, an import, an exported alias, a `let` source, a literal with a spread, a computed key, a getter, a method or a repeated key, a default, a nested pattern. A direct read of a source before its own declarator (`[1].forEach(() => r()); const [r] = createSignal(0)`) is still reported as a read where rc.17 throws `ReferenceError` (a false positive this slice found and did not fix: the TDZ proof covers only function-valued bindings, namespace slots and aliases).
- Every rule (ADR 0468): a callee reached through a returned callable (`(void 0, q.bind(null))()`), an extracted method (`const fn = o.m; fn()`) or a conditional alias is not resolved; a logical or conditional callee over a local setter is SC9012, a member tail or reassigned `let` callee SC4001 uncertifiable.
- Every rule, silent (ADR 0468 review): an assignment or `await` callee (`(f = h)()`, `(x ||= h)()`, `(await p)()`) is not among the composite operands, so `h` gets no owner edge, reachability edge or local-access obligation (`let f = …; const h = () => onCleanup(…); setTimeout(() => (f = h)())` is silent while rc.17 warns; `(x = setW)(1)` in a memo likewise). Silent on main too.
- Strict-read and write rules, silent (containers RC8, RC10): a read or write in a component declared inside a memo compute, or rendered inside an `onSettled` called out of band, takes the enclosing callback's role (`callee_roles.rs` tracked-callbacks arm, `write_roles.rs` `nested_in_leaf_scope`) before the component-body fallback, so a proven component is treated as run in that callback. Fix direction: a shared "nearest proven component execution boundary" query (exact component identity), dropping allowed/tracked spans outside the component when its host provably enters the body (a Dialect question: memo compute yes, an out-of-band `onSettled` yes, an owned leaf no, which ADR 0475 makes uncertifiable). A draft exists outside the repo; its first coverage run moved eight fixtures, six of them to strict-read-untracked in dynamic-component fixtures, which must be reviewed against rc.17 before it lands.
- RC3 (missing-owner and others, silent): an IIFE in a class instance field initializer (`class K { x = (() => { onCleanup(…); })(); }`) runs at each `new K()`, but nothing activates a field initializer at its construction sites: the lexical IIFE edge is refused on purpose and there is no construction-to-field activation. A sound fix needs a construction witness (exact `new K()` sites, no subclass or unknown construction, static vs instance fields, decorators); research estimates a medium-to-large slice. Interim: an obligation-only repair (uncertifiable at such a site) would restore fail-closed.
- RC1b (missing-owner, silent): a call-valued callee `hf1(cb)()` in a timer, where `hf1` returns a function that calls `cb`: no owner edge combines the factory's returned closure with the callback captured for that specific call. Needs a per-call returned-closure identity (all returns the same function, no other escape); `factory()()` is not fixed by callee peeling (ADR 0468).
- `leaf-owner-forbidden-call` (SC3001), recall: JSX itself inside an owned leaf callback (`onSettled(() => { <Child2 />; })`) throws `PRIMITIVE_IN_FORBIDDEN_SCOPE` in rc.17 (rendering a component creates a transparent root, `dev-shared.js:1455-1495` rejects it under a leaf owner), but SC3001's census enumerates calls only (`cleanup.rs:240-342`), not JSX element creation. A claimed code, so a recall gap, not a policy one.
- `PRIMITIVE_IN_EFFECT_CALLBACK` (no rule claims it): JSX written in an effect apply (`createEffect(c, () => <div>{r()}</div>)`) throws in rc.17; SC1001 is silent there since ADR 0470 (the read is tracked), so the defect is unreported.
- Every rule (ADR 0475): a site in a root, primitive or component created in an effect apply or a leaf callback is uncertifiable, also where rc.17 runs it (an `onSettled` called out of band; an older prerelease without `PRIMITIVE_IN_EFFECT_CALLBACK`, as in `setter-in-root-rc3`/`-rc9`). A creation in a layer that also runs elsewhere, past an await, or in an effect cleanup inside the apply is not followed (a remaining false-positive shape where rc.17 refuses it). The apply refusal is not behind a Dialect question (invariant 4): on releases without it only recall is lost.
- Every rule (ADR 0472 review), fail-open: an owner operation in a function returned inside a conditional, a logical expression, an array or an object (`return c ? () => onCleanup(f) : undefined`, `return { run: () => … }`) is not marked and may stay clean.

Leaf body (`leaf-owner-forbidden-call`, SC3001):

- `leaf-owner-forbidden-call` (SC3001), recall lost: a primitive created under `untrack(() => …)` in a leaf body is not reported, though the runtime gives `PRIMITIVE_IN_FORBIDDEN_SCOPE`.
- `leaf-owner-forbidden-call` (SC3001), SC9012 obligations (ADR 0439; 561 in the rc.17 corpus): members of fields or call results, packages with no source, parameter or destructured functions, inherited methods, project constructors and DOM dispatchers (about 25) stay open. A std-library call without arguments in an imported helper or method has no resolved call (ADR 0192); demanding it everywhere cleared 7 and moved other rules. The plain `canvas.getContext("webgl")` is trusted though it fires an event.

## 2. Decisions not to build

- `UNCOMMITTED_INPUT_OVERWRITTEN` has no rule: rc.17 warns only when the DOM differs from Solid's last write (`@solidjs/web` `dist/web.dev.js:252`), that is, after the user edited and before an equal-value re-run. That is a possible order of two user actions, not a proven execution. Editability, commit paths (a ref listener, a directive, a delegated parent, a DOM write-back) and sibling sources that change with the value are each open-world. The runtime oracle and the fuzzer's `probes/uncommitted-input/` cover it. Reopen if a recorded uncommitted edit becomes a checker input.
- A write is not proven legal because every invocation of its function is an event dispatch: a synchronous `click()`/`dispatchEvent` from an owned scope runs the handler under that owner. About 110 corpus SC2001 obligations stay open. Reopen with an owner-at-dispatch fact.
- Host-origin proof (DOM objects handed to Solid helpers, `makeEventListener(window, ...)`) needs the premise that project code never installs members on host DOM objects; app-game has 1,232 unknown-key writes. Reopen when a sweep shows a violation hinging on it and the owner states the premise.
- Anonymous arrows as their own summary owners: they detached captured parameter member calls from the enclosing function and dropped the SC9012 an opaque caller keeps (control: `fixtures/reactive-ir/accessor-provenance/Anonymous.tsx`). Reopen when captured-parameter behavior and callback timing compose across source summaries (Relay's `() => props.environment`).
- A shared reference/identity layer (`Resolved<T> | Unknown`) is not started. Under ADR 0326 every false positive so far was a proof re-deriving "is this still the same value" (props aliases, `arguments`, `delete`, redeclaration, reassigned tags, views of props). Reopen when a proof needs that answer.
- Recall fixes for the section 1 oracle sites: zero corpus yield (no `useParams()` destructuring; every `children()` accessor is read in JSX). Reopen on a real hit.
- An inferred browser host keeps rc.17 `setLinkClaim`'s gap: ADR 0270 admits non-Vite scripts (`node server.js` calling `renderToString`).
- Inferring a `never` exit from a body: a call completes normally unless its signature is `asserts` or returns `never`, and a helper that throws undeclared is outside the model. Treating every helper call in a `try` as unproven would cost recall the owner declined (ADR 0279, option b). Reopen if a producer fact records inferred throws.
- Per-function reads of a handed file (ADR 0408): a chunk records the whole file it was handed, so an edit anywhere in it reruns the chunk. Reopen if hand-out reruns show in a profile.
- Cone propagation of the interprocedural summary, returned and factory fixed points on kept state (S7 design §5): they cost about 2 ms per app-game import edit (ADR 0407), about what diffing their definitions would. Reopen if their seeds become incremental.
- Partial re-attestation of import identities after an update the compiler did not make in place (ADR 0419 keeps the attestation only after an in-place one): an import, reference directive, module augmentation, ambient module or JSX runtime pragma edit, a two-file update, a rebase and a producer restart rebuild the chain and ask the producer's module graph for every file (about 25 ms on app-game). An edited file's ambient module or reference directive can change another file's resolution, so an unchanged importer is exact only with the producer's word on its resolution inputs. Reopen when the producer reports which files' inputs moved.
- A file system lookup cache that outlives a build (ADR 0418 keeps answers for one build only): exact only if every path it answers is observed by the resolution witness or the tracked stamps, failed probes included (extension probing, `@types` and typeRoots lookups, tsconfig `extends`); otherwise an install or a new file stays hidden. Would save the rebuild's 23,500 distinct lookups (about 150 ms of thread time per app-game import edit). Reopen with a test that lists the cache's keys and checks that each is witnessed.
## 3. Recorded precision trades

- A `createEffect` apply is taken to run with no owner (`missing-owner`, `primitive-in-effect-callback`): a `flush()` called synchronously under an owner, in project or dependency code, drains the queue under that owner, and an effect or memo the apply creates is then owned and does not throw (review of ADR 0483). Not vetoed: no census of synchronous flushes exists, and dependency calls are not in the facts.
A violation withheld, or turned uncertifiable, to keep zero false positives. Each loses recall on purpose.

- A refused file (ADR 0360) withholds each violation located or evidenced in it, even one its compiler facts cannot change.
- Instance field initializer: a violation whose primary location is in one is demoted to uncertifiable, whichever rule claimed it (`diagnostics.rs`, `site_in_instance_field`). Static fields and static blocks keep theirs.
- Code in a component's element children (`<Show>`, `<Loading>`, `<Errored>`, portals, wrappers rendering `props.children`) has no proven placement (`inside_component_element_children`); a read there is an uncertifiable `strict-read-untracked`, even where the runtime warns.
- `reactive-handler-frozen` (SC1007) on an element inside a tracked JSX expression or a component's children is uncertifiable: the listener is replaced when the scope re-runs.
- `async-outside-loading-boundary` (SC5003) through a forwarding wrapper that reads `children` with no `Loading` of its own is unresolved (`loading_cover_at`), as is a wrapper resolving `children()` outside any `Loading`.
- `no-store-mutation-outside-setter` (SC2003): a write through a 2.0 props object or a `merge`/`omit` view is uncertifiable: the compiler's props object is plain, so only a proxy drops the write.
- `no-destructure` (SC1003) with an unknown or mixed role is uncertifiable, not a proven snapshot.
- ADR 0509: a strict read of an async source whose first run is not proven pending (ADR 0504/0505) is uncertifiable: rc.17 throws the pending read first, and an apply that never re-runs never warns. Includes the `effect-apply-first-run` premise variants and `strict-read-async-apply`, which were SC1001; ADR 0510 proves module-scope and parent-handed memos pending; the shapes the SC5001 line lists stay open.
- ADR 0509's handed-member net: a call of a member of a caller-supplied value (context, hook result, props view) with no proof is uncertifiable where it would report a write, an action or an untracked read, including zero-argument calls in tracked JSX (`{api.name()}`); the repro cases `clean-context-provider` and `clean-store-draft` pay for it. A callee typed as a Solid accessor is exempt from the write half only. ADR 0511: a `const` alias of a prop now carries its direct twin's obligation (in a layer of a tracked scope it was clean).
- Code in or after a `for await` loop: an uncertifiable SC1002 (`after-await-suspended`), never a violation, though the runtime warns.
- SC1002 (ADR 0340) trades true positives for certainty. A read before the first await, through a call not seen into (a callee outside the audited inert rows, a value, method, getter or inline callback), makes a later read uncertifiable: `await fetchPosts()` over a `declare function` or package import yields none. Coercive or iterating standard-library slots need proven primitives (ADR 0348). A function that always throws without a `never` signature is assumed to return. A prop read before the await may share its getter's signal with a later one. Owner disposal is proven only through a `createRoot` `dispose` the code mentions; a parent that re-runs and disposes the computation, `render` disposal and `Object.defineProperty` getters are not seen.
- A signal read inside a JSX element passed as a prop does not make that prop reactive; reads of it are uncertifiable.
- A generator body is never placed where written, and a call to a generator runs none of it.
- A compound-component holder (`function Screen() { const Tabs = { Sub }; … }`), a holder in a project with a direct `eval`, or an `Object.assign` the project may replace stays uncertifiable (ADR 0331, 0342). An unrelated `Object.defineProperty(param, …)` or `xs[key] = v` on an unresolved object withholds every `Object.assign` holder (an accepted cost). Residual premise: `Object.assign` is not patched by string-built code or an engine hook.
- A function a ref expression writes at its top level that no proof places is uncertifiable, never a violation (ADR 0345): a generator, a callback handed to a callee no dialect slot describes, or a function evaluated without yielding.
- A tagless JSX-returning function is a proven component only where every reference is one ADR 0331's census accepts; others leave its body uncertifiable. Read: audited route components (ADR 0334, 0335) and compound members only JSX member tags reach (`Object.assign(Root, { List })`, ADR 0342). Not followed: `Object.assign(F, ...)` as a statement or `F.List = ...`, a holder named in a type or reached through a namespace import, an identifier-valued nested namespace. Not built: components built by a project call (`protect(X)`, `lazyScreen(...)`), `children` thunks, `2.0.0-next.21`, file routes (`fileRoutes(pageRoutes)`), and a TanStack exposure veto (one `props.component` read withholds it, ADR 0334). A component is a function `createComponent` calls (`precision-map-renderer`, `precision-method-renderer`).
- A read, write or action no fact places (`ExecutionRole::Unknown`) is an uncertifiable finding of its rule, never silent; `Unreported` (several non-reporting roles, or past the strict-read window or a dominating await) stays silent. A write in `catch`/`finally` after an await is uncertifiable unless the `try` starts by awaiting an async call with inert arguments (a synchronous throw otherwise reaches it unsuspended). So are `resolve`/`until` there (SC2004/SC2005), a read a helper makes after an `await` on some paths only (SC1002; a straight-line one is a violation, ADR 0340), and options the syntax cannot read beside an async computation (SC7002). A coverage rule disabled by options still blocks certification.
- SC1002 (ADR 0340) reports a read in an inline callback, a promise handler or an async helper the computation's promise carries, even on an empty receiver. Uncertifiable: a handler an `async` function returns unawaited over a possibly settled receiver, a fulfillment handler on an unproven receiver, a rejection handler, an unawaited helper whose first await is unproven, a `sort` comparator, a `reduce` without an initial value, and a `replace` replacer.
- SC2001 (ADR 0378, 0442): a write whose function has an unfollowed or unplaced entry is uncertifiable. A prop `Child` calls in its body is a violation (ADR 0442), and a function handed to a project helper takes the role of the call that handed it over. Open (ADR 0442): a prop `Child` destructures, spreads onto a component or reaches through a `merge`/`omit` view or a `let` stays an obligation; so does a literal handed to a helper that keeps it, to a package component known only by declarations, or to a primitive's callback slot; reads (SC1001) through a forwarded or aliased owned call stay uncertifiable (a direct body call is ADR 0204's); a registered test callback named by identifier is not followed. The answers are per build and cost about one pass over the functions handed to project code.
- Mixed invocation of one callback (owned setup and event dispatch) refuses the owner proof as a whole (ADR 0327). A callback run only by events is proven unowned.
- `missing-owner` (SC4001): a call written as an event handler or a primitive's callback (`onClick={makeHandler(count)}`, `onClick={untrack(() => …)}`, `createEffect(compute, makeApply(count))`) names no callback, so a literal inside it is not unowned and the call's own effects are silent. A call names its callee (ADR 0346) except identity wrappers such as `wrap(() => …)`; wrappers ADR 0346 refuses stay unplaced. Exact member/tuple and intrinsic-spread literals are placed (ADR 0358), and an intrinsic spread whose declared type has a complete key set with no listener key is not a handler site (ADR 0436); unresolved holders, getters, generators and unaudited web keys retain obligations. Open (ADR 0436): a spread typed `any` or `unknown`, through a type parameter, a conditional or `merge(...)` result, a reverse-mapped type, an `as`-clause mapped type other than `Omit<T, K>`, a mapped type the checker cannot close, or an index signature keeps the obligation, and member handlers (`onClick={props.onClick}`) are untouched. Joined creations (ADR 0359) exclude parameter-decided branches. Open: a call-valued callee's returned callable (`make(() => {})(() => s(1))`) stays uncertifiable, and ~150 leading-token `entities.at`/`get` sites are unaudited.
- `missing-owner` (SC4001), recall lost: in a closed program an exported function that nothing calls, and no namespace or dynamic-import read hands out, has no caller, so a `runWithOwner(null)` callback in it, and a ref IIFE inside that, is uncertifiable rather than a violation (`docs/rules/missing-owner.md`, closed-program paragraph). Other escapes leave exports dormant too: a named import passed as a value (`render(fn)`, `[fn]`), an anonymous default export, a barrel's re-export read through an unresolved namespace. Reuse ADR 0203's `entered_only_through_call_expressions` for the open seed (`owner_graph.rs`).
- `missing-owner` (SC4001): a ref IIFE inside a component's children is unproven, because the owner walk does not place children that run through the child getter (ADR 0345). A ref IIFE in a method or constructor that no resolved call names is uncertifiable for the same reason (`settle_eager_owners`), unless an owner region the compiler records answers it.
- `missing-owner` (SC4001), recall lost: an IIFE inside a function no owner edge reaches (a method or constructor no resolved call names, an unexported function nothing calls) is silent, since that function's context is zero. Module-scope and `runWithOwner(null)` IIFEs are reported (ADR 0347; oracle probes p3 N1, p4 V5).
- `missing-owner` (SC4001), uncertain reach (ADR 0347): a detached callback in an export that only an unnamed namespace escape reaches (`Object.keys(ns)`, passed along, spread, an alias, `export * as`, `require`, an unrecognized dynamic-import shape) is uncertifiable: whether the export runs is unproven. Recall is lost where the runtime warns and the program calls such an export (the `Object.entries` case in section 1).

Event delivery (ADR 0356, 0435): native `dispatchEvent`/`click` withholds event owner/execution proofs program-wide, except a dispatch on the global `window`/`document` (rc.17), in a scheduler callback, at module top level, in `runWithOwner(null, …)` (owner proofs only), in a function only events invoke (ADR 0437) or in a callback a reviewed test runner registers (ADR 0438). A dispatch in a function that is also called from a component body, or in any function nothing places, keeps the veto; other targets and emitters are unmodelled.
Test runners (ADR 0438): the premise is a reviewed reading of the published bytes of vitest 5.0.0 (the fixture pins the 5.0.5 declarations only) and 4.1.11 (`@vitest/runner`), playwright 1.63.0, jest-circus 30.5.2, mocha 11.8.0 and Node 24.22.1's `node:test`; `bun:test` is native and its suite bodies are not placed (a miss: bun 1.4.0 defers them); a jest, mocha, `node:test` or playwright suite body takes the registration's position, no longer a scheduled callback. A helper only test callbacks call (ADR 0438) is covered when it is neither exported nor handed to code the walk cannot follow; an exported test-utility module is followed in a closed program when every other module's reference is a call (ADR 0442: `fireAndFlush` in solid-groove's `testing/events.ts`, an async helper past its await and a factory's destructured member included, takes solid-groove's two held sites out of the veto), but a helper also called from an event handler is not covered, and an exported helper reached through a value use, a re-export specifier or an escaping namespace is refused. A runner configured to wrap tests in a Solid root, a patched runner, `test.step`, `test.extend` fixtures and `vi.mock` factories are outside it. The premise applies to every rule, not to the veto alone: a registered callback is a scheduled-callback role (no owner, no strict-read window), so a read or write there is judged as one in a `setTimeout` callback. An argumentless `el.click()` statement is not demanded for its resolved call, so it is unseen unless returned, in a leaf region or parameter-rooted.

SC6001 root lifetime (ADR 0355): explicit roots in ref apply remain uncertifiable, including disposed and empty roots. Proving live work and non-disposal is not implemented.

Recall trade (ADR 0354): first-iteration reads before a loop await and reads after an awaiting switch case remain uncertifiable.

- `leaf-owner-forbidden-call` (SC3001), precision (minor): a site in a dead tracked-effect body is claimed although the body never runs, when every path to its creation is an owned leaf body (probe m4, line 8). ## 4. Open questions and live approximations

- Import edits on app-game: the producer's update round trip is about 100 ms (module-graph work for the new specifier, producer side). The IR reruns 2 graph chunks and its result reads take about 13 ms, as for a code edit: the inserted line no longer renumbers the file's later local ids (ADR 0415; before, about 60 graph chunks and 65 ms).
- Body edits of an unexported declaration move its `Local` id (ADR 0415), so the two `function_for_symbol` buckets it leaves and joins (`hand_outs.rs`, 1024 buckets by a hash of the id) rerun their readers: app-game body edit reruns 77 graph chunks (28 before), wall +2 to +9 ms across two runs. Widening the buckets to 16384 restores the reruns but grows the bucket memos from about 9k to 24k and adds 13 to 20 ms to mid-file and import edits.
- Precision is measured on `fixtures/uncertifiable-repro` (ADR 0446), not on a corpus. Verified coverage: 45.3% of rc.17's sites (ADR 0448), 2,247 of them confirmed by experiment. Not covered: mechanisms under 10 sites (1,494 sites), 8 cases with second blockers, and `notReproduced`, each with why (packages beyond the budget, open-program families, a project-wide cause). Cause labels are the classifier's reading; a cause that depends on the whole project's sources can move another case in the same project, which `make repro-causes` shows.

- ESLint adapter: native analyzes the file on disk, while the adapter maps byte offsets onto ESLint's in-memory text. An unsaved buffer, or a later `--fix` pass, places findings wrongly.
- `feedback run` with an application `vite.config` on `@solidjs/vite-plugin` next.51+ refuses unless `performanceTracks` and `diagnostics` are off: their module scripts run before the collector. The collector default turns both off.

A package is assumed imported only through a declared dependency: a relative import out of its directory, a `tsconfig` `paths` alias or an undeclared hoisted install is not seen, and Deno and Bazel workspaces are not read, so such a private package still defaults closed.

Residuals: computed or reflective route-option keys (ADR 0334); a bundle-time patch by a Vite plugin or a `vite.config`-only alias (ADR 0324); callables on `Object.prototype` (ADR 0335); a caller that deletes or redefines a getter of its `this` when invoked as `props.onX()` (ADR 0337).
