## 1. Known open detections

Defects the runtime reports and the checker does not. Each is a missing violation, not a false positive; the named rule should claim it. Codes are the runtime's.

Write in an owned scope (`no-write-in-pure-computation`, SC2001):

- A named handler both attached as `onClick` and called directly in the component body hides the write in a helper it calls; the runtime warns at that call.
- A helper that calls its callback and also runs it elsewhere (`cb(); createRoot(() => cb())`, `queueMicrotask(cb)`, a store) leaves a write in that callback uncertifiable under a null owner, a disposal or `untrack` (ADR 0457; rc.17 throws in the other run). A handler literal passed to such a helper (`onClick={() => both(() => setV(3))}`) stays silent: the run in the root is not followed.
- A setter call in a component's default parameter initializer runs in the owned component scope; the write rule places nothing there.
- An `onCleanup` handle that is stored, passed, aliased or returned, or a write in a member the callback builds (`const api = { f: () => setV(1) }; api.f()`), is uncertifiable where rc.17 throws at the call (ADR 0456, `write-cleanup-handle-call`). An alias of a named callback is not followed. On releases other than rc.17 every called handle is uncertifiable: their `onCleanup` return was not read.
- A violation at a site no execution reaches is uncertifiable (ADR 0458, handle calls included). Not read as unreached: a site after a call that always throws, a `try` that cannot complete, `undefined` or a `const` as a test, an exported module-scope function or one in a script, a site whose only proof runs through an unreached call of a function also called elsewhere (an owner edge from a dead call still counts: a wrapper called live with no owner and dead under one is SC4002's), an evidence step in dead code. A lazy memo (ADR 0576) is read only by a direct call of its `const` accessor; a handed, exported or destructured-elsewhere accessor leaves its sites uncertifiable, and a read anywhere restores the creation-time model (a timing-sensitive claim at a memo first read late is not re-placed).
- False clean (fuzzer): a write behind a nested component or slot in a handle callback (`({ slot: c => c() }).slot(Child1)`), or in an `onSettled` in a `setTimeout` rendering `<Child2/>`.
- A closure named in an `onCleanup` callback and passed by name to `createRoot` there takes the callback's lexical role: an action it calls throws (no disposal exemption; fuzzer 8a3b250077, Chrome-confirmed) and is silent. An action written directly in a cleanup did not throw in the two rc.17 triggers probed (a memo rerun, a root disposed at top level: no ambient owner).
- A write in a closure the first step of a generator stepped at its own call runs in place (`(function* () { [1].forEach(() => setW1(7)); yield 1; })().next()` in a handler's root) is placed by the read arm, which stops at the generator (ADR 0521 places only the generator's own body). A bound owner's callback in a handler (`runWithOwner(boundOwner, …)`) leaves every layer unplaced, the stepped generator included.
- SC2001 in `render`/`hydrate` `code` off web rc.13/17: uncertifiable (ADR 0353). Signals rc.17: a typed-only or `let`-aliased setter is unclaimed: `createOptimistic`'s unguarded one shares its type.

Store write outside a setter (`no-store-mutation-outside-setter`, SC2003; ADR 0425):

- `delete store.path` (ADRs 0461, 0791) is a violation only for a static member path whose property Type Facts proves optional and not readonly and whose links past the root get the assignment form's verdict (ADR 0465); behind an optional chain it is uncertifiable. Owed, the proof: V where the producer can also prove acceptance (a resolved symbol the mirror passes; an index signature, where TypeScript asks nothing). A rejection both compilers suppress on its line is judged as if it type-checked (ADR 0830): V for an operand under an assertion or a rejected one. A nested path under a directive stays uncertifiable (the nullish-link premise is file-wide). A directive elsewhere in the file keeps a rejected operand uncertifiable, not silent (ADR 0829's file-wide premise).
- A rejection nothing reports (ADR 0830). Uncertifiable only, owed the proof: a rejected Solid primitive call or a cleanup-accepting callback's non-function return on a line a directive may silence (`refresh`/`affects` targets, an apply's or `onSettled`'s return; Chrome INVALID_REFRESH_TARGET, INVALID_AFFECTS_TARGET, REACTIVITY_HALTED), and in JavaScript, where `checkJs` is not in the facts, every one, V never. The fuzzer cannot claim these codes (INVALID_*_TARGET are out of scope, typed away; REACTIVITY_HALTED is a consequence): probes hold them. Uncertifiable too, never V: SC1005's positions TypeScript closes (a typed native attribute, a class object value, a computed key, an arithmetic, bitwise or relational operand) and SC7007's arity arm, on such a line. ## 2. Decisions not to build

- `UNCOMMITTED_INPUT_OVERWRITTEN` has no rule: rc.17 warns only when the DOM differs from Solid's last write (`@solidjs/web` `dist/web.dev.js:252`), that is, after the user edited and before an equal-value re-run. That is a possible order of two user actions, not a proven execution. Editability, commit paths (a ref listener, a directive, a delegated parent, a DOM write-back) and sibling sources that change with the value are each open-world. The runtime oracle and the fuzzer's `probes/uncommitted-input/` cover it. Reopen if a recorded uncommitted edit becomes a checker input.
- A write is not proven legal because every invocation of its function is an event dispatch: a synchronous `click()`/`dispatchEvent` from an owned scope runs the handler under that owner. About 110 corpus SC2001 obligations stay open. Reopen with an owner-at-dispatch fact.
- Host-origin proof (DOM objects handed to Solid helpers, `makeEventListener(window, ...)`) needs the premise that project code never installs members on host DOM objects; app-game has 1,232 unknown-key writes. Reopen when a sweep shows a violation hinging on it and the owner states the premise.
- Anonymous arrows as their own summary owners: they detached captured parameter member calls from the enclosing function and dropped the SC9012 an opaque caller keeps (control: `fixtures/reactive-ir/accessor-provenance/Anonymous.tsx`). ADR 0686 keeps the SC9012 at any call whose target reads a captured parameter, so what is left is a proof, not a hole: reopen when captured-parameter behavior and callback timing compose across source summaries (Relay's `() => props.environment`).
- A shared reference/identity layer (`Resolved<T> | Unknown`) is not started. Under ADR 0326 every false positive so far was a proof re-deriving "is this still the same value" (props aliases, `arguments`, `delete`, redeclaration, reassigned tags, views of props). Reopen when a proof needs that answer.
- Recall fixes for the section 1 oracle sites: zero corpus yield (no `useParams()` destructuring; every `children()` accessor is read in JSX). Reopen on a real hit.
- An inferred browser host keeps rc.17 `setLinkClaim`'s gap: ADR 0270 admits non-Vite scripts (`node server.js` calling `renderToString`).
- Inferring a `never` exit from a body: a call completes normally unless its signature is `asserts` or returns `never`, and a helper that throws undeclared is outside the model. Treating every helper call in a `try` as unproven would cost recall the owner declined (ADR 0279, option b). Reopen if a producer fact records inferred throws.
- Per-function reads of a handed file (ADR 0408): a chunk records the whole file it was handed, so an edit anywhere in it reruns the chunk. Reopen if hand-out reruns show in a profile.
- Cone propagation of the interprocedural summary, returned and factory fixed points on kept state (S7 design §5): they cost about 2 ms per app-game import edit (ADR 0407), about what diffing their definitions would. Reopen if their seeds become incremental.
- Partial re-attestation of import identities after an update the compiler did not make in place (ADR 0419 keeps the attestation only after an in-place one): an import, reference directive, module augmentation, ambient module or JSX runtime pragma edit, a two-file update, a rebase and a producer restart rebuild the chain and ask the producer's module graph for every file (about 25 ms on app-game). An edited file's ambient module or reference directive can change another file's resolution, so an unchanged importer is exact only with the producer's word on its resolution inputs. Reopen when the producer reports which files' inputs moved.
- A file system lookup cache that outlives a build (ADR 0418 keeps answers for one build only): exact only if every path it answers is observed by the resolution witness or the tracked stamps, failed probes included (extension probing, `@types` and typeRoots lookups, tsconfig `extends`); otherwise an install or a new file stays hidden. Would save the rebuild's 23,500 distinct lookups (about 150 ms of thread time per app-game import edit). Reopen with a test that lists the cache's keys and checks that each is witnessed.
- ADR 0973 (batch 11, slice 9B), SC1002, silences the owner left out (ruling 5): a **role silence** (a handler, a deferred callback, a test callback, a module-level function: `AfterAwaitRoleNotComputation`), a **read the walk's pre-await window already tracked** (`Tracking::Tracked`, `AfterAwaitReadAlreadyTracked`) and a read inside an **`untrack` callback** the walk crossed (`AfterAwaitUntracked`, which must keep a row for a read after an `await` inside `untrack(async …)`, which rc.21 still warns for). Each needs a typed premise whose span the proof log can confirm and a Chrome twin of its own; the corpus holds at most 49 sites of the first kind outside test callbacks (event handlers 8, `Unreported` 13, effect applies 5, tracked JSX 23), so the cost of leaving them out is small. Reopen with the premise and the twin.
- ADR 0973, a **census reason** (no tracked async computation in the program, `holds_suspending`, ADR 0963, and no package nothing here reads may run the function): built first, ended 0 of the corpus' sites, and not kept: the census is only as complete as the producers' index of computations, and Chrome shows starts the index does not find (`createMemo.call(undefined, work)`, `Reflect.apply(createMemo, undefined, [work])`, `[createMemo][0](work)`, a function declaration handed by identifier to a wrapper that gives it to `createMemo`: the oracle cases `after-await-universe-census-{call,reflect,element,wrapper}`), so it silently ended a read that runs as a computation. Reopen only with a proof that no computation runs the function (no value use of it, callers only module-level code or functions of the same kind), not the absence of a recognized start; the four cases and the fixture `after-await-universe-census` must keep their rows.
- ADR 0973, a **callee reason** (a call of a project function whose whole transitive closure reads no source the checker lists ends its site): built first, owner-ruled, and not kept: the review of #233 found it unsound. A read reaches a continuation through values no call shows, and the closure is a list of reads and calls: a store read through an alias binding, a stored generator object stepped by a spread, a `for…of` or a destructuring, a Proxy trap or a getter installed through a handler or a descriptor declared apart, a props alias (the oracle case `after-await-closure`, 12 programs and 11 twins on the first build). Making it exact asks for facts the checker does not have: an alias of a store or props value, a generator object and a value handed to a Proxy or to `defineProperty` by reference would have to count as "reads possibly", and every operation on a value of unknown type (a member read, a coercion, an iteration, a spread) would need the value shown plain: the type of the operand, or the arguments at every call site. Reopen with value facts (primitive-typed operands, argument purity, a store and props alias census); the programs of `after-await-closure` must keep their rows.

## What the server build does (ADR 0659)

Measured on rc.21; the input to `claims_client_runtime` and `ExecutionPaths`.

| API | Server build |
|---|---|
| `createEffect` | compute once, apply never |
| `createRenderEffect` | compute and apply both run |
| `createTrackedEffect`, `onSettled` | never run |
| `createReaction` | tracking callback runs, reaction never |
| signal, store setter | `SERVER_WRITE` warns, lands, no throw |
| direct store write | silent, lands |
| `flush`, `refresh` | no-ops |
| `resolve`, `until` | throw "not implemented on the server" |
| `isPending` | rethrows a pending read |
| `action` | returns `fn` unchanged |
| `render`, `hydrate`, `insert`, `ref` | throw "Client-only API" |
| strict window, write guard | absent |
| a pending read in a body | retried by the boundary; the body runs twice |
