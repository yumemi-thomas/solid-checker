## 1. Known open detections

Defects the runtime reports and the checker does not. Each is a missing violation, not a false positive; the named rule should claim it. Codes are the runtime's.

Value-use census (ADR 0692), accepted trade: a hook's object or tuple handed on past one hop (`value-forwarded`, `value-to-unresolved-callee`, `value-in-carrier`) is uncertifiable, 1,221 corpus sites. Reopen: follow holders through a second hop and through `Object.keys`-style calls that read no value.
Value-use census, owed proof: a store or props root handed to a function (a project helper, `value-root-in-helper`; a selected package's, `value-to-unresolved-callee`) is uncertifiable at the hand-off where the function reads or writes it (patterns `values/d8-pkg-plain-json`, `-member-read`, `-store-handoff`; their same-file twins too; Chrome STRICT_READ_UNTRACKED, STORE_WRITE_OUTSIDE_SETTER). A memo over a parameter or a callback prop that every caller fills with a settled value is uncertifiable (ADR 0802): `source_compute_open` does not follow the arguments yet. So does a memo whose compute calls a `.map` callback's parameter over a closed literal (`objects.map(item => item.read())`): the handed net does not follow it.

**Premise, ADR 0803:** a primitive's own array-pattern slots are exact unless an analyzed file writes visibly toward array iteration or obtains an intrinsic or code from a string (ADR 0801's census). Outside the model: a script element, a frame, and code not analyzed. Known held cost: a project whose dependency source or tests obtain an intrinsic (`new Function` in test helpers, `globalThis[key]` in a build plugin) holds every tuple slot, uncertifiable. Write in an owned scope (`no-write-in-pure-computation`, SC2001):

- A named handler both attached as `onClick` and called directly in the component body hides the write in a helper it calls; the runtime warns at that call.
- A helper that calls its callback and also runs it elsewhere (`cb(); createRoot(() => cb())`, `queueMicrotask(cb)`, a store) leaves a write in that callback uncertifiable under a null owner, a disposal or `untrack` (ADR 0457; rc.17 throws in the other run). A handler literal passed to such a helper (`onClick={() => both(() => setV(3))}`) stays silent: the run in the root is not followed.
- A setter call in a component's default parameter initializer runs in the owned component scope; the write rule places nothing there.
- An `onCleanup` handle that is stored, passed, aliased or returned, or a write in a member the callback builds (`const api = { f: () => setV(1) }; api.f()`), is uncertifiable where rc.17 throws at the call (ADR 0456, `write-cleanup-handle-call`). An alias of a named callback is not followed. On releases other than rc.17 every called handle is uncertifiable: their `onCleanup` return was not read.
- A violation at a site no execution reaches is uncertifiable (ADR 0458, handle calls included). Not read as unreached: a site after a call that always throws, a `try` that cannot complete, `undefined` or a `const` as a test, an exported module-scope function or one in a script, a site whose only proof runs through an unreached call of a function also called elsewhere (an owner edge from a dead call still counts: a wrapper called live with no owner and dead under one is SC4002's), an evidence step in dead code. A lazy memo (ADR 0576) is read only by a direct call of its `const` accessor; a handed, exported or destructured-elsewhere accessor leaves its sites uncertifiable, and a read anywhere restores the creation-time model (a timing-sensitive claim at a memo first read late is not re-placed).
- False clean (fuzzer): a write behind a nested component or slot in a handle callback (`({ slot: c => c() }).slot(Child1)`), or in an `onSettled` in a `setTimeout` rendering `<Child2/>`.
- A closure named in an `onCleanup` callback and passed by name to `createRoot` there takes the callback's lexical role: an action it calls throws (no disposal exemption; fuzzer 8a3b250077, Chrome-confirmed) and is silent. An action written directly in a cleanup did not throw in the two rc.17 triggers probed (a memo rerun, a root disposed at top level: no ambient owner).
- A write in a closure the first step of a generator stepped at its own call runs in place (`(function* () { [1].forEach(() => setW1(7)); yield 1; })().next()` in a handler's root) is placed by the read arm, which stops at the generator (ADR 0521 places only the generator's own body). A bound owner's callback in a handler (`runWithOwner(boundOwner, …)`) leaves every layer unplaced, the stepped generator included.
- SC2001 in `render`/`hydrate` `code` off web rc.13/17: uncertifiable (ADR 0353). Signals rc.17: a typed-only or `let`-aliased setter is unclaimed: `createOptimistic`'s unguarded one shares its type.

Store write outside a setter (`no-store-mutation-outside-setter`, SC2003; ADR 0425):

- `delete store.path` (ADRs 0461, 0791) is a violation only for a static member path whose property Type Facts proves optional and not readonly and whose links past the root get the assignment form's verdict (ADR 0465); behind an optional chain it is uncertifiable. Since ADR 0829 an operand Type Facts proves neither optional and writable nor rejected by TypeScript (`deleteOperandRejected`, the producer's mirror of `checkDeleteExpression`) is uncertifiable, `delete-operand-unproven`: an element access (`delete st["a"]`, `st.rec[k]`, `st.items[0]`), an index-signature key (`st.rec.k`), a non-optional `T | undefined` without `exactOptionalPropertyTypes`, an `unknown`. Owed, the proof: V where the producer can also prove acceptance (a resolved symbol the mirror passes; an index signature, where TypeScript asks nothing). A rejection both compilers suppress on its line is judged as if it type-checked (ADR 0830): V for an operand under an assertion or a rejected one. A nested path under a directive stays uncertifiable (the nullish-link premise is file-wide). A directive elsewhere in the file keeps a rejected operand uncertifiable, not silent (ADR 0829's file-wide premise).
- A rejection nothing reports (ADR 0830). Uncertifiable only, owed the proof: a rejected Solid primitive call or a cleanup-accepting callback's non-function return on a line a directive may silence (`refresh`/`affects` targets, an apply's or `onSettled`'s return; Chrome INVALID_REFRESH_TARGET, INVALID_AFFECTS_TARGET, REACTIVITY_HALTED), and in JavaScript, where `checkJs` is not in the facts, every one, V never. The fuzzer cannot claim these codes (INVALID_*_TARGET are out of scope, typed away; REACTIVITY_HALTED is a consequence): probes hold them. Uncertifiable too, never V: SC1005's positions TypeScript closes (a typed native attribute, a class object value, a computed key, an arithmetic, bitwise or relational operand) and SC7007's arity arm, on such a line. Silent by design under a directive: SC8003's lowercase `innerhtml` (rc.21 `ChildProperties` has no lowercase entry, so `setAttribute` writes it and no content is lost: the runtime, not tsc, decides); `draggable` (`no-implicit-draggable` is retired, outside the checker's domain); SC9012's invalid call (`values[i]()` on a number is a plain TypeError, and no Solid claim rests on it).
- The setter window is a dynamic extent (ADR 0476). A write in a function called inside the setter and also handed on, or in a callback given to a function this does not know, is uncertifiable, not followed. Still reported though it commits: a function called only from another module's setter (windows are per file), or reached by dynamic dispatch in the setter. Unproving every exported or handed-out writer would cover them, at every exported component's cost.
- Past the root (ADR 0465, 0476): a write through a link is uncertifiable, and silent where a link may be nullish under strictNullChecks (TS18048/TS18047): a link may hold a value the store does not wrap (frozen, non-plain), which no fact excludes; a proof from the store's initializer is built only where the setter is never referenced and no proxy of the store leaves as a value (ADR 0491); a store handed out through a hook, object or tuple stays uncertifiable (ADRs 0497, 0500 prove the destructured, tuple and member-read hook forms). Known miss: a write through a hook holder that is not an ADR 0481 member alias (the holder escapes, is written, or is read by a computed key) is silent, since nothing proves its root is the store (`store-write-literal-links`). Shared premise of every SC2003 violation, root or link (review, unprobed): rc.17's `writeOverride` is one module-wide flag a projection's draft operations raise (`dist/dev.js:2294`, `:6520-6542`), so a store write run from user code during one (a getter on another projection's seed) lands; no fact places a write outside such a window. Without strictNullChecks that is an internal result where strict `tsc` would report; no tsc-oracle case can pin it (fixture `store-write-chain-links-loose`). The effective strictNullChecks follows TypeScript 7 (`strict` on unless `false`), so in a project built with TypeScript 5.x and no `strict` key a nullish link is silent though its `tsc` is loose. `createOptimisticStore` results are treated as stores (unprobed on rc.17; upstream ignores them).
- Type-correct rebinding (`count = otherAccessor`, `store = { … }` on a `let`) is silent: the accessor-binding and accessor-member (`memo.a = 1`) arms are deleted, and the cast and same-type spellings are no proven defect.

Missing provider (`missing-context-provider`, SC4002, ADR 0352): a context is claimed only when no provider exists in the program. An open context (provided somewhere, escaped, a member or alias read; ADR 0713) is an obligation unless every render is under its provider; a render prop callback is not followed. Not claimed: package contexts (kobalte, router, query), `createContext` through an alias. In an open program a read the census finds no provider for is an obligation (ADR 0517), never a violation. A default the syntax does not prove is not `undefined` (`createContext(maybe())`, an imported or `let` default) is an obligation (ADR 0575); a provider whose value is `undefined` only at runtime counts as a provider (tsc types it unless `T` admits `undefined`). Decided not to build (2026-11-03): a read in a function assigned to a member (`o.m = …`, `this.m = …`, a factory's returned object, a literal member) or handed to a project wrapper (`run(hf)`) and called later on the same stack stays SC4001's obligation (SC9012 where the dispatch net fires); it would need definite assignment of the member before the call and no other write or alias, a member-state analysis (mx-recall CONTEXT_NOT_FOUND `handoff-{wrapper,assign,assign-param,assign-returned,assign-this,member}`, 90 programs, recall gaps under the declining judge). A callback prop called in the child's `onSettled` callback or handler is not given an owner edge (ADR 0562).

SC1002 (ADR 0565): a function run through a hand-off the walk does not follow (a project wrapper, `ho.m()`, a member assigned through a parameter, a factory or `this`) is an obligation; only an exact same-file wrapper called by name that calls it on every completion proves (`run(hf)`). ## 2. Decisions not to build

- `UNCOMMITTED_INPUT_OVERWRITTEN` has no rule: rc.17 warns only when the DOM differs from Solid's last write (`@solidjs/web` `dist/web.dev.js:252`), that is, after the user edited and before an equal-value re-run. That is a possible order of two user actions, not a proven execution. Editability, commit paths (a ref listener, a directive, a delegated parent, a DOM write-back) and sibling sources that change with the value are each open-world. The runtime oracle and the fuzzer's `probes/uncommitted-input/` cover it. Reopen if a recorded uncommitted edit becomes a checker input.
- A write is not proven legal because every invocation of its function is an event dispatch: a synchronous `click()`/`dispatchEvent` from an owned scope runs the handler under that owner. About 110 corpus SC2001 obligations stay open. Reopen with an owner-at-dispatch fact.
- Host-origin proof (DOM objects handed to Solid helpers, `makeEventListener(window, ...)`) needs the premise that project code never installs members on host DOM objects; app-game has 1,232 unknown-key writes. Reopen when a sweep shows a violation hinging on it and the owner states the premise.
- Anonymous arrows as their own summary owners: they detached captured parameter member calls from the enclosing function and dropped the SC9012 an opaque caller keeps (control: `fixtures/reactive-ir/accessor-provenance/Anonymous.tsx`). ADR 0686 keeps the SC9012 at any call whose target reads a captured parameter, so what is left is a proof, not a hole: reopen when captured-parameter behavior and callback timing compose across source summaries (Relay's `() => props.environment`).
- A shared reference/identity layer (`Resolved<T> | Unknown`) is not started. Under ADR 0326 every false positive so far was a proof re-deriving "is this still the same value" (props aliases, `arguments`, `delete`, redeclaration, reassigned tags, views of props). Reopen when a proof needs that answer.
- Recall fixes for the section 1 oracle sites: zero corpus yield (no `useParams()` destructuring; every `children()` accessor is read in JSX). Reopen on a real hit.
- An inferred browser host keeps rc.17 `setLinkClaim`'s gap: ADR 0270 admits non-Vite scripts (`node server.js` calling `renderToString`).
- Inferring a `never` exit from a body: a call completes normally unless its signature is `asserts` or returns `never`, and a helper that throws undeclared is outside the model. Treating every helper call in a `try` as unproven would cost recall the owner declined (ADR 0279, option b). Reopen if a producer fact records inferred throws.
- Per-function reads of a handed file (ADR 0408): a chunk records the whole file it was handed, so an edit anywhere in it reruns the chunk. Reopen if hand-out reruns show in a profile.
- Cone propagation of the interprocedural summary, returned and factory fixed points on kept state (S7 design §5): they cost about 2 ms per app-game import edit (ADR 0407), about what diffing their definitions would. Reopen if their seeds become incremental.
- Partial re-attestation of import identities after an update the compiler did not make in place (ADR 0419 keeps the attestation only after an in-place one): an import, reference directive, module augmentation, ambient module or JSX runtime pragma edit, a two-file update, a rebase and a producer restart rebuild the chain and ask the producer's module graph for every file (about 25 ms on app-game). An edited file's ambient module or reference directive can change another file's resolution, so an unchanged importer is exact only with the producer's word on its resolution inputs. Reopen when the producer reports which files' inputs moved.
- A file system lookup cache that outlives a build (ADR 0418 keeps answers for one build only): exact only if every path it answers is observed by the resolution witness or the tracked stamps, failed probes included (extension probing, `@types` and typeRoots lookups, tsconfig `extends`); otherwise an install or a new file stays hidden. Would save the rebuild's 23,500 distinct lookups (about 150 ms of thread time per app-game import edit). Reopen with a test that lists the cache's keys and checks that each is witnessed.

An in-place update needs tsrs to replace a file whose imports changed: `Program::reuse_program` refuses one (`can_replace_file_in_program` compares imports) and the per-file resolutions it would patch are crate-private, so it waits on a fork revision; the producer-side refreshes could be kept for files a rebuilt chain shares.
- Retained daemon floor (ADR 0400, ADR 0591): every request, a cache hit included, stats the resolution witness (about 6,000 entries on app-game) and every tracked source, about 7 ms of a 10 to 12 ms cache hit; only a file-event watcher could prove what did not change. The package boundary is re-derived per request (about 6 ms); emit re-serializes every finding (about 5 ms).
- Late-stage whole-program passes (ADR 0413): every edit pays the owner requirement census (`provider_free_contexts`, about 32 ms on app-game; it scans every call, binding, reference and JSX element, and its escape scan needs a record per reference, not per candidate), the server rules (`http_response_after_flush` walks every call, about 15 ms), the leaf passes (about 40 ms), the after-await rule (about 13 ms), final ordering (about 24 ms, mostly the memo sweep in `end`) and the graph stage (about 42 ms on app-game, unchanged).
- Classified dispatch veto (ADR 0449, 0450): classified in every build in which the program moved (12 ms on app-game, the stage chunks fingerprint its two bits); a reader reruns only when a bit moves. A write-flow answer (ADR 0442) is one memo per function that reads the whole program, so it reruns for each function a reused chunk asked, in every build in which the program moved; recording the files its walk read would make it exact. The kept program-boundary decision (ADR 0450) trusts the daemon's file stamp (device, inode, length, mtime, ctime) for the manifests and member listings it read, as the daemon does for its other disk inputs; a decision that listed a symbolic link is decided again every request.
- ADR 0538 trades and misses: a named function handed to a project helper, written as a member's value or an object slot, or a method of a class written inside an effect apply, an action step or a leaf callback is an obligation where the helper or member is legal; a callback prop forwarded to another component, destructured with a default, spread, or copied before its call is not followed (SC2008/SC6002 silent there); an action step's run at an inline carrier is reported as an obligation, not a violation, until every reference of the function is proven in the step.
- ADR 0539 trade: a read in the cleanup an effect apply returns is an obligation, never a violation, even where a rerun is certain: proving it needs an order between the rerun and the owner's disposal (which runs the cleanup outside the window).
- ADR 0540 miss: a read in an effect bundle's `effect` member is an obligation, not a violation. ADR 0548: an owner operation in a bundle's `error` member written as a method, or behind a spread, is an obligation.
- ADR 0547 trade: an action body's read is a violation only when every call of the action is proven to run; an action also called from a handler, exported, stored or handed to another function leaves the read an obligation. Parameter initializers of the generator are obligations.
- ADR 0549/0551 trades: a `createReaction` tracker reached through a `let` is an obligation at `track()`; one that escapes (exported, handed whole to a call, a JSX attribute's value, returned, assigned, no binding) is an obligation at its creation, not at its `track()` calls, even when every use is followed; through a `function`-declared hook, a hook with several returns, two nested hooks or a hook called in another module, only that creation obligation speaks.
- ADR 0550 trade: an SC3001 operation in an action's step called from a leaf is an obligation, not a violation, after a plain `yield`, behind a helper, a control-flow layer or a hand-off inside the step, or in an action another module holds (fuzzer action-from-settled/-tracked: 707 of 1,316 at a 0.2 sample).
- ADR 0541 trade: a primitive or `flush` in a render effect's apply, or in the cleanup an apply returns, is an obligation, never a violation (the first run, or a disposal, is outside the effect phase); a reaction bundle's `effect` member is not walked.

- ADR 0781, an assertion away from the receiver: `run(t as any)` into a `Promise<void>` parameter, a field or a return holding an assertion raises nothing, so the written type is trusted and the program certifies where Chrome warns. Held in `scripts/fuzz/patterns/types/p3-cast-*`, listed in `open-defects.json`. It needs value flow from the assertion to the receiver.
- ADR 0781, an unknown key on a global (`globalThis[key] = v`) vetoes standard functions and constructors, not instance methods: `x.push` stays proved though `key` could name `Array`. A project-wide veto of every method was +751 rows, from a test helper and a build plugin.

## What the server build does (ADR 0659)

Measured on rc.21; the input to `claims_client_runtime` and `ExecutionPaths`.

| API | Server build |
|---|---|
| `createEffect` | compute once, apply never |
| `createRenderEffect` | compute and apply both run |
| `createTrackedEffect`, `onSettled` | never run |
| `createReaction` | tracking callback runs, reaction never |
| signal, store setter | `SERVER_WRITE` warns, lands, no throw |
| direct store write | silent, lands |
| `flush`, `refresh` | no-ops |
| `resolve`, `until` | throw "not implemented on the server" |
| `isPending` | rethrows a pending read |
| `action` | returns `fn` unchanged |
| `render`, `hydrate`, `insert`, `ref` | throw "Client-only API" |
| strict window, write guard | absent |
| a pending read in a body | retried by the boundary; the body runs twice |

ADR 0683 limit: a class extending a standard container vetoes that member project-wide; only an array-literal receiver is exempt, so a `new Map()` receiver is not yet proved plain (+68 uncertifiable in `app-game`). A mixin or a patched prototype raises nothing.

ADR 0659 limits: `--rendering hydrated` resolves packages as the client, so dependency source is the client graph on both paths. A site in a function with no symbol that only an arm reaches keeps its finding (ADR 0677). `typeof window` is uncertifiable even under a browser selection that could decide it. `claims_client_runtime` lists the rules the audit measured: SC1001, SC2001, SC2002, SC2003, SC2008, SC5001, SC6002. The corpus sweep still runs every project as `csr`.
