# Decisions

Every design decision that still governs the code, by ADR number. Code cites
these numbers; link one as `docs/decisions.md#adr-NNNN`. A new decision gets the
next number and a short entry here: the rule as it holds, its
premise, and the owning files. History, alternatives and review rounds go in
the commit message. The original ADR texts are in git:
`git show docs-archive-2026-10-19:docs/adr/<file>`.

Retired numbers (their subsystems are gone; see the archive tag; ranges inclusive): 0001, 0004–0026, 0028–0109, 0112–0126, 0128–0131, 0133–0135, 0137, 0139, 0140, 0142–0152, 0154–0159, 0162–0165, 0167–0175, 0177–0189, 0191, 0197, 0198, 0207, 0208, 0223, 0224, 0226, 0227, 0229–0247, 0249–0265, 0267, 0271, 0272.

## ADR 0002 — Type Facts lives in this repository
The Type Facts producer (Rust, on tsrs; Go until ADR 0365) and the Rust process/session client are part of this repository and keep their versioned process seam. A semantic fact is added, produced, consumed and measured in one change. Compiler internals never cross into Reactive IR: consumers see the wire facts only. Owners: apps/solid-typefacts, rust/crates/typefacts, schema/.

<a id="adr-0003"></a>
## ADR 0003 — The Solid 2 compiler follows `solidjs/solid` next
Solid 2 compiler facts come from `solidjs/solid/packages/compiler` through the `yumemi-thomas/solid` fork at one exact commit. The fork carries semantic-fact models, output-neutral recording hooks, validation, serialization and fact tests only: no change to lowering, output, diagnostics, runtime behaviour, features or performance. A compiler defect is fixed upstream separately and the affected fact stays open until the fork rebases. Owners: rust/Cargo.toml (`solidjs-compiler` rev), rust/dialects/solid-v2/compiler/src/lib.rs.

<a id="adr-0027"></a>
## ADR 0027 — The built-in Solid runtime comes from the dialect
Behaviour of `solid-js`, `@solidjs/signals` and `@solidjs/web` (the dialect's primitive-defining packages) is stated by the selected dialect's reviewed premises, combined with exact symbols, Type Facts and control flow; no package document is read for them. Missing native behaviour stays unknown, never "no effects". Packages with similar names are external. Owners: rust/crates/solid-dialect (`primitive_defining_packages`), rust/crates/solid-facts-backend/src/package_requirements.rs.

<a id="adr-0110"></a>
## ADR 0110 — The checker analyzes Solid 2 only
The resolved `node_modules/solid-js` major picks the dialect. A major this build carries no dialect for (1.x, any future major) yields one project-level `SC9013` refusal naming the deciding `package.json`, and no other findings; a missing or unparsable install defaults to 2.0. The 1.x-only rules `jsx-no-undef` (SC8005) and `prefer-classlist` (SC8013) were dropped without replacement. The eslint-plugin-solid parity corpus is retired: `upstream_compat` is retained behaviour with no upstream control, and a divergence worth keeping is pinned as a product-owned ownership case. `Version::V1` stays so the refusal can recognise 1.x. Owners: rust/crates/solid-facts-backend/src/dialect.rs, rust/crates/solid-dialect/src/lib.rs.

<a id="adr-0111"></a>
## ADR 0111 — Dialect words belong to the dialect
Shared code asks the `Dialect` vocabulary rather than hardcoding primitive lists: whether a call returns a destructurable reactive tuple (`returns_reactive_tuple`) or a store (`returns_store`) is the dialect's answer, so `createOptimistic` and `createOptimisticStore` are recognised without a shared list. A shared `match` on `Primitive` is a seam a new dialect re-enters through; `Primitive` variants no carried dialect names are not live arms. The contract-word half of the original ADR is retired. Owners: rust/crates/solid-dialect/src/lib.rs, rust/crates/solid-reactive-ir/src/{indexes,local_access,source_discovery}.rs.

<a id="adr-0127"></a>
## ADR 0127 — Audited, defaulted and conservative vocabularies are separate
`Solid2::AUDITED` (the audited triple), `Solid2::DEFAULTED` (a project with no resolved `solid-js`) and `Solid2::CONSERVATIVE` (an owner that did not resolve, answered by each field's `#[default]`) coincide today but are kept apart, so moving the audited release changes only `AUDITED_INSTALLATION` and the vocabulary `AUDITED` names. Which release gets which answers, and its notice, is ADR 0194. Owners: rust/crates/solid-dialect/src/solid_2/releases.rs, rust/crates/solid-facts-backend/src/{dialect,release_scope}.rs.

<a id="adr-0132"></a>
## ADR 0132 — A relative edge inside one installed package is no package boundary
In the package-requirement census a relative import is skipped when the importer and the resolved file have the same owning manifest (nearest `package.json` above each that declares a `name`). The edge stays a requirement when it climbs into another installation, reaches a nested copy of the package, or has an unresolved edge or unreadable manifest. Only part 1 of the original ADR is live. Owner: rust/crates/solid-facts-backend/src/package_requirements.rs (`is_package_local_edge`).

<a id="adr-0136"></a>
## ADR 0136 — `createComponent(C, props)` is a call edge to `C`
The dialect states which call renders a component argument (`Dialect::renders_component_argument`; Solid 2 answers argument 0 for `createComponent`). A call is a render site of project function `F` only when the callee resolves into a primitive-defining package under a rendering name and argument 0 is a bare identifier whose symbol is `F`; anything else stays an escape. Only the attribution call graph reads the edge, kept apart from `function_call_sites` (component identity, execution roles). Owners: rust/crates/solid-dialect/src/solid_2.rs, rust/crates/solid-reactive-ir/src/{indexes,attribution}.rs.

<a id="adr-0138"></a>
## ADR 0138 — `Dynamic` renders the component its `component` prop holds
The dialect lists `(export, prop)` renderers (`component_prop_renderers`; Solid 2: `Dynamic`/`component`) and says only `createMemo`'s accessor yields exactly its compute (`accessor_yields_only_its_compute`). `component_value_flows` follows a value into such a prop only when every reference is a proven read (parentheses, `?:`, `??`/`||`/`&&`, `const X = value` read as `X`, a one-argument parameterless arrow memo read as `X()`); parameters, member reads, `let` and other calls remain escapes. The call graph walks the render as an edge. Owners: rust/crates/solid-facts/src/ast/component_value_flow.rs, rust/crates/solid-reactive-ir/src/{indexes,attribution}.rs.

<a id="adr-0153"></a>
## ADR 0153 — Context roles are a dialect fact (live part)
`Dialect::context_role` names `createContext` (Create), `useContext` (Read) and `createComponent` (Render). Reading `useContext(C)` yields `C`'s default or a value stored under its fresh id; a provider stores its `value` prop. Accessor provenance uses the roles to prove a parameter is only read as context. The package-context census chapters are retired. Owners: rust/crates/solid-dialect/src/{lib,solid_2}.rs, rust/crates/solid-reactive-ir/src/accessor_provenance.rs.

<a id="adr-0161"></a>
## ADR 0161 — A call that runs on every normal completion
`unconditional_calls` returns the calls a function runs exactly once on every normal completion: each step from the call up to the body must be evaluated once, unconditionally, and no earlier statement of an enclosing block may leave by `return`/`break`/`continue`. `synchronously_unconditional_calls` is the caller-facing form (ADR 0275, 0276): an earlier `throw` is an exit, an `async` function counts only calls before its first suspension, a generator states nothing. Under a declared host the conditions are already folded (ADR 0166). Owners: rust/crates/solid-facts/src/ast/unconditional_calls.rs; read by solid-reactive-ir cleanup.rs and execution_role.rs. (The original ADR's proposal-input use is dormant.)

<a id="adr-0166"></a>
## ADR 0166 — A host constant is folded per declared host
With exactly one declared host (`browser` or `node`), a named import of a bare package whose `exports` map selects only targets that all export the name as a module-level `const` bound to the same `true`/`false` literal (`@solidjs/web` `isServer`) is that literal. The value is read from the resolved bytes, never from the name; a `let`, re-export, pattern or array target, disagreeing targets or two hosts fold nothing. The fold is a span-preserving rewrite that blanks the dead arm; the fact file keeps the original `source_hash`. ADR 0295 extends it with Window-realm comparisons. Owners: rust/crates/solid-facts-backend/src/{host_constants,dependency_program}.rs, rust/crates/solid-facts/src/ast/host_constants.rs.

<a id="adr-0176"></a>
## ADR 0176 — An owner requirement after an `await` is proven unowned
A call listed in the producer's `calls_after_await` (after an `await` on every path of its async function's own body) runs from a promise continuation on a fresh stack. Its owner is the dialect's `fresh_stack_callback_owner` answer (Solid 2: none), so an effect, cleanup or owner-requiring call there is proven unowned, with the evidence "runs after an `await`, from a promise continuation". `onSettled`'s returned cleanup keeps the enclosing context; `runWithOwner` callbacks are nested closures and unaffected. Owner: rust/crates/solid-reactive-ir/src/owners.rs (`AwaitContinuations`).

<a id="adr-0190"></a>
## ADR 0190 — A primitive receiver dispatches to its built-in prototype
A parameter-member invocation at a call site carries no `SC9012` obligation when the argument is a primitive literal (not spread), or when Type Facts resolves the call to one standard-library declaration owned by `String`, `Number`, `Boolean` or `BigInt`. Object-typed built-ins (`Date`, `Array`, `Map`) are not covered. The demand plan therefore asks for the resolved call of argumentless member calls rooted at an enclosing function's parameter. Premise: no program patches a primitive prototype to read reactive state. Owners: rust/crates/solid-reactive-ir/src/interproc.rs, rust/crates/solid-facts-backend/src/demand_plan.rs (`parameter_rooted_member_call`).

<a id="adr-0192"></a>
## ADR 0192 — A built-in call in a leaf scope is resolved
The demand plan also asks for the resolved call of an argumentless method call written inside a leaf-owner callback (found by `callback_semantics_at(..).owner == Leaf`), so a standard-library method there is settled rather than an obligation. The demand stays scoped to leaf callbacks and parameter-rooted calls: demanding every member call adds a second symbol candidate and loses proven violations. Optional calls stay open (no resolved call from the producer). Owner: rust/crates/solid-facts-backend/src/demand_plan.rs.

<a id="adr-0193"></a>
## ADR 0193 — An application is the whole program
With no explicit program boundary, the nearest `package.json` decides: `"private": true` is an application (closed); otherwise a manifest publishing `exports`, `main`, `module`, `types`, `typings` or `bin` is a library (open); a manifest publishing nothing is closed; no or unreadable manifest is open. An explicit `--program-boundary`, the ESLint `programBoundary` setting or `.solid-checker/runtime.json` wins. The default is part of the diagnostic identity. Closing removes only the unseen-caller assumption; callers still have to be enumerated exactly. ADR 0444 reopens an application a workspace sibling depends on. Owner: rust/crates/solid-facts-backend/src/program_boundary.rs (`default_program_boundary`).

<a id="adr-0194"></a>
## ADR 0194 — The audited Solid 2 release is rc.17
`AUDITED_INSTALLATION` names `solid-js`, `@solidjs/signals` and `@solidjs/web` at `2.0.0-rc.17` (`Solid2::AUDITED` is `RC17`): rc.13's answers but `on`+uppercase spread listeners, an unguarded `createOptimistic` setter, `latest` absorbing a pending read, a deferrable `hydrate`, and `dynamic`'s static form from `solid-js`. `READ_RELEASES` is rc.0-rc.9, rc.13, rc.17; others get conservative answers under `SC9014`, older read ones the older-release notice. On the rc.17 triple `dynamicComponent` takes `dynamic`'s forms, `dispatchAsInteraction` runs `fn` inline in the caller's owner, `createDeferred` answers as `createMemo`, `lazyModule` as `lazy`'s loader, and `onHydrationEnd` runs later, owner conditional; `setLinkClaim` is an import-scoped gap, closed by declared CSR only (an inferred host admits non-Vite hosts). Owner: rust/crates/solid-dialect/src/solid_2/releases.rs; review in docs/release-audits/.

<a id="adr-0195"></a>
## ADR 0195 — A source tracked before the await is a dependency
SC1002 (`reactive-read-after-await`) skips an after-`await` accessor call when the async function has a straight-line call of the same symbol before its first suspension of any kind (any `await`, `for await`, `await using`). `straight_line_calls` excludes `if`, ternary, `&&`/`||`/`??`, loops, `try`, `switch` and optional chains, and is per innermost function. Member reads (store paths, props) keep the rule. A mistake can only hide a finding. Owners: rust/crates/solid-reactive-ir/src/static_rules.rs (`tracked_before_first_suspension`), rust/crates/solid-facts/src/ast/mod.rs (`straight_line_calls`).

<a id="adr-0196"></a>
## ADR 0196 — The compiler follows Solid rc.17
Fork commit, adapter revision literals, compiler-facts identity and identity document move together; the facts API is linear commits on `next`. Pin: distribution `9f5fff59`, upstream `5b1b7776` (rc.17), implementation `a4983a71`; trace 3, protocol 2. Only `on` + uppercase lowers as a listener (`Dialect::compiler_lowers_event_attribute`). Universal/Dynamic, TSRX, `sourceNames.locations` traces refuse. Owner: rust/dialects/solid-v2/compiler/src/lib.rs.

<a id="adr-0199"></a>
## ADR 0199 — A callback prop forwarded to an event runs on dispatch
A function literal written as a project component's prop takes `ExecutionRole::EventCallback` when that component only hands the prop to DOM event dispatch. The tag must resolve to one project function; the props parameter is one identifier whose every reference is a static member access that is an intrinsic event-handler value, inside such a handler, or a prop of another component satisfying the same proof. Follows `merge`/`omit` views, `const` aliases and un-namespaced `on...` spreads; a props object that escapes whole or a forwarding cycle proves nothing. Unproven stays uncertifiable. Owner: rust/crates/solid-reactive-ir/src/execution_role.rs (`forwarded_event_prop_role`, `prop_reaches_only_events`).

<a id="adr-0200"></a>
## ADR 0200 — A literal a wrapper runs as a tracked compute is tracked
A function literal passed whole to an exactly resolved synchronous project wrapper takes `ExecutionRole::TrackedJsx` when every reference to the wrapper's parameter is a direct call inside one function literal that is itself the whole argument of a tracked primitive callback (`createMemo`/`createEffect` compute) in the wrapper's body. Wrappers of wrappers and calls from nested functions stay unproven. Owner: `rust/crates/solid-reactive-ir/src/execution_role.rs` (`forwarded_tracked_compute_role`).

<a id="adr-0201"></a>
## ADR 0201 — A helper's read in its own body runs during the call
At a call with one target (a synchronous project function, outside JSX), an attributed read keeps the call's own role when it is written directly in the callee's body (not in a nested function, timer, listener, getter, `untrack` callback or default parameter) or is the accessor argument the body calls. Reads propagated from a deeper callee stay attributed; ADR 0204 extends the chain. Owner: `read_is_direct` in `rust/crates/solid-reactive-ir/src/interproc.rs`.

<a id="adr-0202"></a>
## ADR 0202 — Feedback reports what the user can act on
An unresolved member dispatch raises no obligation at a call whose execution role is an event callback, deferred callback, tracked JSX or deleted code, since no read rule reports there. The violations / "Needs review" / "Analysis coverage" output tiers now exist only behind `--internal` (ADR 0328). Owners: `interproc.rs` (dispatch roles), `rust/crates/solid-facts-backend/src/snapshot_emission.rs` (`render_default`).

<a id="adr-0203"></a>
## ADR 0203 — A closed program has no unseen caller of an exported helper
In a closed program, the `exported-parameter-member-dispatch` obligation of an exported helper is discharged when every reference to it or its aliases is the callee of a call resolving to it, its declaration, an import, or an export specifier. JSX renders, rendering props, values handed out, class members and unnamed functions keep it. Open programs are unchanged. Owner: `discharge_closed_program_export_dispatch`, `entered_only_through_call_expressions` in `rust/crates/solid-reactive-ir/src/attribution.rs`.



<a id="adr-0204"></a>
## ADR 0204 — Three reads that run while a component renders
(1) A read written directly in a function entered through a chain of plain identifier calls (no methods, at most eight hops, cycles prove nothing) is direct. (2) A callee's default-parameter accessor read runs at a call omitting that argument, without spread. (3) A literal that is exactly a component prop runs during render when the child calls `props.<prop>` directly in its body. "Directly in a body" excludes nested parameter lists. Owners: `directly_entered_functions` (`rust/crates/solid-reactive-ir/src/interproc.rs`), `prop_literal_invoked_during_render` (`execution_role.rs`).
<a id="adr-0205"></a>
## ADR 0205 — Coverage gaps group by family and subject
Each analysis-coverage finding carries `coverageFamily` and `coverageSubject`, set at projection from the defect's fields; grouping never parses message text. Seen only in internal views (ADR 0328). Owners: `coverage_group` in `rust/crates/solid-reactive-ir/src/projection.rs`; `render_coverage` in `rust/crates/solid-facts-backend/src/snapshot_emission.rs`.

<a id="adr-0206"></a>
## ADR 0206 — A component's owner carried to runWithOwner is not null
The owner argument of `runWithOwner` is proven non-null when it names a `const` initialized by a dialect-resolved `getOwner()` call written directly in a proven non-async component body, not in a nested function or default. Parameters, `let` bindings, properties and helpers stay conditional; disposal is a separate question. Owner: `component_owner_binding` in `rust/crates/solid-reactive-ir/src/owners.rs`.

<a id="adr-0209"></a>
## ADR 0209 — A method of an exact instance is followed in a leaf scope
A method call in a leaf-owner callback is followed when the receiver is a `const` bound to `new C(...)` (or `this` in such a method), `C` is a single-declaration project class, and the resolved method is declared in `C` itself. No assignment may write a member of that name or replace a prototype (ADR 0213/0314 narrow this). Owners: `exact_instance_method` in `rust/crates/solid-reactive-ir/src/cleanup.rs`; `member_name_may_be_reassigned` in `indexes.rs`.

<a id="adr-0210"></a>
## ADR 0210 — Host callbacks and member calls in a leaf scope
A standard-library call's arguments follow the audited timing table: inline callbacks (`forEach`, `map`, `call`/`apply` receiver, setter updaters, `Promise` executor) are walked like helper bodies; fresh-stack and deferred callbacks run after the scope; `PromiseLike.then` and unaudited callables leave SC9012 open, never a violation. Member calls are read from the resolved declaration, never the span's entity. Synchronous dispatch is handled by ADR 0329. Owners: `member_call_operations`, `standard_library_argument_operations` in `cleanup.rs`; `runtime_semantics.rs`.


<a id="adr-0211"></a>
## ADR 0211 — A value whose origin fixes its class fixes its members
An argument that is a fresh built-in (array literal; `new` of Array/Date/Map/Set/WeakMap/WeakSet/RegExp/ArrayBuffer/DataView/typed array; `Array.from`/`of`, `Object.keys`/`values`/`entries`, `String.split`; species-built array results) runs prototype members that read no reactive state; an instance of exactly a project class runs that class's own plain method. Followed through `const` only; void where the program may replace the member. Owners: `value_origin`, `class_method_symbol` in `rust/crates/solid-reactive-ir/src/indexes.rs`.

<a id="adr-0212"></a>
## ADR 0212 — An accessor's value is proven from every write
Proven built-ins also include: a signal accessor whose init is proven and not a function, every setter reference a call and every write or updater return proven; a `createMemo` accessor with a synchronous literal; a plain call of an exact project function with every return proven; `??`/`||`/`&&`/`?:` of proven operands; array literals; members of a proven receiver (`sort` returns it; `map`/`filter`/`slice`/`split` build fresh values). Props, stores, cross-file accessors stay open. Owners: `accessor_origin`, `setter_writes_builtin`, `returns_builtin` in `indexes.rs`.
<a id="adr-0213"></a>
## ADR 0213 — A parameter holds what every caller passes
In a closed program a parameter-member obligation on a plain unwritten identifier parameter is discharged when the function is entered only through calls (ADR 0203) and every call's argument (or default), followed up to four hops, is a proven origin. A named prototype write (`C.prototype.m = f`) refuses only `m`; replacing a prototype or writing at an unknown key refuses all. Owners: `CallGraph::parameter_holds_builtin` in `rust/crates/solid-reactive-ir/src/attribution.rs`; `member_name_may_be_reassigned`.

<a id="adr-0214"></a>
## ADR 0214 — A prop holds what every tag passes
In a closed program an obligation on `props.name` is discharged when `props` is the component's sole plain parameter, never assigned; the component is rendered only through resolved JSX tags (a call, `createComponent`, rendering prop or other escape fails); and every tag passes a built-in value (a spreading tag fails, a missing attribute is `undefined`, `children` is not followed). Owners: `prop_holds_builtin`, `rendered_only_through_jsx`, `value_holds_builtin` in `attribution.rs`.



<a id="adr-0215"></a>
## ADR 0215 — The value-flow proofs survive review
Computed writes record their literal or `const` key; any other computed prototype write refuses every member; a binding is written if any assignment target or loop head references it. An exact class instance has the class's own members only if no constructor returns a value and no field, parameter property or computed element can define the member, through the whole `extends` chain (unresolved proves nothing). Function values must be current. Owners: `class_instance_is_exact`, `function_value_is_current`, `binding_written` in `rust/crates/solid-reactive-ir/src/indexes.rs`.
<a id="adr-0216"></a>
## ADR 0216 — A forwarded prop is as reactive as its source
`<Inner value={props.value}/>` makes Inner's prop reactive, static or unresolved exactly as the caller's own prop is, by a least fixpoint over forwards; a prop is static only when no chain reaches a reactive or unresolved value. A props object passed whole, `merge`/destructured views, a store passed whole, several children and `props.a.b` off a static head are unknown, never reactive. Owners: `classify_passed_expression`, `resolve_forwarded_props` in `rust/crates/solid-reactive-ir/src/source_discovery.rs`.

<a id="adr-0217"></a>
## ADR 0217 — Leaf scopes reach helpers, namespaces and more host callbacks
Argumentless calls in helpers a leaf callback reaches get a resolved-call fact. `ns.f()` on a namespace import binding follows the exactly resolved exported function declaration or `const` function; computed members and aliases keep the obligation. Host rows: `Promise` executor and `NodeList.forEach` inline; global `addEventListener` and `MediaQueryList.addListener` deferred; `MediaSession.setActionHandler` fresh-stack. Owners: `rust/crates/solid-reactive-ir/src/cleanup.rs`, `runtime_semantics.rs`; `rust/crates/solid-facts-backend/src/demand_plan.rs`.



<a id="adr-0218"></a>
## ADR 0218 — A callback every use of which is closed is not a strict read
A callback handed to a project function or component clears only the SC1001 finding when every runtime reference of its subject (parameter, optionally one static property of an exact literal or attribute) is closed: a dialect tracked slot, exact unlabelled `untrack`, compiler-tracked JSX, a fresh-stack scheduler, or an exact forward. Storing, aliasing, unknown packages, DOM listeners and cycles are open; labelled `untrack` and `callback_may_open_strict_window` slots never inherit a window. Owners: `rust/crates/solid-reactive-ir/src/project_consumer.rs`, `projection.rs`; `Dialect::callback_may_open_strict_window`.
<a id="adr-0219"></a>
## ADR 0219 — A type query and a namespace call are accounted entries
The entry census of ADR 0203 also accounts for erased type queries (`typeof fn` in type position) and a namespace call whose property resolves to the call edge's declaration, only while no runtime code reaches the module as a namespace object (escaping namespace import, `export * as`, dynamic `import()`/`require`, transitively). Specifiers resolve by the compiler's module graph; unresolved bare ones may name anything; files outside the program import no project module (ADR 0193). Owners: `module_namespace_escapes`, `specifier_reaches` in `attribution.rs`.

<a id="adr-0220"></a>
## ADR 0220 — The project's bundler answers where a load goes
Opt-in `--runtime-resolution required` runs a Node worker that loads the project's own Vite config and asks a client plugin container (`resolveId`) about each load occurrence, joined by literal span. With the table present `specifier_reaches` uses it alone; unknown answers (error, virtual or query module, declaration target, `require`) may reach anything; any failure leaves an empty table; the run bypasses the daemon. Default off. Owners: `rust/crates/solid-facts-backend/src/runtime_resolution.rs`, `packages/cli/scripts/runtime-resolver.mjs`.

<a id="adr-0221"></a>
## ADR 0221 — A prop head and an async prefix run at the call
The head of a props member chain (`props.snapshot?.x`) is a Get backed by the ADR 0216 fixpoint. A control-flow primitive's sole exact children literal runs while rendering. An exact plain call of an async project function runs its prefix up to the first suspension (no suspending loops or `switch` tests). An omitted argument activates its default. New async/default paths need a runtime source witness; a store Get needs a key the dialect says warns. Owners: `local_access.rs`, `interproc::body_site_runs_during_call`, `Dialect::store_key_warns_strict_read` (exact rc.13).
<a id="adr-0222"></a>
## ADR 0222 — A returned source and a helper's prop read reach the caller
A project function whose every normal completion returns the same unwritten `const` bound to a dialect source primitive in that frame (exact, current, synchronous, block-bodied, no loops/`try`/`switch`) returns a fresh source per call. A component-local helper's prop read counts at each proven exact plain call with the call's role and ADR 0216 backing. Owners: `rust/crates/solid-reactive-ir/src/source_discovery.rs`, `local_access.rs`; `completion_return_cover` in `rust/crates/solid-facts/src/ast/completion_call_cover.rs`.

<a id="adr-0225"></a>
## ADR 0225 — An exact receiver for getter instantiation
A getter on an argument runs at the call that copies it only when the receiver is a fresh closed object literal, or one immutable local `const` initialized by one (no alias, export, descriptor change or earlier spread; no internal spread, computed or numeric key, duplicate, setter or `__proto__`). Anything else stays an explicit obligation. Only the receiver rule is live (used by ADR 0283); the contract protocol words are gone. Owner: `rust/crates/solid-reactive-ir/src/property_gets.rs`.

<a id="adr-0228"></a>
## ADR 0228 — The certified contract tier is retired
`bundledContracts`, `installedPackages` and `exportConditions` stay in the WASM `CheckRequest` and its typings for compatibility but are accepted and have no effect. Owners: `rust/crates/solid-checker-wasm/src/lib.rs`, `packages/wasm/index.d.ts`.

<a id="adr-0248"></a>
## ADR 0248 — Contract gaps are opt-in in ESLint
No shipped ESLint config enables the `package-contract-incomplete` rule; it is filtered out of every config's default-enabled set. Uncertifiable results are anyway not user-facing (ADR 0328). Owner: `packages/cli/eslint.cjs` (`CONTRACT_GAP_RULE`). Superseded by ADR 0440: SC9005 has no ESLint rule at all.

<a id="adr-0266"></a>
## ADR 0266 — Standard runtime configuration premise

## ADR 0270 — Browser host from feasible execution reachability
With no explicit target, discovery infers a browser host from closed, non-executing config (one conventional `vite.config.*`, scripts naming Vite only in plain forms, no custom resolver) and client roots; an unproven premise refuses with a `solid-checker: note: browser host not inferred` line. ## ADR 0273 — Transported member stability premise
Members of an object a factory returns or a context provides are assumed never reassigned, deleted or redefined. Only a visible write vetoes: any static member write by name on any receiver, `Object.defineProperty`/`assign`/`Reflect.set` by exact library identity, with unknown keys or spread arguments vetoing every member. Two states per member (Assumed, Vetoed). Over-veto only withholds. Owner: `MemberStability` in `rust/crates/solid-reactive-ir/src/accessor_provenance.rs`.

## ADR 0274 — Option getters through a forwarding helper
A call of a local helper counts as the copy of its parameter when the helper (exact, current, synchronous, directive-free module, never naming `arguments`/`eval`) passes the plain unwritten parameter to the copying call as the whole value of a `const` or unconditional `return`, outside classes, JSX and fragments. Every getter of a hazard-free prefix (none mentions `this`, `super` or `eval`) is guaranteed. Owner: `rust/crates/solid-reactive-ir/src/property_gets.rs`.

<a id="adr-0275"></a>
## ADR 0275 — A helper's operation counts only on every completion
In the leaf-scope walk, a called body's operation (or call to the next helper) is performed by the call only when it runs on every normal completion the caller can continue from; an earlier `throw` is a way out, an async helper counts only its prefix before the first suspension. Otherwise it is an uncertifiable `leaf-owner-forbidden-call`. The leaf callback's own body keeps the statically-present-code premise. Owner: `reached_on_every_call` in `rust/crates/solid-reactive-ir/src/cleanup.rs`.

<a id="adr-0276"></a>
## ADR 0276 — A read through a helper counts only on every completion
A completion site is a call, `new` or member expression in a function's straight-line flow (no conditional, logical right operand, logical assignment, loop, switch or try; nothing before it can `return`/`break`/`continue`/`throw` out; in an optional chain only what precedes the first `?.`). A summary row is direct only when proven on every completion at every hop; others stay uncertifiable "only on some of its paths". Owners: `AstFacts::completion_sites` in `rust/crates/solid-facts/src/ast/mod.rs`; `site_on_every_completion`, `read_is_direct` in `interproc.rs`.

<a id="adr-0277"></a>
## ADR 0277 — A callback runs only when its helper calls it on every completion
A helper invokes its parameter during the call only when a call of the parameter is a completion site of its synchronous body; this governs inline-arrow roles, stored-literal proofs and accessor-by-reference reads. A call on some paths is an uncertifiable obligation (SC2001 stays silent); `cb?.()` is not a completion site. The completion-call table is bound into `cross_file_proof_digest`. Owners: `invokes_parameter_during_call` in `rust/crates/solid-reactive-ir/src/execution_role.rs`; `parameter_called_on_every_completion` in `indexes.rs`.

## ADR 0278 — Exact callback mapping and never-returning guards
A call TypeScript resolves to a `never`-returning signature is an exit; sites after it are not completion sites. A written parameter is not the caller's callback. An argument reaches its parameter only through an exact mapping: no `f.call`/`apply`/`bind`, a current function value, no earlier spread. Owners: `project_callee_at_parameter` in `execution_role.rs`; `never_returning_call_before`, `parameter_completion_calls` in `rust/crates/solid-reactive-ir/src/indexes.rs`.

## ADR 0279 — Assertion and never signatures, and exact method callees
The Type Facts producer states, per resolved call, whether the selected signature carries an `asserts` predicate or returns `never`; either makes the call a possible exit (a throw in an undeclared helper is outside the model). A method callee runs its declared body only for a module namespace member, an unwritten member of a `const` object literal, or a member of a `const` bound to `new C()` of the declaring class. Owners: `Call.AssertionSignature`/`NeverReturns` in the producer and `rust/crates/typefacts`; `member_runs_declared_method` in `execution_role.rs`.

## ADR 0339 — A mention of a function-valued binding runs after its declarator only where that is proven
A `const` or `let` function-valued binding is not hoisted: a mention that runs before its declarator throws, and a `var` reads `undefined`. Within one module a mention follows when it is in the declarator's own body after it, inside the function itself, in a function or arrow created after it, in an arrow or nested declaration written before it whose every mention follows, or in a hoisted declaration that nothing running ahead of the declarator can call. Owner: `rust/crates/solid-reactive-ir/src/indexes/initialization.rs`; withheld mentions are bound into the cross-file proof digest.

## ADR 0345 — A ref expression's own functions run where they are written
A `ref` expression runs in two places. The function it yields to the ref application (the expression itself, or an element, conditional branch or logical operand of it) runs with no owner: a violation. A function the expression evaluates without yielding (a getter's body, a tagged template's substitution, an operand of `void`) is undecided. Code that a call in the expression evaluates runs during render under the owner of the code around the expression: an IIFE, the body of a factory the expression calls, and a callback a dialect slot runs during its call (`untrack`) are owned. Code at module initialization runs with no owner (a violation), and a call inside a component's children is undecided, since it runs inside that component's own memo. A generator never runs when called, and a callback no dialect slot describes may run with or without an owner: both are uncertifiable. A callback is named only by a function literal, a bare identifier or element 0 of an event handler's tuple. Premise: an owner edge reaches the enclosing function; one that no edge reaches (a method no resolved call names, an exported function a closed program never calls) has an unknown owner and is uncertifiable. Trade-off: an effect a factory called by a ref creates is owned, so it is SC6001 only, not SC4001 (the open item in docs/open-work.md). Owners: `ref_value_marks` and `yielded_value_contains` in `rust/crates/solid-reactive-ir/src/owners/owner_context.rs`; fixtures `ref-expression-owner-walk`, `directive-owned-effects`, `callback-containment`.

<a id="adr-0346"></a>
## ADR 0346 — A callback's identity is the entity whose symbol covers its whole span
A typefacts entity names the symbol at its demanded span's first byte. That symbol is the value's only when it covers the whole span (`symbol_covers_span`, Type Facts wire schema v21, handshake protocol 80); otherwise it is a token inside the span, such as the callee of `f(x)` or the object of `o.p`. Every callback identity reads this exact answer: owner discovery and the owner callback index, the event handler and ref roles, named callbacks, and reachability roots. A TypeScript wrapper (`h as X`, `h!`, `h satisfies X`) keeps the identity of `h`. A call-valued callback names a literal only when the call is an identity wrapper: a project function, declared or bound by an immutable `const` to a function literal, that returns one of its parameters on every completion, returns no other value, is neither async nor a generator, and never otherwise references that parameter, its name, `arguments` or `eval`. A wrapper whose declaration is written later in its module (`wrap = function …`) names nothing. A callee names only the identifier it is, and a member read of a server function with a resolved declaration is no server call. Premises: the covering answer is exact, and the wrapper read is the one that runs (a wrapper changed in another file invalidates its callers through the cross-file owner cache). Stays uncertifiable: a call-valued callee's returned callable (SC2001, SC1001). Trade-off: a reactive read keeps its leading token (`a.b.c`, `sig().x`, `props.x ?? []`), so each read is still attributed to the source it goes through; making those exact removed six correct SC1001 violations in a corpus trial, so they were not changed. Owners: `EntitySymbols::exact` and `value_symbol` in `rust/crates/solid-reactive-ir/src/indexes.rs`; `identity_wrapped_literal_span` in `indexes/identity_wrappers.rs`; `symbol_covers_span` in `rust/crates/typefacts/src/lib.rs`; fixtures `callback-ts-sugar-identity`, `identity-wrapper-callback`, `identity-wrapper-rejections`, `call-valued-callee-identity`, `server-member-transport`.

<a id="adr-0347"></a>
## ADR 0347 — An invoked literal runs under its call's owner; a namespace hand-out is reachable
A direct call of a function literal runs its body inside the call, so the call is an owner edge under the function that holds it: unowned at module scope, owned in a component body. It is withheld for an instance field initializer (it runs at construction) and for JSX in the owner's own body (a component's children run in its memo, ADR 0345). In a closed program, an export that a namespace import hands out is seeded with the open-world unowned bit, so a callback proven unowned whatever the caller does is a violation, and a requirement in the export's own body is uncertifiable; an export that only an unnamed escape reaches is never proven. A dynamic import hands out only the names its result reads (`const { a } = await import(x)`, `lazy(() => import(x), options)`). A leaf body is not region-owned, an `onSettled` in it is queued with no owner (rc.13), and a `createTrackedEffect` body always runs under the tracked node. Premises: a namespace or dynamic import whose specifier does not resolve to the module does not count, since ADR 0203's "may name anything" premise would seed every export of a closed program. Mechanics: `rust/ARCHITECTURE.md`, `docs/rules/missing-owner.md`, `docs/rules/leaf-owner-forbidden-call.md`. Fixtures `owner-invoked-literal`, `owner-invoked-literal-forms`, `owner-guard-iife`, `owner-namespace-reachable`, `owner-namespace-named-reads`, `owner-tracked-body-forbidden`, `owner-leaf-*`.

## ADR 0348 — An inert standard call is inert for its runtime arguments; an async prefix runs on the caller's stack

## ADR 0366 — A binder-level symbol's id is a pure function of the program
First slice of STABLE-IDS (retention stays off, ADR 0364). The id of a symbol proven binder-level is `H(domain, key)`, keeping the `symbol:h:<24 hex>` spelling and the wire. Key: `Intrinsic` (a checker singleton, matched by pointer), else `Global(name)` (an entry of the checker's `globals` table), else `Export` (the declaration's reference is a module export), else `Decl` over the minimum declaration by `(path bytes, name start)`, not merge order. A pre-merge binder symbol maps to its merged symbol first (one `JSON`, one `Set`). Private and unique-symbol names are hashed without the checker's counters (`#<classId>@x`, `@sym@<id>`). The claim map is gone: which symbol asked first no longer decides an id. Proof of binder-ness: not `Transient`, or a merge clone (a declaration's binder symbol is recorded as merged into exactly it) with no check flag or derivation link. Anything else, instantiations, `this` clones, mapped and spread properties, takes its exact derived key or no id (ADR 0398; was a counter) and never shares a binder id; so does an id whose key collides, and a symbol that does not own every declaration it lists (each declaration's binder symbol merges into it, or it is that declaration's local half): a parameter property's parameter shares its node with the property, so only the property keeps the hash. Derived symbols: ADR 0372; multi-origin properties: ADR 0371. A property read through an instantiation or a class instance's `this` type has a derived id. Owners: `apps/solid-typefacts/src/binder_key.rs`, `src/identity.rs`, `tests/binder_ids.rs`.

## ADR 0368 — A dependency-source program lists the project's roots first, in tsc's order
TypeScript orders a program's files by its root files, and its answers can depend on that order. The generated sibling tsconfig (ADR 0284) listed its roots by path, so closure files under `node_modules` came before `src`: in probus-hk (TanStack Router) TypeScript 7.1, on that program, reports 188 router call errors that `tsc` on the project does not, and the checker took 21 calls as TypeScript-owned (`recovery`), hiding 5 SC9012 findings. Root order causes it, not check order. The project's files now come first: its configured roots in `ParsedCommandLine.fileNames` order (the producer's `ModuleFact.root`), then its other files by path, then the closure. TypeScript then holds the project's files in `tsc`'s order (measured on probus-hk, unproven for every closure). Owners: `dependency_program.rs` (`program_modules`), `dependency_sources.rs` (`program_document`), `apps/solid-typefacts/src/module_graph.rs`.
Review: a root is placed as the loader places it (an extensionless name's first existing extension, a project-reference redirect); a root it cannot place (`unmappedRoots`, protocol 83) refuses the sources (`ProgramPreparationUnavailable`), never path order. A root under `node_modules` stays listed. Every project call's validity is the project's own program's (kept open): `Recovery` there is TypeScript's (silent), `Recovery` only in the generated program is SC9012 `dependency-source-program-call-error`. A `Recovery` call in selected package source to a non-callable callee refuses that package (SC9005). `solid-reactive-ir/src/base/memo`: a memo table maps a key to a value computed through a `Ctx`, the only way its code reads the build: a file section (source, compiler map, entity rows; the key's own file is free), an L1 index key, a file's slots, a build constant, another memo. Reads are kept as `QueryId`s with the answer's fingerprint (for a memo, the revision its answer last changed in) and a reverse map. A build's changed inputs (section fingerprints, the store's index Δ) mark readers dirty and their readers maybe-dirty; an answer is reused, verified through its memo reads in recorded order, or recomputed, and an equal recomputed value stops propagation. Keys and values are `Canonical` (no hash containers). Only context-free answers are memos, so reads form a DAG; a cycle answers the table's fail-closed value, is reported and empties the store. `SOLID_CHECKER_IR_VERIFY_REUSED` recomputes each reused answer and names the table and key that differ. First tables: identity wrappers (ADR 0346) per function and per declaration symbol; the cross-file digest keeps their section. Reuse across edits needs stable TypeFacts ids (study S0).

## ADR 0386 — Member resolution is memoized; an unported read is a probe
`object_members/memo.rs`, `assigned.rs`: object-member targets, spread handlers and literal receivers are one memo per file slot, `ReceiverClosed` one per receiver (owner, literal, declaration, symbol), `PrototypeOwnerAt` one per `R.prototype` write, and the assigned-member census one project memo. The lookup's `Targets`, `SpreadTargets`, literal-receiver set and `AssignedMembers` are assemblies of these answers in file order (a later slot of a path still overwrites an earlier one); the old builders are deleted. A receiver's uses come from the base `symbol_uses` index plus TypeScript's references of its symbols, and the host-prototype proof from the `spellings` index, never a scan of every file. A table not ported yet is read through a **probe** (`base/memo/probes.rs`): a keyed question the lookup answers from its table, recorded as an input with the answer's fingerprint; the store asks every recorded probe again in `begin`, so an answer that moved dirties exactly its readers, and a probe may not read a memo. The digest keeps its object-member, spread and prototype-write sections (per-file caches rely on them), fed from the memos, and gains the cross-file literal receivers, closing ADR 0383's latent key; a literal declared in the member's own file moves with that file's hash.

## ADR 0387 — Project-wide answers are memos; what is not yet narrow reads the whole program
`solid-reactive-ir/src/indexes/project_memos.rs`: the effect-apply tables, exported primitive consts, withheld initialization mentions, parameter-completion calls, never-returning calls, the exempt store-key census and the any-file vetoes (intrinsics, string code, tuple iteration, the `bind` patch, objects assigned into, router parameters) are memo tables (ids 32+). The rest read the lookup through `Ctx::project`, recorded as `Input::Project`: it moves on any file change, any TypeScript table not reported unchanged (`cache::typescript_unchanged`), or a closed-program flip. Such an answer is reused only across builds in which nothing moved, and narrows as the tables under it port. Fixed points (parameter completion) and the recursive initialization proof stay one whole-program answer each (cone recomputation is S7). Answers are sorted vectors; the lookup keeps per-build hash views. The cross-file digest keeps every section, fed from these memos: the per-file caches rely on it. Premise: module-resolution attestations change only with a source edit or a cache-domain change.

## ADR 0389 — The client patches its symbol closure from exact per-file changes

## ADR 0390 — Returned-callback uses are a memo; the digest keeps its source hashes

## ADR 0393 — Project passes solve on kept state and publish per key

<a id="adr-0394"></a>
## ADR 0394 — The retained daemon verifies its answers while idle
`daemon/idle_shadow.rs`. After a materialized answer and 300 ms idle, a background-priority thread opens a fresh state from the same request, answers the same check and compares findings JSON, status and notice byte for byte and the IR `Program` table by table (ADR 0383's `first_difference`). Comparable only when both builds saw the same inputs (tracked source and config hashes, package inputs); otherwise inconclusive, never a mismatch. A request cancels the check (a flag read between the fresh answer's phases); it restarts after the next debounce. It runs only while the machine has room for a second build: available memory (Linux `MemAvailable`; macOS free, inactive and speculative pages; purgeable ones are already among those) of at least the daemon's resident size plus `SOLID_CHECKER_IDLE_SHADOW_MIN_FREE_MB` (default 1024), whatever the daemon's own limit; the watchdog does not hold a running check to that limit while the room lasts, and abandons it first when it does not. One connection per request leaves no push channel, so the next request delivers a mismatch: logged (stderr, `<socket>.shadow.log`, first differing table and row), the whole state dropped (memos, indexes, per-file caches, producer), the answer opened from scratch, response header `recovered`. Accepted: the stale answer was already served. Off by default, like oxlint's language server (each check costs about a cold check of CPU); `SOLID_CHECKER_IDLE_SHADOW=1` turns it on, `panic` ends the daemon (tests, CI); off when the inline shadow is on. Debug builds carry `_FAULT` and `_DELAY_MS` hooks. Cost: a transient second build (+0.8 GB on solid-groove, +1.4 GB on app-game since ADR 0399), none on the next edit once it ends; an edit arriving mid-check measured +10% on app-game.

## ADR 0395 — Interprocedural summaries are canonical sets
`SummaryReads` (`interproc.rs`) used to keep or drop a row by arrival: a later dominating row was kept beside the weaker one before it, so the rows, and the `origin`, `origin_context`, `declaration`, `kind` and structured-return label ties picked, depended on worklist order. It is now, per key `(display, origin, declaration, transported)`, the rows no other row dominates, where domination is the product order on `local`, `conditional` and a rank (hops from the seed, origin, declaration, display, symbol, kind, context, owner, undecided). A product order, not "flags, then a tie-break": every propagation transfer is monotone in each component, so a dropped row only ever yields rows the survivor's yield dominates, and the fixed point is order-free. Rows sit in canonical order, so emission's stable sort and structured returns' first row read the canonical first row; delta propagation reads an arrival log. Step 0 against rc17 and the fixtures (full JSON, related fields included): hop order moved no finding; location order moved three related locations onto a deeper helper's read.

## ADR 0398 — Per-file checkers with exact ids are the producer's only mode
A file's facts are a pass: a fresh checker of its own checks the file first, then answers its demands, async facts and reference scan, and computes the rows of every id they name; the program's other non-declaration files get a reference pass. Answers that read every file (reference spaces, the default-library write census, structural-accessor descriptor suppression) are deferred and completed from the merged passes. Ids: binder (0366) and set (0371) keys, else the exact derived key (root and canonical type context, `derived_key.rs`); no key, no id (an absent fact), never a counter. A pass is reused while its read set (the forward closure over recorded resolutions of the file and of every global contributor) is unchanged path by path in `Text`, `Exports` and `Resolutions` (every resolution record of the file and the files its edges land on), with `Options`, `Ambient` (program order), its census answers and its own demands; the rest run on a pool (`SOLID_TYPEFACTS_PER_FILE_WORKERS`). This holds across a rebuilt chain (an import edit, a deleted or new file, a rebase): a kept read set's members kept their edges, so it is the same paths (computed again and compared); a newly imported file enters only read sets that reach the edited file. Two passes minting one id for two keys make the table the sequential shared-identity run's. Supersedes ADR 0367's check-first and ADR 0369; the selection flags are gone (no escape hatch). Moved once and reviewed: coverage 0 findings; rc17 corpus 8,220 findings, 0 added, 0 removed; 2 of 13.8M fact cells (a `merge()` history movement). Owners: `apps/solid-typefacts/src/per_file.rs`, `passes.rs`, `derived_key.rs`, `identity.rs`, `rust/crates/typefacts/src/session.rs`.

## ADR 0400 — The daemon's residue per edit
Outside the reactive IR and the producer an app-game body edit cost resync 19 ms, package inputs 23, solve 17, emit+cache 12, and a 5.5 MB answer per linted file. Now 10, 13, 6, 10 (release, interleaved against the parent, loaded machine). Each is exact: (1) `snapshot_of` placed each location by scanning its file; it computes each file's line starts once per answer, O(log n) (line starts kept per source `Arc` were removed: saved under 3 ms in the 2026-10-25 audit, groove 7 ms faster without). (2) The package boundary read each import's manifest and scanned every file per import: one read per manifest, a set of held files. (3) The resolution witness drops absent entries under an absent ancestor (the ancestor's entry fails first) and resolves a directory entry's canonical path as its parent's, once per check; tracked sources' and directories' stamps are read on six workers. (5) `--only-file <abs path>` (`--format json`) answers the report with only the findings that can matter to that file: project-scoped, no path, primary or related location equal after lexical normalization, or a path it cannot settle (relative). Positions are recorded as the report is written (`FindingIndex`); everything else, and each kept finding's bytes, is the full report's. The ESLint adapter sends it for the native checker only, and projects per file as before. An app-game answer is 12 KB, not 5.5 MB; parse in Node 5.3 ms to 0.03; a repeat request 36 ms to 17.

## ADR 0406 — The memo begin and the read sets cost what changed

## ADR 0421 — A retained edit's disk checks run beside the producer's update; its bookkeeping runs after the answer

An ordinary retained edit used to check its resolution witness, send the update, wait, read the inference closure, analyze, extend the witness and sweep the memo store, one after another. Now, when every edited file keeps its module lines (lines naming `import`, `from`, `require`, `<reference` or `declare`), the witness check and the closure read run while the producer applies the update, and a stale witness abandons that session for a fresh one once the update has landed, before any analysis. When the lines change, the witness is checked first as before: beside a program rebuild those reads slowed its file-system lookups by more than they saved (import edit +19 ms). The choice is only of order; both are exact. The memo sweep runs once the answer is written, or its write failed: the daemon answers one request at a time, and a build begins by running a sweep still due. ## ADR 0442 — A function handed to project code takes the role of each place that code invokes it
A function literal, or a same-file function named by identifier that the file hands on (a whole argument, a non-intrinsic JSX attribute value, a `const` alias), takes for a write the join of the roles of every invocation ADR 0319's forward walk finds: through the callee's parameter (every use a call, or handed on to another exact project callee), through `props.<name>` of an exactly resolved project component (an intrinsic `on…` attribute or a call in the child's handler is a delivery, a call in the child's body or a tracked computation is owned, a call in a leaf scope is exempt, a prop forwarded to another component recurses within the walk's budget), and through a reviewed scheduler's callback slot (`setTimeout(fn)`, a fresh stack). A call is placed by what its own position proves, without a census of the other entries of the function holding it, and a call in a function the walk entered through a parameter takes the role of the call that handed the value over, never of that function's other callers. The join follows ADR 0378: an owned invocation (the body, a tracked computation) makes the write the violation whatever else invokes the value; otherwise every invocation must be placed (several non-reporting roles give `Unreported`), and a census gap, an unplaced invocation, a destructured or `let` or stored or escaped use, a `merge`/`omit` view, a spread or repeated attribute on the element, a package component known only by declarations, a primitive's callback slot, or an unresolved child keeps the obligation. A prop literal needs no closed program (what a child does with a prop does not depend on its other callers); the answers are one per-build table, bound by `Section::WriteFlowAnswers`. A write inside a layer the walk runs in place (an immediately invoked function, a callback the standard library runs inline) takes the answer of the function around it only when no layer's position follows a suspension: an `await` that may precede the write in the write's own function, or in any function around it up to the answered one, puts it in the ownerless continuation (ADR 0333), which no invocation of that function places, so it stays unplaced (`write_flow_role`; fixture `prop-callback-roles/variants/after-await`). ## ADR 0444 — A workspace package a sibling depends on is an open program
ADR 0193's default made every `"private": true` package, and every manifest publishing nothing, a closed program. The workspaces read are `package.json` `workspaces` (array or `{ packages }`; npm, yarn, bun), `pnpm-workspace.yaml` `packages` (without the key, pnpm's default of every subdirectory) and `lerna.json` `packages` (default `packages/*`), at the package's directory or any directory above; a pattern is `*`, `?`, `**` and `!` negation over directories holding a `package.json`. ## ADR 0450 — Edits on a project with dispatch sites cost what they cost on one without

## ADR 0451 — A change that moves findings is gated on edit latency at a looser ratio
ADR 0423's gate skipped the ratio whenever base and head answered differently (a pull request may move findings on purpose), and its ceilings only report. ## ADR 0452 — A closure a tracked scope builds runs where it is called
A tracked scope (a memo or effect compute, a tracked JSX expression) gave every write and read written in it its role, a proof for code it runs. Building a closure runs nothing. `enclosed_by_stored_function` left an anonymous stored literal to its invocations but skipped a function bound to a name ("the call sites' business"), and the lexical role was returned before any call site was consulted (`write_roles.rs`, `direct`), so `SC2001` reported `const openFn = () => setOpen(true); return openFn` (rc.17 runs it from a click, legal), and a read in a returned or stored closure was certified tracked although rc.17 warns `STRICT_READ_UNTRACKED` when the body calls it. Writes: the named closure's entries decide (`named_closure_in_tracked_scope`): a call in the scope's own pass is a violation, also through layers that run in place (an IIFE, an inline standard-library callback), an alias or an outer closure; a call in a leaf scope or handler is not; a closure only returned or stored is uncertifiable. A name decides nothing (a capitalized closure is judged by its calls; one that returns JSX is a possible component). Reads (`unrun_closure_within`, in both tracked arms of `semantic_role_before_awaits`): inside the region, a stored function, or a named closure not entered only by calls in tracked positions, takes no role, so the read is uncertifiable; an IIFE and a name every reference of which is a tracked call keep `Tracked`. A default value (`(x = set(1)) => x`, `({ a = count() }) => a`) lies outside its function's body but runs only when that function is called, so every closure question looks at the functions whose body or parameter list holds the site (`functions_around`: the stored-literal, JSX-attribute, region and named-closure guards). `functions_around` finds the owners of a parameter list by their whole span, so a function written inside a default (an IIFE, an inline callback) belongs to the closure too, and a write there is unplaced whatever role its lexical position or the function around the closure has (`write_flow_role` and the walk's entries took the body-based function, so a helper returning the closure placed the default by the helper's own calls). A call in the owner's own parameter list is no call in its body for the summary rows (`interproc/graph.rs`, `callback_chain.rs`): it runs only when the caller omits the argument. The `containing_ast_function` lookups (about 150) still placed a site in a nested parameter list in the function around it: ADR 0454. The same query now serves the component-child, provider-value, `merge` argument, named-callback, retained-literal and summary-owner questions. A named closure with a default in it is unplaced for writes and reads: its parameter list is not inert, so the call graph withholds its call sites (ADR 0339), which also costs the violation for a write in the body of a closure with a non-literal default called in the scope. Costs: an object method the scope runs by coercion (`valueOf`) and a recursive closure (its own calls are in progress, so unproven) are uncertifiable too; the corpus gains 17 uncertifiable results, no violation. Not changed: `project_consumer` and `runs_outside_owner_call` still read `attribute_function_within` alone. Fixtures `write-named-closure-in-tracked-scope`, `read-closure-in-tracked-scope`; rule page `no-write-in-pure-computation`.

## ADR 0454 — A site in a parameter list belongs to the function whose list it is
A default value (`(x = cb()) => x`, `({ a = count() }) => a`), and a function written in one, runs only when its function is called without that argument. The lookups through `containing_ast_function` (the innermost function whose *body* holds a site) put such a site in the function around it, so `function runNested(cb) { const g = (x = cb()) => x; return g; }` as `createMemo(() => { runNested(() => setV(1)); return 1; })` was an `SC2001` for a write that never runs (`calls_parameter_in_body` took the call for one in `runNested`'s body, and `write_site_role` placed it in `runNested`'s activation). rc.17 throws nothing for it, nor for the forwarded `(x = runBody(cb)) => x`, the closure in a branch, returned directly, destructured, declared, with an IIFE in the default, or called with the argument supplied (`oracle-behaviour-parameter-list-owner`: the counters stay 0 where the checker said violation). The owner primitive is `AstFacts::innermost_function_owning` / `functions_owning`: the innermost function whose body holds the site or whose parameter list does (from its first parameter to the body; its name and type parameters are bound around it). Over it, `owners.rs`: `owning_function`; `containing_body_function` (the owner when its body holds the site, else none); `owned_by_body` (`containing_ast_function(span) == function` for a call, member, JSX element or binding, true only for a site in the body); `in_parameter_list`; `functions_around` is `functions_owning`. `containing_ast_function` stays the lexical lookup the role pipelines use: a list site takes the role of the code around its function and is then withheld (`parameter_default_owner`, now the owner of a site directly in a list, `unrun_closure_within`, the write guard); a global switch of it to the owner moved `prop-head-get`'s dormant default from uncertifiable to a violation. A call in the owner's own list (`run(cb, x = cb())`) runs when a caller omits `x`: no body call, kept unplaced; no proof that every caller omits it is built. Audit of the 180 lines naming `containing_ast_function`, `innermost_function_body_containing` or `functions_body_containing` (64 files): 52 uses converted, 123 unchanged-safe (returns and awaits, uses behind `body.contains` or `written_directly_in`, role lookups behind the veto, comparisons of two owners, labels), 5 definitions. A parameter called in a list is a call that may be made: `calls_parameter_in_parameter_list` keeps the summary row uncertifiable, as the misplaced call did. Costs: those true violations; a forbidden call in an IIFE's default in a leaf callback is one obligation at the IIFE, not also one at the call (`DefaultImmediate`). The owner graph (SC4001) places a call by its owner too (`owner_discovery.rs`, a second review found it body-only: a cleanup in a never-called closure's default was a `missing-owner` violation, also in a module function's or a constructor's list, and through a helper reached only from a default): a call in a list is an edge from no source that may be unowned (`MayBeUnowned`), its requirement is uncertifiable, held by the owning function's context (zero, never called, counts as unowned) and not by a providing region around the function; a component's own list under its owned body stays silent, unless the call is a function literal invoked there (`m = (() => onCleanup(…))()` is legal and uncertifiable: the in-place invocation has no source). The SC3001 leaf walk judges a call in the callback's own list like a call in its body, kept uncertifiable: rc.17 calls an `onSettled` callback with no arguments (`@solidjs/signals` dist/dev.js `onSettled`, `untrack(callback)`), so its default runs in the leaf scope (`oracle-parameter-list-owner-leaf`; it was silent), but no dialect fact states the arguments a primitive passes, so no violation is proven. ## ADR 0455 — A write's owner is the one its callback's call gives it, through the layers that run in place
Two fuzzer-found `SC2001` false positives (Chrome-confirmed; rc.17 throws nothing and the write lands: `oracle-behaviour-detached-owner-layers`, `oracle-behaviour-root-untrack-default`) shared one cause: `write_region_adjustment` (`write_roles.rs`) placed a write by the callback that lexically holds it. U1, `runWithOwner(null, () => { (() => setV(1))(); })` (also `forEach`, in a component body, memo or effect compute): only a write directly in the callback took its no-owner role; an IIFE or inline callback in it took the lexical role of the code around the call, and the guard rejected a write with no owner to reject it. U2, `createRoot(() => ({ f: (p = setV(1)) => p }))` called from a click, and the `untrack` form: the site is in the parameter list of a function the callback builds, which `direct_callback_contains` took for the callback's own body, so `CreatedRoot` and `CallSite` placed a write that runs only when the closure is called without the argument (ADR 0454; the memo's guard left it unplaced after those arms had returned). Costs: a closure with a default called in a root or `untrack` body with the argument omitted is uncertifiable where it was a violation (rc.17 throws; nothing proves the omission, as in a memo), and so is a write under a bound `createOwner()` owner (directly or in a layer), which `run_with_owner_callback_owner` does not prove non-null. In the oracle's own harness (a dispatching entry) every handler write is uncertifiable, an `untrack` IIFE in a handler too.

## ADR 0456 — A called `onCleanup` handle runs its callback where it is called
rc.17's `onCleanup(fn)` returns `fn` (`@solidjs/signals@2.0.0-rc.17` `dist/dev.js:2377-2405`, prod `signals.js:65-67`). So `const h = onCleanup(() => setV(1)); h();` in a memo runs the write at `h()`, with `disposalDepth` 0, and throws `REACTIVE_WRITE_IN_OWNED_SCOPE`. A write in an `onCleanup` callback took the callback's lexical `Deferred` role, though, and the handle was never read, so 60 of the 75 items of the disposal fuzz run (Chrome-confirmed, 7 of them `ACTION_CALLED_IN_OWNED_SCOPE`) were silent. Now `Dialect::disposal_callback_returned` (`Returned`, `NotReturned`, `Unknown`) says what the call returns. Solid 2 answers `Returned` for `onCleanup`'s callback when the read signals release is rc.17, and `Unknown` otherwise. The answer keys on `write_guard_in_disposal`'s `StandsDown`, which is exactly `Read(RC17)`: a digit of its own would double the variant table. `cleanup_handle.rs` takes the census by exact resolution. The callback runs only in the disposal when the result is discarded or bound to a `const` nothing reads. It also runs at the handle's calls when the result is a `const` whose every reference is a call in the file (not exported, no `eval`, no other-file reference), or when the call is written on the result (`onCleanup(fn)()`). Anything else (stored, passed, returned, aliased, an unread release) is unplaced. The write walk climbs from the write to the callback through layers that run in place (an IIFE, an inline standard-library callback, `untrack`) and judges the write at each handle call: one that rejects it is the violation, an unplaced one leaves it uncertifiable, and calls that are all legal keep the disposal's role. A closure the callback builds, or a write under an owner a call in it gives (`runWithOwner`, `createRoot`), is left to its own entries: a named closure is judged at its calls, which take the handle's role. `runs_in_disposal` asks the same of an owner-given write. A handle call proven outside a disposal is `NotIn`, a violation (`CleanupHandleCalled` and `CleanupHandleCalledAtOnce` of `write-owner-in-cleanup` moved from uncertifiable). Costs: a passed, aliased or object-member handle, and any called handle off rc.17, is uncertifiable. Not this mechanism (`docs/open-work.md`): an action in a closure a cleanup hands to `createRoot` by name; `flush()` in an effect's cleanup. A handle call in an instance field, a possible or undecided component or a refused file is unplaced, by the backend's own predicates (it withdraws by the write's location, never the call's). A callback registered by name is judged like an inline one when `fn` is exactly resolved, else uncertifiable; a write that may follow an await is placed at no handle call. A handle call in a dead branch (`if (false)`, after a `return`) or in a function proven not to run (every call and render unreached, or unreferenced) is unplaced too. Fixture `write-cleanup-handle-call`; rule page `no-write-in-pure-computation`.
