# Audit: Solid 1.9.14 core primitives — the `creates` call domain

Date: 2026-09-12. Status: **draft for the repository owner's review**. No
audited JSON document was touched by it; it neither revives nor relies on the
`creates: []` closures that the 2026-08-28 migration wrote into
`pkg/contracts/bundled/solid-v1/*.json`, which `docs/precision-backlog.md`
records as manufactured from missing knowledge.

This is a hand implementation census, in the sense of
`docs/adr/0008-implementation-census-for-creates.md` and the 2026-09-04 rc.3
audit ([`2026-09-04-solid-2-rc3-core-primitives-creates.md`](2026-09-04-solid-2-rc3-core-primitives-creates.md)),
performed over the exact published `solid-js@1.9.14` bytes for the eleven
primitives (2026-09-12; five more on 2026-09-13, §§ 13–17) that block the most Solid 1.x consumer exports in the ecosystem
pin. Measured over `benchmarks/ecosystem/report.json`'s
`contractContent.dialectSilentBlockers`, the 1.x dialect's silence declines
`creates` on 5,721 export-domains across 68 of 168 solid1 rows, and seven
spellings carry over 1,200 of the blocked exports: `useContext` 405,
`splitProps` 245, `createEffect` 198, `mergeProps` 157, `on` 98, `onMount` 69,
`createRenderEffect` 50 (`phase21/2026-09-12-consumer-demand-measurement.md`
§ 8.1). `batch`, `createComputed`, `createMemo` and `createSignal` are added
because every one of the seven reaches them and because they are the spellings
the census meets first in almost any 1.x consumer.

It decides only what `semantic-model.md` § "What a closed call domain denies"
§ creates lets it decide:

> `creates: [] closed` denies that one invocation of this export gives rise to
> any operation of kind X, where X is exactly *this export performing a
> published `create` operation* — […] **registering a version-1 resource into
> a runtime outside this invocation** — a browser document or a server runtime
> — so that the resource remains live there after the call returns, reachable
> by that runtime rather than only through a value the call handed back.

Reactive nodes, owners and computations coming into existence are **not**
`create` operations (§ creates and the census plan § 3 item 3); a package's own
module-level binding is not a runtime that acts on what it holds (§ creates,
`runCreatingOwner`); and a one-shot `queueMicrotask` that drains the module's
own queues registers no version-1 resource (rc.3 audit § 1.5, applied here
unchanged). Every section below says so where it applies rather than leaving it
implied.

### 1.3 What the method was

For each primitive: the definition was located in each bundle (the cited byte
range is exactly `function NAME(...) { … }`, or `const NAME = …;` for the
server alias), and every call in its body was followed until it resolved to
one of the rc.3 audit's terminators (§ 1.3 there, reused verbatim): a
**module-local** helper whose body was read and is cited by line; an **engine
builtin** with what it transfers control to; a **caller-supplied callable**,
whose invocation is a `callbacks` item and whose body is not this export's
behaviour; an **installed hook** — a callable the export did not define and the
caller did not supply, reached through module state — recorded; or a
**host-runtime touch**, recorded with what it registers and for how long. The
browser update cycle is common to R4–R9 and R11, so it is walked once (§ 1.5)
and the sections say which dispositions rest on it.

### 1.4 The declaration/runtime split, here

Unlike rc.3, `solid-js@1.9.14` declares and implements every one of these
names in the same archive, so the tier's declaration-keyed row and the runtime
a consumer executes are always the same archive. The split that remains is the
one § 1.2 tabulates — three implementations under one declaration — and a row
is sound only because all three were read.

### 1.5 The browser update cycle, and the archive-wide host census

`createComputation` (`dist/solid.js:737`, `dist/dev.js:780`) allocates a plain
computation object, links it into `Owner.owned`/`Owner.tOwned` (in-memory
owner tree), and — only when `ExternalSourceConfig` is installed — wraps `fn`
through `ExternalSourceConfig.factory` with a private `createSignal` and an
`onCleanup` (hook path, H1). `updateComputation` (`solid.js:685`,
`dev.js:728`) calls `cleanNode` and `runComputation`, and under a *completed*
transition schedules a one-shot `queueMicrotask` (`solid.js:691`,
`dev.js:734`) that re-runs the node — a microtask draining the module's own
state, not a version-1 resource. `runComputation` (`solid.js:701`,
`dev.js:744`) sets `Owner`/`Listener`, calls the **caller's `node.fn`**, and on
an exception routes to `handleError` (`solid.js:999`, `dev.js:1045`), which
calls the owner's `ERROR` context handlers — callables the caller registered —
or rethrows. `runUpdates` (`solid.js:816`, `dev.js:861`) and `completeUpdates`
(`solid.js:832`, `dev.js:877`) drain `Updates` through `runQueue`/`runTop`
(`solid.js:877`/`:787`; `dev.js:922`/`:832`) or, **only when `Scheduler` is
installed and a transition is running**, through `scheduleQueue`
(`solid.js:880`, `dev.js:925`), which calls `Scheduler(...)`; they then drain
`Effects` through `runEffects`, which is `runQueue` until `createEffect` has
ever run and `runUserEffects` (`solid.js:897`, `dev.js:942`) afterwards.
`runUserEffects` reads and writes the module's own `sharedConfig` hydration
bookkeeping (`solid.js:121-140`) and calls `setHydrateContext`, which assigns
`sharedConfig.context` — module state. `completeUpdates` also calls
`setTransPending`, the setter of the module's own `transPending` signal
(`solid.js:559`). `writeSignal` (`solid.js:652`, `dev.js:695`) marks observers
and pushes them onto `Updates`/`Effects`; it throws after 10⁶ pending updates
and otherwise touches nothing outside the module. `cleanNode` (`solid.js:943`,
`dev.js:988`) unlinks sources and runs the node's registered `cleanups` —
callables the caller (or `createComputation`'s hook path) registered.

The dev bundle adds, on these paths: `console.warn` when a computation or
cleanup is created with no `Owner` (`dev.js:798`, `:508`) — a host diagnostic
that registers nothing; `DevHooks.afterCreateOwner`, `afterUpdate`,
`afterRegisterGraph`, `afterCreateSignal` (`dev.js:173-177`, `:829`, `:919`,
`:606`, `:222`) — all `null` unless a devtools consumer installs them, i.e.
installed hooks; and `registerGraph` (`dev.js:601`), which pushes onto
`Owner.sourceMap` — the owner tree again. The module-initialization
`globalThis.Solid$$` check (`dev.js:1804-1805`) is not an operation of any
export.

`MessageChannel`, `process`, `performance`, `localStorage`, `fetch`, `Promise`,

**Browser bundles** (`solid.js:1385-1432`, `dev.js:1435-1482`).
When `SUPPORTS_PROXY && $PROXY in props` — the caller passed a proxy props
object — it returns `keys.map(k => new Proxy({get, has, keys}, propTraps))`

the caller passed. **Server** (`server.js:434-448`): copies the
caller's descriptors onto fresh clones with `Object.defineProperty` and deletes
them from a local descriptor map. Verdict: no `create` on any path.
