# Phase 1 semantic and policy freeze

Date: 2026-08-27

## Verdict

Phase 1 is complete. `semanticModelVersion: 1`, the temporary
`schemaVersion: 2` field vocabulary, and the machine-verification policy are
frozen sufficiently to begin the deep module interfaces in Phase 2. No public
schema, producer, consumer, bundled contract, fixture, or finding changes in
this phase.

The freeze optimizes for one condition: a package behavior may be certified
only when its exact artifact and the local claim are proved, while unrelated
incomplete behavior remains analyzable as open knowledge. Human review is not
part of the normal acceptance path.

## Authority

- Published `solid-js@2.0.0-rc.3` and related `@solidjs/*@2.0.0-rc.3` runtime
  artifacts and declarations remain the behavioral authority.
- The pinned semantic-only Solid compiler fork supplies lowering facts, not
  runtime-library behavior.
- Repository-owned Type Facts supplies TypeScript semantics through its
  process/session interface.
- Solid 1.x behavior, earlier Solid 2 betas, RC.0 examples, API-name inference,
  and framework labels cannot override exact RC.3 artifact identity.

## Frozen semantic answers

### Knowledge and closure

Closure applies to one immediate set-valued claim domain. It never transfers
through a parent, child, sibling, summary reference, guard alternative,
recursive value, or referenced resource. A closed domain must carry its
collection, including an empty collection that proves absence. Omission never
proves a negative.

Structured value knowledge follows the same rule. Tuple slots, object
properties, and choice alternatives close locally. Array element shape and
length-interval knowledge remain independent. One unknown leaf cannot erase a
proved sibling or be hidden by parent closure.

### Operations rather than phases

The normalized primitive is an acyclic operation graph. Flat phases are only a
possible producer presentation and do not cross the normalization seam.
Operations distinguish:

- eligibility trigger from actual execution point;
- same-stack, queued, and external dispatch;
- tracking state from ownership;
- owner source, requirement, production, capabilities, and lifetime;
- possible behavior from guaranteed behavior and bounded repetition;
- order, data, invalidation, error, cleanup, and lifetime edges.

This is sufficient for split effects, repeated async emissions, cleanup
replacement, transitions, render/hydration roots, response commitment, and
callbacks that execute in multiple contexts without duplicating whole
summaries.

### Conditional behavior

Guards may use only facts the configured TypeScript/compiler/artifact pipeline
can decide exactly: selected signatures, argument counts, finite literals,
value/protocol kinds, fixed property presence or callability, tuple
alternatives, result protocols, and exact artifact cases. Unresolved selection
joins all possible cases. Complete negatives require every joined case to be
negative.

### Values and capabilities

The recursive algebra carries structural and observable behavior, not API
names. Projection and snapshot are represented by value shape, capability, and
resource relations unless a published runtime protocol later proves a distinct
observable category. Contradictory capabilities are normalization failures,
not consumer conventions.

### Artifact selection

The contract records the result of real package-export resolution. It does not
reimplement resolution by matching browser/node/mode labels. Exactly one case
must agree with the host-resolved runtime, declarations, resolution trace,
closure, transform identity, and exports. Zero or multiple matches refuse that
artifact case. Mixed-framework packages are selected by exact artifact and
dependency/import closure, never a manual framework label.

### Proof and ordinary analysis

The proposal generator is untrusted. Probes witness possibility and falsify
claims but never prove absence, exhaustiveness, minimum cardinality, or a
finite maximum. Only the independent verifier closes domains and issues a
receipt. Ordinary analysis consumes the accepted normalized model and receipt
offline; it does not require raw evidence sidecars.

## Deep module interface constraint

All wire omission rules, summary expansion, alpha-renaming, closure arrays,
artifact selection, guard normalization, receipt validation, and canonical
hashing terminate in one contract document module. Its output is the normalized
contract model owned by Reactive IR. JavaScript orchestration and dialect
consumers must not implement another semantic normalizer.

The deletion test is the Phase 2 acceptance criterion: deleting this module
would force compact-wire knowledge into every consumer. If callers still need
to know `closed`, summary IDs, omission rules, or schema versions, the module is
too shallow and Phase 2 is not complete.

## Questions closed in this phase

- `closed` at the wrong level cannot certify sibling or descendant facts.
- Cardinality always carries a trigger/call/resource scope.
- Scheduling cause and execution point are separate.
- Owner source, requirement, creation, capabilities, and lifetime are separate.
- Conditional behavior shares operations through guarded references rather
  than whole-summary duplication.
- Recursive leaves are independently knowable and independently provable.
- Resolution traces are provenance for actual resolution, not environment
  matchers.
- Summary references have no overrides.
- The main contract contains sidecar hashes, not claim evidence.
- Experimental is a positive local marker; missing is unknown, not stable.
- `schemaStatus`, framework labels, general Boolean guards, generic deferred
  timing, phase lists, nominal projection/snapshot brands, generator trust
  fields, embedded review status, and per-fact `{status,value}` wrappers are
  excluded.
- The essential field missing from the earlier compact proposal was
  cardinality scope; it is now required whenever a bound is known.

## Deliberately open evidence, not design questions

The freeze does not claim that every RC.3 package behavior is already proved.
Dynamic loading, runtime generation, opaque native/WASM behavior, reflection,
unknown callback escape, open-world dispatch, arbitrary races, and unstable
server-component protocol details keep only their affected claims open. The
sixteen Solid 2 conformance rows still require the Phase 13 positive, negative,
partial, refusal, TypeScript-oracle, and artifact-mismatch fixtures.

Numeric compactness targets remain performance gates, not semantic authority.
The frozen 1 MiB safety cap and structural limits may be lowered by policy; a
policy change cannot silently validate an existing receipt.

## Phase 2 entry

Phase 2 may now define private wire types in `solid-facts-backend`, normalized
types in `solid-reactive-ir`, the accepted/proposal/evidence/receipt typestates,
the single loading interface, resolver and evidence adapters, typed failures,
and interface-level tests. It must not implement schema migration or new facts
before those interfaces exist.
