# Receipt-bound factory export roots

Status: implemented and measured on retained Solid 1 recovery; no new published
root case yet.

An exported variable initialized by an imported identity factory can lack any
usable declared root shape (`any`). Protocol 44 supplies a positively unwritten
initializer chain and direct object-literal arguments. The certification
consumer now joins this derivation to an exact dependency return claim. It
proves only the empty export-root path, never nested members or callability of
a returned callable.

The initializer query must match the authenticated runtime export's source,
span and owning snapshot. Materialized installation coordinates identify the
original importing module. The factory must resolve to that importer's exact
dependency export and declaration reference, including source span, artifact
case and semantic digest. A single whole-parameter return must select an
actual object-literal argument slot. Incompatible selections refuse.

This is conditional evidence, not permission from a proposal. Its witness
records a distinct factory-return requirement containing the dependency,
importer, resolved-import root, export, return claim and parameter index. Graph
composition independently selects the exact dependency node for every such
requirement and authenticates its receipt, policy, issuer, epoch and verifier
build. The certified contract must explicitly close that return enumeration
with the same parameter identity, and its receipt must contain the exact
closed claim. The requirement root is returned only after every discharge
succeeds. Finalization refuses an absent or different discharge token.

Receipt and trust roots commit those discharges. Existing public receipt fields
and coverage metrics are unchanged. The creates-census channel remains
separate; an empty creates claim cannot satisfy this positive root proof.

The native `factory_return_composition_requires_exact_closed_identity_and_receipt`
test certifies an aliased root through synthetic authenticated archives and a
completed return veto. It refuses an open return domain, an unrun veto, a
different returned parameter, callable argument, reassigned binding and another
export or importer (with identical child artifact bytes). The different-parameter child has its own correct recipe, and the test
asserts that its parent lacks the required object argument rather than allowing
an unrelated veto failure to stand in for that check.

No ecosystem entrypoint gain is inferred from this fixture. The retained Solid
1 graph was remeasured through ordinary publication and consumer checks; see
the result below.
