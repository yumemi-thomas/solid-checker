# ADR 0186: The tier carries what the app corpus installs

- Status: superseded by [ADR 0228](0228-the-certified-contract-tier-is-retired.md) (2026-10-08). Originally: accepted and implemented (2026-10-05). Tenth lever of the owner's
  package-misuse goal of 2026-10-04. Owner decision of 2026-10-05: make the
  compiled-in tier match what users actually install.
- Owners: the compiled-in accepted-contract tier (`pkg/contracts/accepted/`
  and `accepted_bundles/embedded.rs`), regenerated by
  `scripts/bundle-accepted-contracts.mjs`.
- Relation: adds consumer-environment certifications to the tier. The bundler
  already carried that kind of certification: one made in a tree a real
  consumer installs (owner decision, 2026-09-26). No code change, no new
  trust: each bundle is the certification's own receipt, authenticated and
  re-issued by `solid-contract-bundle`.

## Context

Until now the tier was built from the census and checkpoint runs: package
versions chosen by the corpus, certified in fresh installs. It matched no
installed environment in the 38-app corpus, so an app got no package findings
unless its developer certified packages in place (the `SC9005` remedy). That
remedy, automated over the 38 apps (`rust/target/local-certify/drive.mjs`),
found 9 true-positive violations with no false positive, after ADRs 0184 and
0185 fixed pnpm and Bun admission.

## Decision

The catalogs those in-place certifications wrote are bundled into the tier.
A bundle is keyed by the dependency environment it was proven in, so each one
applies exactly where the same package version is installed with the same
dependency versions and integrities: the apps of the corpus, and any project
that installs the same tree.

Procedure, from a local-certification run `<run>` (its `catalogs/<key>/` and
`issuers/<app>/<project>/trust.json`):

1. Stage each catalog with the trust configuration its certification wrote:
   `<staging>/<key>/.solid-checker/` and
   `<staging>/<key>/.solid-checker.authority/trust.json`.
2. `bun scripts/bundle-accepted-contracts.mjs --carry --catalogs <staging>`.

The bundler refuses, as it should:

- `solid-js` itself (ADR 0027), 159 catalogs;
- 24 certifications that state no dependency environment, since no consumer
  install could be matched against them.

## Consequences

- The tier grows from 1,448 to 1,848 bundles, and from about 16 MB to 23 MB.
- A bundle matches only its exact environment. A project with any other
  dependency version or integrity still needs to certify in place. This is
  the same bounded reach every consumer-environment bundle has.
- Regenerating the tier without `--carry`, and without these catalogs, drops
  them. The measurement script keeps `--carry`.

## Evidence

- From `rust/target/local-certify/local-0185`: 39 catalogs staged, 400
  bundles added; every one of the 1,448 checked-in bundles is carried.
- 38-app browser sweep with the plain release binary, no local certification
  (`rust/target/defect-sweep/c0186-browser.json` against `c0183f-browser.json`):
  - violations go from 264 to 273 (+10, −1);
  - the +10 are the local-certification findings, now delivered by the tier
    alone: nine untracked reads of TanStack router `useSearch`/`useParams`
    memos in `probus-hk` (one line holds two), and the `useMutation` store
    read in a `createEffect` apply in `spotify-desk-thing` (ADR 0184). Each
    is runtime-confirmed `STRICT_READ_UNTRACKED`;
  - the −1 is the known `combineProps` partial-contract precision loss
    (`overlays`);
  - uncertifiable goes from 10,085 to 10,355 (+451, −204). More imports now
    carry a contract that leaves claims open, mostly missing-owner
    obligations: the honest unproven state, not a claim.
- The node-mode sweep is unchanged (264), as expected: these certifications
  were made for the browser host.
- Coverage and the ownership gate are unchanged. `make test-rust` passes except
  the known pre-existing
  `sessions_process::incremental_contract_exports_refresh_changed_summaries`.
