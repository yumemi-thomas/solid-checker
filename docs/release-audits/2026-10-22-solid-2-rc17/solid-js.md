# A. `solid-js` premises, rc.13 to rc.17

Bytes: `solid-js@2.0.0-rc.13` (`sha512-62bYOI4J…MIBdoQ==`) and `2.0.0-rc.17`
(`sha512-ym3x2kzC…Ot+Hxw==`), each installed beside its own signals and web
(`/tmp/sc-rc17-audit/inst13`, `inst17`). Every rc.13 citation below was
re-checked on the rc.13 bytes. Function bodies were compared per build with
`scripts/forkA/fndiff.py`. The probe is `scripts/forkA/probe.mjs`, run under
Node with `--conditions=development` on `solid.dev.js`, `solid.js`,
`server.js` and `server.dev.js` of both releases.

Tags: **[M]** measured by probe, **[R]** read from source.

## Required checker changes (solid-js)

1. `releases.rs` `vocabulary_for`: `lazy_renders_component` must hold for
   `solid_js` rc.17 (A1). Read the release set as {13, 17}, not `>= 13`,
   because rc.14-rc.16 were not read.
2. B2 (`dynamic_options`): `dynamicCore` in `solid-js` now implements the
   option (A17). Re-own the answer: decide it from `solid-js` when web ≥ 17
   (or from both), update the `releases.rs` table row and the module docs
   ("`@solidjs/web` (`if (options?.static)`, from rc.9)"), the mixed-install
   gap text, and every `web.dev.js:2199` / `server.js:3729-3733` citation
   (`solid_2.rs`, `vocabulary.rs:92`, `static_api.rs:258`,
   `docs/rules/static-dynamic-async-source.md:35`).
3. New callback-taking exports need a modelled-or-excluded decision:
   `dynamicComponent`, `createDeferred`, `lazyModule`, `onHydrationEnd`
   (root), and `trackFillReads` (`solid-js/internal`) (A19-A22, A26). Add
   them to `exports/solid_v2_solid_js.rs` VALUES, with `DynamicOptions` in
   TYPES. Fix `materializeContainerTrace`, now under
   `solid-js/internal/container-trace` (A24).
4. Citation refresh only, no answer change: A4, A7, A8, A9, A11, A12, A13
   (mention the `edgeHooks.signal` wrapper in ADR 0338's server sentence),
   A16, A23.
