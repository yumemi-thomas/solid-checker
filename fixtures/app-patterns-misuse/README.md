# app-patterns-misuse

A recall ledger for application code: plain-Solid misuse patterns from real
apps, each with a misuse twin and a correct twin of one component. `cases.json`
is generated by `build_cases.py`. It is run through the misuse ledger's harness:

```sh
SOLID_CHECKER_NATIVE_BIN=... SOLID_TYPEFACTS_BIN=... \
MISUSE_CASES_ROOT=<an install with the audited Solid release>/.solid-checker-app-patterns \
node benchmarks/reviewed-package-models/development/misuse-runtime-ledger.mjs out.json <chromium> \
  --cases fixtures/app-patterns-misuse/cases.json
```

A case's runtime verdict is `detected` when the misuse twin raises the Solid
dev diagnostic its rule implies and the correct twin raises none. Its static
verdict is the checker's finding for that rule on the misuse twin;
`false-positive-on-correct` would mean a violation on the correct twin.

Measured 2026-10-06 on rc.13 with ADR 0204 (`docs/precision-backlog.md`):

- Runtime: 31 of 33 misuse twins raise their diagnostic in Chrome.
- Static, on those 31:
  - 29 are proven violations under the case's rule, including
    `callback-prop-called-in-render` (uncertifiable before ADR 0204) and the
    two cases ADR 0204 added, `hook-chain-reads-own-signal` and
    `default-parameter-read`;
  - 2 are proven violations under another rule: `body-read-in-condition` by
    `components-return-once`, and `child-props-destructured` by
    `no-destructure`.
- No correct twin gets a violation.
- The 2 runtime-silent cases (`on-settled-read`, `signal-in-tracked-effect`)
  are statically silent too.

## Corpus twins

`corpus-twins.json` holds 18 more misuse/correct pairs, each modelled on an
rc.13 corpus site found by the 2026-10-06 censuses: package option getters
(`@tanstack/virtual-core` 3.17.8, `@tanstack/table-core` 9.2.4), async
helpers whose synchronous prefix or default reads state in an effect, props
read in `For`/`Show` bodies and effect apply callbacks, and a native `find`
predicate during render. Each case names the corpus `install` whose
`node_modules` it imports from; `run-corpus-twins.sh` runs one ledger pass per
install.

Measured 2026-10-06 in Chrome on rc.13: all 18 misuse twins raise
`STRICT_READ_UNTRACKED` at the case file, and no correct twin raises anything.
The checker (ADR 0215) proves 4 of them, leaves 11 uncertifiable and is silent
on 3 (`ai-for-captured-forwarded-workspaces`,
`openbot-for-captured-conversation-snapshot`,
`openbot-show-request-prop-in-effect-apply`): the recall targets.
