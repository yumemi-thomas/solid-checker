# exported-helper-in-apply

**Claim (ADR 0963, batch 10b group C).** An exported function is entered by calls outside the project as well, so the claim that its code only ever runs in an effect's apply is not made; but the calls the walk sees are proven runs there. Chrome (rc.21) throws `PRIMITIVE_IN_EFFECT_CALLBACK` at a creation an exported helper makes when an apply calls it (imported, through a re-export under another name), and the program was certified clean: the walk answered nothing for an exported function, and the ADR 0710 ownerless premise (an exported function may be a component and run under its render's owner) hid the unplaced net too. The creation is an uncertifiable row of SC6002 (one proven run with others the walk does not prove is an obligation, ADR 0516), never a violation.

`App.tsx`: `InApply` calls `createsMemo`, `arrowCreates` (an exported `const` arrow) and `viaLib` (`createsMemo` re-exported as `viaLib` by `lib.ts`): two rows in `helper.ts`. `LocalTwin` calls the same helper not exported: the violation, as before. `ThroughSelfImport` calls a `const` arrow that `export { selfConstLocal as selfConst }` exports, through a self-import of `App.tsx`: the call graph withholds that call (ADR 0339: a `const` is not hoisted, and a call through an import cycle may run before its declarator), the walk follows it as a run it does not prove: an uncertifiable row of SC6002, where it was certified clean. `ThroughSelfImportFunction`, the same with a `function` (hoisted, its edge kept): an uncertifiable row of SC6002 (`effect-owner-unproven`), as an exported helper is. It was a violation until ADR 0970 (R1 of the re-review of #221): `module_exports` took an export statement that contains the function, or Type Facts' export flag, for an export, and `export { selfFunctionLocal as selfFunction }` is a specifier, so the function counted as unexported. A function an export specifier publishes is an export like one its declaration publishes: the one proven run does not make the claim (ADR 0516). The only violation any snapshot lost to this change. Silent: `FromHandler` (an exported helper only an event handler calls: `onlyFromHandler`'s creation has no run in the effect phase).

The flush variant (SC2008) is `runtime-oracle/flush-in-effect-callback`'s `OtherFile`: its `open` entry, an exported helper's flush, is removed with this change, the checker has an uncertifiable row at the site now. The cells are `ob-exp-*` (ob-shapes.mjs).
