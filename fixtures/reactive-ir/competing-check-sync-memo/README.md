# competing-check-sync-memo

**Claim (ADR 1052, part 2).** `createMemo(async, { sync: true })` reports SYNC_NODE_RECEIVED_ASYNC (SC7002) at its result probe, after every creation guard. Where an earlier check at the creation throws (an SC6002 violation or its `effect-owner-unproven` obligation: the effect-callback guard; an SC3001 violation written at the call: the leaf owner's refusal), SC7002 is uncertifiable `creation-throws-first`:

- `MemoInApply`, `NamespaceMemoInApply`: PRIMITIVE_IN_EFFECT_CALLBACK first.
- `MemoInTracked`, `MemoInSettled`: PRIMITIVE_IN_FORBIDDEN_SCOPE first (a call written in the leaf callback, every run of which is refused).

Part 5: `MemoInTrackedHelper`, `MemoInTrackedOnlyHelper` (a helper every reference to which is a refused call) and `MemoInGuardedRenderApply` (a render effect's apply the owned first run may leave before the creation) are uncertifiable. Part 6: `MemoInRerunCleanup` (a cleanup the rerun calls inside the effect callback) and `MemoInActionFromSettled` (an action only a leaf callback calls) are uncertifiable. Violation kept: `MemoInNeverRerunCleanup` (only the disposal calls the cleanup), `MemoInActionFromApply` (an action step lowers the effect flag), `MemoInBody`, `MemoInRenderApply` (straight line: the owned first run probes), `MemoInTrackedAndBodyHelper` (the body calls the helper first). Part 8: `MemoInSlotCalledInApply` (a module slot only an effect's apply calls), `MemoInNamedPropApply`, `MemoInForwardedPropApply`, `MemoInSpreadPropApply` (a callback prop an effect's apply calls, through a named function, a forward, a spread: SC6002 a violation) and `MemoInPropSettled`, `MemoInForwardedPropSettled` (only an owned `onSettled` calls it) are uncertifiable; `MemoInSlotCalledInRenderApply` (the owned first run probes), `MemoInForwardedPropAlsoInBody` and `MemoInPropUnownedSettled` (`onSettled` from a handler is no leaf owner) keep the violation. Part 9: `MemoSharedApplyAndHandler`, `MemoSharedTrackedAndHandler` (a helper refused at mount and a handler of the same mount, which `render` disposes on the throw) are uncertifiable; `MemoSharedApplyAndTimer` and `MemoSharedConditionalApply` keep the violation. Part 10: `MemoInRemovedListener` (a listener on a fresh element only an owned `onSettled` fires, removing it) is uncertifiable; `MemoInAttachedListener` and `MemoInRemovedListenerBlurredInBody` keep the violation. The earlier checks keep their own rows.

Part 9's mount premise: `MemoSharedDeferredApplyAndHandler` keeps its violation. A `defer: true` apply does not run at mount, so nothing refuses the helper before the handler's flush runs it (mx-recall `effect-apply-defer-flush-rerun`, a proved verdict part 9 lost).
