# later-assigned-function

**Claim (ADR 0535 amended, batch 11).** A function the program assigns to a variable after its declaration (`let h = () => {}; h = () => flush(); h();`) holds the value written last, and every call of the name resolves to the declaration's initializer or to nothing. The assigned function has no binding name, so every walk that asks who calls a function (`runs_unplaced_once`, the effect-phase origin, the read nets) read "nobody" and placed a site in it nowhere: a `flush()` in an effect's apply or an action's step, or a primitive created in an apply, was certified clean while Chrome (rc.21) reports FLUSH_IN_EFFECT_CALLBACK, FLUSH_IN_ACTION and PRIMITIVE_IN_EFFECT_CALLBACK at it (15 generator programs, `la-*`; the real oracle gave `unproven-clean` in the action and effect hosts). The member forms (`o.f = …`) were an obligation since ADR 0535. A function written as the value of any assignment is one nothing places: an uncertifiable row (`function-run-unplaced`) at the site, never a violation and never silence.

`App.tsx`: `LetLater`, `LetNoInit` (`let h: () => void;`), `LetOther` (assigned inside another function, `set()` then `h()`), `LetCreates` (a primitive created, SC6002) and `StepLater` (an action's step, SC2006) are the rows this change adds (SC2006 and SC2008 at a `flush()` an apply or a step may run, SC6002 at the creation). `LetEarly` (called before the reassignment), `MemberLater` and `ElementLater` are rowed as before (a binding the walk does not resolve, a member and an element the census withholds). Silent: `NothingToFind`, the same shape with no site in the function assigned.

The fixture's runtime-oracle twin (`fixtures/runtime-oracle/later-assigned-function`) runs the same file against the real packages. The violation arm of SC2008 needs the runtime packages' source, which this stub environment lacks: a `flush()` called directly in the apply is silent here and a violation there.
