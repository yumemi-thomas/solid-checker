# SC2003: the setter window is a dynamic extent (ADR 0476)

A write the own setter's callback schedules (`queueMicrotask`, `setTimeout`, `.then`, after an `await`) is a violation; one on the callback's stack (an IIFE, `forEach`, a helper calling its callback) is silent, and so is a function defined outside whose every call is inside the setter (`CalledInside`). Called outside too: violation (`CalledBoth`). Silent too: the callback named by the argument (`setStore(byName)`), an exact `const` alias of the setter. Handed on, given to an unknown function, through a method (`api.run()`), a caller chain deeper than followed, an IIFE in JSX inside the callback, after an `await` in an async compute function: uncertifiable. Past the root (`PastFrozenLink`): uncertifiable; the root write is a violation. See `docs/rules/no-store-mutation-outside-setter.md`.
