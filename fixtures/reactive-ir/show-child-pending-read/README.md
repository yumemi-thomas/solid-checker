# show-child-pending-read

Claim (ADR 0836): a read in a closure handed on from a control-flow child callback with a parameter (`<Show when={1}>{(_u) => { hc1(() => { pending(); }); … }}</Show>`) is not rendered in a tracked insert: the only JSX around it is the element whose child the callback is. `Forwarded` is uncertifiable for the pending rules (SC5001, SC5003), never the SC5003 violation it was (rc.21 in Chrome: PENDING_ASYNC_UNTRACKED_READ only; W's recall rows `flow-show` forward-2/13, 12 false positives confirmed by Part 13). `InChild`, the read in the child's own body, stays SC5001's violation. This fixture has no mount, so the build before answered `Forwarded` SC5003 uncertifiable (`mount-unresolved`); the grid ids hold the violation it gave under a `render()` mount. Stubs as in `flow-iife-tracked`.
