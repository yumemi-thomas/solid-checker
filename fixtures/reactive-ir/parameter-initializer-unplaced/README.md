# parameter-initializer-unplaced

**Claim (ADR 0961, PD).** A site written in a parameter initializer (a default value, a destructuring default, an IIFE, a closure or a helper call in one) of a function that is called or referenced anywhere in the program runs when a call of the function omits the argument. Every net asked about code in a function BODY, so a flush in `function h(x = flush())` an action's step calls was certified clean while Chrome (rc.21) fires `[FLUSH_IN_ACTION]` there (and FLUSH_IN_EFFECT_CALLBACK, PRIMITIVE_IN_EFFECT_CALLBACK in an effect's apply). No walk reads which calls omit the argument, so the site is an uncertifiable row of the rule that asks (SC2006, SC2008, SC6002; `parameter-initializer-unplaced`), never a violation and never silence.

`App.tsx`: `viaValue`, `viaArrow`, `viaIife`, `viaClosure`, `viaHelper`, `viaDestructured`, `viaGenerator` (an action's step calls a function whose default holds the flush: SC2006, and SC2008 beside it: the flush may also run on an apply); `viaMethod` (a method's default: the same row); `viaPassed` (the argument is passed, Chrome is quiet, the row stays: a coarse rule); `InApply` (SC2008 for the flush default, SC6002 for the creating default). Silent: `ownDefault` (the action's own step generator: its parameters are evaluated when the action creates the generator, before the first step, ADR 0454) and `unused` (nothing calls or names it).

The leaf-scope hosts (`onSettled`, `createTrackedEffect`) are covered by SC9012 withholding rows (`leaf-callback-opaque`, `value-as-parameter-default`) at the helper's call, as before; the fuzz cells `pd-*` judge them.

Since the flip of ADR 0967's default (the review of #216) this fixture's program has an open boundary (no `.solid-checker/runtime.json`), so each `flush()` written in an exported function keeps an uncertifiable row of every code its program censuses ruled out (SC2006 `flush-in-action-unaccounted`, SC2008 `flush-in-effect-unaccounted`, SC3001 `leaf-operation-unaccounted`): an export may be entered by code this build cannot see, an action's step among it. The snapshot's additional rows are those; the claim above is unchanged.
