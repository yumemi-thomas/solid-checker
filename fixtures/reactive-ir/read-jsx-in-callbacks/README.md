# read-jsx-in-callbacks

**Claim (ADR 0470).** A read in a JSX expression the compiler wraps runs in what the compiler makes of it, wherever the JSX is evaluated: a child or a dynamic attribute in a render computation (`insert(el, r)`, `effect(() => String(r()), …)` at the pinned `@solidjs/compiler@2.0.0-rc.17`), a component prop or child in a getter the receiving component reads. So it never runs in the strict-read window of the `createRoot` / `runWithOwner` callback, effect apply or handler that builds the JSX. Legal (rc.17 silent, fast path): `RootChild`, `RootAttribute`, `RootNamespaceChild`, `RootStoreMemberChild`, `RootComponentProp`, `RootComponentChild`, `RootIifeInChild`, `RootForEachChild`, `OwnerChild`, `UntrackChild`, `HandlerChild`, and `ApplyChild` (rc.17 throws PRIMITIVE_IN_EFFECT_CALLBACK at the insert instead; no rule here claims it). Before, `RootChild`, `RootAttribute` and `RootComponentProp` were reported SC1001 violations and `RootComponentChild` was uncertifiable.

Violations (rc.17 warns STRICT_READ_UNTRACKED): a read in the callback's own body, beside the JSX (`RootBodyRead`, `RootBodyBesideJsx`, `OwnerBodyBesideJsx`, `ApplyBodyRead`); only that read is reported. Stub: rc.17 shapes (copied from `read-in-place-layers`).
