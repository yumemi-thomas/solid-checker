# callback-runs-1109

**Claim (ADR 1109).** Three findings of the ADR 1106 review (`coord-land/review-1106.md` section 2 and F2), each Chrome-checked in `fixtures/runtime-oracle/callback-runs-1109`.

- **P1.** A helper's call of its parameter after a statement that may throw, in a `try` whose `catch` completes normally, is not on every completion: a throw there is caught and the `try` completes without the call. `TryThrowMember` (SC1001) goes violation → uncertifiable (`callee-callback-timing`); Chrome never runs the callback. `TryThrowDestructure` (SC1003) stays a violation: SC1003 reads a call on some path as reachable (as it does for `BranchDestructure`, `if (Math.random() > 2) f()`), and nothing proves `JSON.parse("x")` throws. Twins that keep the violation and run in Chrome: `TryRethrowMember` (the `catch` only rethrows), `TryFinallyMember` (no `catch`, a `finally` with no jump), `PlainHelper`. Cost: `TryCallFirst` (the call first in the `try`) goes violation → uncertifiable, though nothing before it can throw.
- **P2.** A standard inline callback that never runs: `NamedEmptyForEach` (a `const` holding `[]` whose only reference is the receiver of a non-filling iteration method) and `OneElementSort`/`OneElementSortMember` (`[1].sort(cmp)`, one element is never compared) go violation → uncertifiable (`function-unentered`, ADR 1019's ruling: a site that provably never runs is U). Twins that keep the violation and run in Chrome: `TwoElementSort`, `NamedFilledForEach` (the name is pushed to), `NamedEmptyHanded` (the name is handed to a helper that fills it).
- **F2.** A store handed through a standard inline callback's parameter, `[st].map(({ v }) => v)` (`MapParamDestructure`) and `[st].map((s) => s.v)` (`MapParamMember`), had no row while Chrome warns STRICT_READ_UNTRACKED; it is now an SC9012 uncertifiable (`value-in-carrier`) at the literal. `MapParamPlain` (a number, not a store) has no row.

`BranchMember` stays SC1001 uncertifiable, as on main.
