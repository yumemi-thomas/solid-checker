# prop-callback-roles

**Claim (ADR 0400).** A function handed to a project component as a prop (a literal, or a same-file function named by identifier) takes, for its writes, the role of each place the component calls `props.<name>`; the answer is the join of those places. An invocation in an owned scope (the component's body, a tracked computation) makes the write `SC2001` whatever else the prop does (ADR 0378's entries rule, so a handler beside a body call still violates); a DOM event gives a clean write with no owner; a leaf scope exempts it. A prop forwarded to another component is followed to that component's uses. The child must resolve exactly and every use must be one the walk follows (`props.<name>` calls and member reads, a `const` alias, a prop forwarded to another project component, an intrinsic handler): a destructured parameter, a spread onto a component, a stored or `let`-aliased function, a call through a `merge` view and a package component known only by its declarations leave the obligation. The same program is open: what a child does with the prop does not depend on its other callers.

`UsesInLeaf` and `UsesInMemo` differ in the write only: the read in a leaf scope or tracked computation is no strict read. Stubs: `solid-js.d.ts` is `forwarded-event-prop`'s, whose `createMemo`, `createTrackedEffect`, `merge` and `omit` are the published rc.9 declarations.
