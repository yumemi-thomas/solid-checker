# owner-after-await

An owner-requiring operation (`onCleanup`, an effect) that runs after an `await` on every path through its async function has no owner, whatever it was entered with: a proven `SC4001` (`owners::AwaitContinuations`) in `cleanupAfterAwait`, `effectAfterAwait`, `cleanupInTry` and the exported `exportedCleanupAfterAwait`. Before the first await is silent; one-branch awaits and non-awaiting catch paths are uncertifiable (ADR 0357). An owner restored with `runWithOwner` (`cleanupUnderCapturedOwner`) is not a violation but stays an `SC4001` uncertifiable result. Runtime (rc.0-rc.9): `getOwner()` is `null` after the `await` (`NO_OWNER_CLEANUP`/`NO_OWNER_EFFECT`). Stub: `fp-owner-leaf-helper-after-await`'s plus `getOwner`/`runWithOwner` verbatim from rc.9.
