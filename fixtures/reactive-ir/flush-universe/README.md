# flush-universe

**Claim (batch 11, slice 5).** Every flush the flush census lists ends, per code, in a row of that code's rule at the site, an SC9012, the compiler's discard, a typed reason (`flush_accounting.rs`, `FlushSafe`), or an uncertifiable row of the code's own rule: SC2006 `flush-in-action-unaccounted` (the flush may run in an action's step), SC2008 `flush-in-effect-unaccounted` (in an effect's apply), SC3001 `leaf-operation-unaccounted` (in a leaf owner's callback). Never a violation. Before this, a flush no producer rowed was a clean nobody accounted for: every producer's silent exit (`unplaced_blocker` answers "placed off" for a function no call edge reaches, a body that may be a component, an owner set around the call, as well as for a proof) read the same.

`App.tsx`: the program steps an action, runs an effect's apply and opens a leaf scope, so no program-wide reason holds. `save()` is the one uncertifiable row of each code (three rows): its every invocation is an event delivery (the census's `EventHandler`), which rules no code out, since a delivery may be dispatched from a step (owner ruling 5a: a give-up is not a reason, the site stays uncertifiable). Silent, each on a typed reason: the callback `setTimeout` runs (`FreshStack`), the code past an `await` (`AwaitContinuation`), module evaluation (`ModuleInitialization`), a function nothing enters (`NeverRuns`). `SOLID_CHECKER_IR_ABLATE_SILENCE=all` (or a reason's id, `flush_accounting.account.<end>`) drops the reasons: each of the four then has a row of each code (15 rows, one reason ablated alone gives the three of its own flush).

Siblings: `flush-universe-no-action` (no action in the program: SC2006 ends on `NoSteppedAction`, SC2008 and SC3001 stand), `flush-universe-bare` (no action, effect or leaf scope: all three codes end on their program census), `flush-universe-test-runner` (a flush written directly in a scheduled test callback ends on `TestRunner`; the helper only the tests call, `TestHelper`, does not).
