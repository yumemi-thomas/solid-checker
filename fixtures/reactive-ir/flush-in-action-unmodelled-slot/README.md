# flush-in-action-unmodelled-slot

**Claim (ADR 0959).** Inside an action's step, a callback of a primitive that runs it in place (`untrack`, `latest`, `runWithOwner(null, …)`, `createRoot`) with a parameter the primitive may never pass, or an `async` one, runs on the step's stack: its first synchronous part flushes inside the step, and Chrome (rc.21) throws `[FLUSH_IN_ACTION]` there. The slot climb crosses such a callback as an obligation, so the flush is an uncertifiable row of SC2006 (`function-run-unplaced`), never a violation and never silence. The plain callback stays the walk's proof (`plainUntrack`: a violation); a parameter callback that flushes nothing (`quiet`) and a flush outside an action (`Handler`) have no row.
