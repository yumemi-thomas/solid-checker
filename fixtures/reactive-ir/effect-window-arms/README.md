# effect-window-arms

ADR 0540: full-7 (2026-11-01) reported 1,884 false positives on legal rc.17 programs. (1) 400 SC1001 in an effect bundle's `error` member reached through a closure: the bundle object is the apply argument, and `direct_callback_contains` took its largest function as the apply. rc.17's `runEffect` calls `_errorFn` before it opens the strict-read window (`@solidjs/signals@2.0.0-rc.17` `dist/dev.js:1966-1989`). ErrorArm's reads are silent at every layer; BundleEffect's reads in the `effect` member (arrow or method) keep the apply's role (they stay obligations, as before); SpreadBundle, whose members are not exact, is an obligation. (2) 1,484 SC2001 in a `createReaction` callback reached through a helper or an IIFE: the write climb stopped at the callback and took the component body's role. The callback runs as its effect's apply from the flush with no owner (`dist/dev.js:2653-2664`), so ReactionWrite's writes are legal at every layer, and so are ReactionAction's action calls (full-7: 550 SC2002 false positives, the same climb). MemoWrite's write through a layer in a memo compute stays a violation. ReactionBundle's `error` read is an obligation (unchanged): the reaction slot has no error-arm placement yet.
