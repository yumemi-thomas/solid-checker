# resolve-inline-entries

Claim (ADR 0857): `resolve` and `until` throw on an active observer. `flush(fn)` runs `fn` before it drains, with the caller's observer (rc.21, Chrome), so `FlushInJsx` and `FlushInMemo` are violations (both were certified). A function a tracked expression runs by a direct call is run under that observer: `Called` is a violation (was uncertifiable). `Mapped`, `[1].map(Row)`, throws in Chrome too, but `Row` returns JSX and the component census takes it for an escaped component, whose violations are obligations: uncertifiable, `component-identity-unproven` (was certified). `Empty`, `[].map(Row)`, may run nothing: uncertifiable (was certified). Clean: `Tag`, `<Row />` renders a component, whose body has no observer; `Untracked`, `untrack` clears it. Stubs: rc.21's `solid-js`, `@solidjs/signals` and `@solidjs/web` versions; `solid-js.d.ts` as strict as the published typings for what it calls. Amendment (reviews R13, R16): a walk that stops proves nothing about the entries it did not read, so the call is open however its own role reads: `PastTheBound` is uncertifiable, `search-depth-limit`; `Stepped` is uncertifiable, `function-run-unplaced`. `AsyncPrefix` runs on the call's stack: a violation. `AsyncSuffix` is past the await: clean.
