# after-await-promise-unconsumed

**Claim (ADR 1090 G1, not built).** The proposal was this: rc.21 raises UNTRACKED_READ_AFTER_AWAIT only for a read whose V8 async stack holds an async computation's flight frame (`@solidjs/signals` `dist/dev-shared.js` `watchAsyncTail`, `attributedFlight`), so a read in a function whose promise nothing consumes could not be attributed. Four reviews each found false cleans, and the discharge was removed. Every case here documents one: rc.21 attributes by the frame's name (`^__solidAsyncCompute_(\d+)$`) and stack, so "nothing consumes the promise" does not bound where its reads run. Every case is uncertifiable, and the twin `awaited` stays a violation.

Uncertifiable: `fire` (a discarded call, the case the proposal would have ended), the two `.then` handlers (no exact fact says the receiver is a native promise; `Kept` is a subclass that keeps its instances), `looped` (its loop reads before the first await), `classed` (the read is a class field initializer, run where `new` runs), `built` (the site is a call returning a class), `jsxed` (the read is a JSX attribute, a getter), `scripted.ts`'s `fire` (`export {}` is erased, so the file may be a classic script), `voided` (`void f()`: the promise is an operand), `stored` (the promise is kept), `exported` (a host may call and await an export, referenced or not), `chained` (the derived promise is returned), and `awaited`, which an async memo awaits: its read is the producers' (Chrome reports UNTRACKED_READ_AFTER_AWAIT there).
