# primitive-in-effect-callback

SC4005 `primitive-in-effect-callback` on the audited `2.0.0-rc.17` triple. A user effect's apply is queued and runs from the flush, not under any owner, between `setEffectCallback(true)` and `setEffectCallback(false)` (`@solidjs/signals` `dist/dev.js:1994`, `:2024`). rc.17's `createOwner` and `setupComputedNode` both call `assertNotInEffectCallback()` (`dist/dev-shared.js:1496`, `:4927`), which throws `PRIMITIVE_IN_EFFECT_CALLBACK` while the marker is up and the context is null (`:3947-3957`); the production build creates the computation and nothing owns it. The typings accept the calls (`EffectFunction` returns `(() => void) | void`; `createRoot`, `createMemo` and `createDeferred` take any callback), so `tsc` is clean, and the stubs are byte-faithful for the signatures the claims rest on (see their headers).

Violations (12): `createRoot`, `createMemo` and `createDeferred` directly in an apply; through a non-exported helper only applies call (also a chain of two, and an async helper before its first `await`); a namespace member; an `untrack` callback and an immediately invoked function written in the apply; a memo in a branch; and the outer call of a root holding a memo and of a memo holding a root (the inner call runs under the outer's own owner or never runs).

Silent: `createSignal` (inert there); `onCleanup` and the effect constructors in an apply (SC4001's claim: it reports them and this rule adds no second finding); a primitive under `runWithOwner(owner, …)`; after an `await` in an async helper; in a callback handed to a timer or microtask, or a stored closure; a `createRenderEffect` apply (its first run is synchronous at creation, so the rule cannot tell runs apart); the `createEffect` compute function; a helper with a caller outside the effect phase (the module body, an event handler, an alias), a generator, a reassignable binding, an exported helper (`memo.ts`) or a member of an object; an apply passed by name; a shadowing local named `createMemo`. `unresolved.ts` passes an apply from a module that does not resolve: nothing is placed, and SC7001 is the only result. The rc.13 twin is `primitive-in-effect-callback-rc13`; `fixtures/runtime-oracle/oracle-rc17-primitive-in-effect-callback` runs the positives and a `runWithOwner` control in Chrome against the real packages.
