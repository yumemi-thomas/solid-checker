# leading-token-after-await

**Claim (ADR 0376).** SC1002 names an async computation, and a prop read after an await, from exact spans only. `createMemo(fetchMember.sync)` hands over the expando member, so `fetchMember`'s read after its await never runs as a computation (before: SC1002 through the leading token `fetchMember`). `props.load().value` reads the box `load` returns; its leading token `props` and the leaf `value` made it a read of the reactive prop `value` (before: SC1002). A props chain is rooted at an identifier through static members only, and its prop is the root's own member (`props.a.b` reads `a`). Controls: `createMemo(fetchCalled)` and `props.value` after the await stay SC1002 violations. Owners: `AsyncComputations::new`, `member_reads_after_await`, `plain_member_chain_root` in `static_rules.rs`. Stub: `fp-owner-component-ref`'s (published rc.9 typings).
