# arrow-bound-helper-module-loads

**Claim (ADR 0339).** A call of an imported `const`-bound arrow proves it runs only where the importer cannot run before the declaring module. A load the import graph does not order (`import x = require("m")`, a `require("m")` call) is an edge of that graph: `impeq-a.ts` loads `impeq-b.tsx`, which imports `impeq-a.ts` back and calls `helper` in a module-level `createRoot`, so evaluating `impeq-a.ts` first runs the call with `helper` uninitialized (ReferenceError); `req-a.ts` does the same through the global `require`, and `shim-a.ts` through a `declare function require` shim that shadows it in the binder (a call of a bare `require` the facts did not record as a load is an unmodeled one). Both stay uncertifiable or silent, never a violation. Stubs are the arrow-bound-helper-reachability stubs (published rc.13 typings); `SC9014` is the missing `@solidjs/signals` install.

Loads no import statement shows (ADR 0339): `glob-a.ts`/`glob2-a.ts` (an `import.meta.glob(…, { eager: true })` becomes static imports), `bridge-a.ts` (a relative import that resolves to `bridge.d.ts`, whose runtime `bridge.js` is project code no analyzed file carries) and `ambient-a.ts` (`declare module "virtual:b"`) put their module on a possible cycle; the module's helper stays uncertifiable. `lazy-a.ts` is the control: a lazy glob (no options, or `eager: false`) is a dynamic import and orders nothing, so its helper is proven. An installed dependency (a package under `node_modules`) is assumed not to import the project (no self-reference back into the app); that premise is in the ADR.
