# iteration-written-slots

**Claim (ADR 0349, ADR 0803).** A program that writes the array iterator visibly (`patch.ts`) has no exact array pattern of a primitive: `const [s, set] = createSignal(1)` may hold anything the patched iterator hands it. `body-write`'s `set(2)` and `s()` are uncertifiable (SC9012, `tuple-iteration-written`), never SC2001. Chrome (rc.21): quiet, the patch hands back a no-op setter (pattern `types/s04-local-setter-iteration-written`). Without `patch.ts` the same body is a proved SC2001 (Chrome REACTIVE_WRITE_IN_OWNED_SCOPE), as every other fixture's tuple still is.

Variants (each `patch.ts` beside the same body):
- `next-alias`: `IP.next = f` through `const IP = Object.getPrototypeOf([][Symbol.iterator]())`, which ADR 0349's spelling misses. Uncertifiable; Chrome quiet.
- `reflect-alias`: `Reflect.set(AP, Symbol.iterator, f)` through `const AP = Array.prototype`. Uncertifiable; Chrome quiet.
- `class-prototype` (negative): `Foo.prototype.bar = 1` on a project class spells `prototype`, and ADR 0282's census clears it. Proved SC2001; Chrome warns.
- `named-key` (negative): `Object.assign(Array.prototype, { zzz() {} })` writes a literal key that is not iteration's. Proved SC2001; Chrome warns.
- `key-alias`: `AP[k] = f` through `const AP: any = Array.prototype`, a key no literal names. Uncertifiable; Chrome quiet.
- `hook-object`: the slots leave a hook in an object (`return { count, setCount }`); the call `setCount(2)` in the body is uncertifiable at the call, not only at the hook's reference.
- `prop-value`: a caller passes a withdrawn slot's read as a prop (`value={level()}`, `value={state.x}`) and the child reads it in its body (`createSignal(props.value)`). The withdrawn slot stays a source, so the reads keep their rows, but the prop's backing is unproven: SC1001 uncertifiable, `read-backing-unproven`, never SC1001 violation from a slot the patch may have replaced. Chrome warns here (this patch replaces only setters): uncertifiable, not wrong.
- `prop-value-intact` (negative): the same without `patch.ts`. Proved SC1001 twice.
- `open-compute`: a memo whose compute calls a withdrawn slot. The slot may be any function, so the memo's provenance is open (ADR 0665): SC5003 uncertifiable, `async-provenance-unproven`, at the JSX read.
- `open-compute-intact` (negative): the same without `patch.ts`. Certified.
- `function-escaped`: a `Function` held in a parameter runs a string that patches iteration (pattern `types/s03`). No write spells it; ADR 0801's census (code from a string) withdraws the slots. Uncertifiable; Chrome quiet.
- `compared-prototype` (negative): `!(proto = Object.getPrototypeOf(obj)) || proto === Object.prototype`, a prototype only compared, as router and store code writes it. No intrinsic is handed on: proved SC2001; Chrome warns.
- `uncalled-accessor` (review a9fc #7): `${count}` of a withdrawn slot. upstream_compat's uncalled-accessor arm takes `count` for the primitive's accessor; the static row is held by place: SC1005 uncertifiable, `tuple-iteration-written`. `uncalled-accessor-intact` (negative): proved SC1005.
- `global-alias-hook` (review a9fc #1): the patch reaches `Array.prototype` through `const g = globalThis; g.Array.prototype` under a key no literal names, and the hook returns a 3-tuple the patch reorders (Chrome: `now` is the setter, REACTIVE_WRITE_IN_OWNED_SCOPE). The global object handed on withdraws the hook's slot: `now()` has its own row, uncertifiable.
- `handed-seen-listener` (negative, review a9fc #1 step 2): `bindEvent(window, ...)` into a project function that only calls `target.addEventListener` with an arrow that takes no parameter: the global object reaches seen code that hands nothing on. Proved SC2001.
- `handed-listener-param` (review D3, negative since the follow-up): the caller's listener passed through (`addEventListener(type, handler)`) is read at the call that hands the window on: the literal reaches nothing. Proved SC2001; `handed-bind-reads-window` is the listener that does reach it.
- `handed-unseen`: the same call into a function with only an ambient declaration (no source): unseen code receives the global object, so the slots are withdrawn. Uncertifiable.
- `handed-proto-writer`: `itSet(Array.prototype, Symbol.iterator, f)` into a project function that writes `p[k] = f`: seen code writes the intrinsic under a key no literal names. Uncertifiable; Chrome quiet.
- Reviews R2 and R7 (ADR 0803 step 2), each uncertifiable: `handed-map-function` (`[[code]].map(Function.apply.bind(Function, null))`, the spelling that runs: a standard function that calls what it is given is no seen code), `handed-call` (`patch.call(null, globalThis)`: `call` runs its target with the arguments shifted, and `patch` writes `Array.prototype` through its parameter), `handed-timer` (`setTimeout(patch, 0, globalThis)`: a timer schedules its arguments), `handed-stored-map` (`new Map([[1, Array.prototype]])`, written back out of the map), `handed-global-stored` and `handed-global-returned` (the global object kept in an object, or returned from a function, then written through).
- `handed-call-seen` (negative): `listen.call(null, window, "resize")` into a project function that only calls `addEventListener`: the shifted argument reaches seen code that hands nothing on. Proved SC2001.
- `handed-signal-held` (review D1): `Array.prototype` kept in a signal and written back out of it. The dialect's runtime hands back what it keeps, so it is no seen code that keeps nothing. Uncertifiable; Chrome quiet.
- Review D3, each uncertifiable: `handed-listener-this` (a function listener that mentions `this`), `handed-listener-event` (an arrow listener that reads its event), `handed-on-handler` (`window.onresize = (event) => ...`), `handed-timer-this` (a timer calls a function callback with the window as `this`), `handed-window-this` (`window.open()`: a method of the window outside the closed list runs with it as `this`).
- `handed-window-seen` (negative): a listener that reaches nothing, `scrollTo`, `getComputedStyle`, `onresize = null`, and timer callbacks that never mention `this`. Proved SC2001.
- `handed-default-view` (review R12): `document.defaultView` is a window by its type, and its `Function` runs a string that patches iteration. Uncertifiable; Chrome quiet. `handed-default-view-intact` (negative): the same value tested and only asked for `getComputedStyle`, and a destructured `top` and a member `parent` whose types are no window. Proved SC2001. `handed-default-view-optional` (negative): the same call as `view?.getComputedStyle(...)`: the value is a window, so its method is the window's by key. Proved SC2001.
- Review D4, each uncertifiable: `handed-any-default-view` (`(document as any).defaultView`: a window name whose value is `any` may be the window) and `handed-object-listener` (a `{ handleEvent }` listener is no function literal the checker can read). Sloppy code's `this`: fixtures `sloppy-this-dependency` and its siblings.
- Reviews R19a to R58, the settler and the callbacks ADR 0803 step 2 reads at the hand-off: `variants/README.md`.
