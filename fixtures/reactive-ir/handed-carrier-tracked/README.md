# handed-carrier-tracked

**Claim (ADR 0776).** A named function a carrier provably runs at a tracked position reads there, with no boundary: a proved SC5003 (`[1].map(hf)`, `hf.call(null)`, a module function, a two-element `sort`). A carrier under `Loading` with the function outside it (`g2a`) and an empty literal (`g2b`) raise no SC5003 and no violation: the cover and the run are the carrier's, not the function's. `g2b` stays certified. `g2a` was certified too, and since ADR 0968 (batch 11, slice 4) it carries one uncertifiable SC1001 `strict-read-unaccounted` at `a1()`: the read ended in the async-read table's row, which answers that table's codes and not STRICT_READ_UNTRACKED, and no named ending proves the carrier's tracked run silent for that code yet. Chrome is quiet (the run is tracked): the cost of ending a site per code, not a defect.
