# flush-in-tracked-named-async

**Claim (ADR 0959, slice 5's lead).** `isPending(fn)` takes what `fn` throws, so a `flush()` in a synchronous callback of a leaf owner (`createTrackedEffect`, `onSettled`) raises nothing. An async callback's synchronous throw is the rejection of the promise it returns, which `isPending` does not catch (ADR 0960 measured the literal form), and Chrome (rc.21) throws `[FLUSH_IN_TRACKED_QUEUE_CALLBACK]` at the flush. The literal `isPending(async () => { flush(); })` was an obligation (ADR 0959); a callback named at module scope went through another reader (`slot_callback_operations`), which took the slot's swallowing for every callback, so the program was certified clean for SC3001 (Chrome confirmed it on main 3b22442d4). An async callback, named or reached through a function the callback calls, is an uncertifiable row of SC3001 at the `isPending` call (`leaf-owner-unproven`), never a violation (ADR 0959's coarse rule) and never silence.

`App.tsx`: `NamedAsync` (an async arrow bound by name), `DeclaredAsync` (an async function declaration), `WrappedAsync` (`isPending(() => rejects())`: the arrow returns the rejected promise), `SettledNamedAsync` (the other leaf owner). Silent: `NamedSync` and `WrappedSync` (the throw is the callback's own, which `isPending` takes) and `NamedAfterAwait` (the flush follows an `await`: off the leaf owner's stack).
