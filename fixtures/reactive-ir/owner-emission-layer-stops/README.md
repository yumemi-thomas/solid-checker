# owner-emission-layer-stops

**Claim (batch 11, the follow-up to the review of #220 and of #221; ADR 0970).** The owner emission (SC4001) asks `named_layer_entry_open` whether a layer around an owner-requiring operation (`onCleanup`, an effect, a context read) may be entered by a route the owner graph holds no edge for, so that the owned context its edges give is no proof of every run. It adopted the premises the owner-call universe gave the same walk: a component is entered by renders alone only where every reference of its binding is a JSX tag (fixture `owner-emission-component-by-reference`), and two stops of it that let a layer through (N1 and N2 of the check of B1 on #220):

- **N2, the stop at an owner-creating layer returned before the function's references.** `createRoot(function f() { if (!saved) { saved = f; return; } onCleanup(..) })`: the root runs the callback at once and it saves itself, a later `saved()` from a timer, a handler or an effect's apply runs it on its own stack under no owner. A callback an owner-creating primitive runs (or a control-flow child) is now entered by that position alone only where nothing references it (`referenced_only_by_entry`).
- **N1, the caller walk took a generator's body for a placed run.** A layer that is a generator (and, through the caller walk, any function its body calls) is an open entry: its body runs where an iterator is stepped. The emission already answered a helper called from a generator's body on main (its generator-step obligation), so the cell stays uncertifiable on both builds.

| `onCleanup` in `StepHelper`'s `helper`, called from the generator a timer steps | SC4001 uncertifiable | N1: no owner is current where the iterator is stepped (Chrome: NO_OWNER_CLEANUP); uncertifiable on main too |
| `onCleanup` in `NamedUnreferenced`'s root callback, a name nothing references | silent | the stop holds: only the root enters it |
| `onCleanup` in `PlainCaller`'s `helper`, called from a plain function the body calls | silent | no generator and no reference but the call: rendering enters it |
| `onCleanup` in the arrow `Wrapped = hoc(() => { .. return <p/> })`, `hoc` calling its argument from a timer | SC4001 uncertifiable | B1 of the review of #221: the census takes the arrow for a component (`hoc_bound`), but a function handed to a call is entered by whoever the callee is; only a primitive's position and a standard-library call that runs it inline place it. **The false clean this fixes** (Chrome: NO_OWNER_CLEANUP) |
| `onCleanup` in the compute of `PrimitiveOwned`'s `createMemo(() => { .. return <p/> })` | silent | B1's control: the whole argument of a primitive the dialect gives an owner for is a position the owner graph places, the memo's owner is current |

| `onCleanup` in `ClosedExported`, exported and rendered by a tag, in a closed program where nothing reads the module's namespace | silent | R3's control: every caller is visible, rendering is the only entry. In an OPEN program the same export is an obligation: fixture `owner-emission-open-export` |

The SC3001 rows at the `lib.tsx` creations are the owner-call universe's (ADR 0969, policy A: an export of an open program is handed out, a hand-off to an unread package may run it); they are not this fixture's subject and stand on both builds. The direct-`eval` form of the same stop (B3) has its own fixture, `owner-emission-eval`, because a program that calls `eval` opens every layer of itself.

Chrome (`fixtures/runtime-oracle/owner-emission-layer-stops`, every component exported, and `owner-emission-namespace` for B2): main is `unproven-clean` at the self-saving root and the PR head of #221 at the wrapped arrow and at `Comp`; the fix is `covered-uncertifiable` at each.
