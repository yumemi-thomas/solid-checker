# SC7006: client wrappers and exports in a module-level directive file

Under a module-level `"use server"` the client module is rebuilt as bare references (`transform.rs:8-11`), so a module-scope call to a client-side declaration wrapper never runs on the client (RFC 10: `GET` is "meaningless inside a module-level file"). The built-in wrappers (`GET`, `live`, `withMeta`, `query`, `action`, `liveQuery`) are matched by the call's exact import binding from `solid-js`, `@solidjs/web`, `@solidjs/router` or `@solidjs/start` (or a subpath), never by spelling: a project function, a shadowing declaration, a namespace member and an import from another package are silent. A non-function export throws at boot (`registerServerReference`, rc.17 `server.js:1567`); a re-export is a compile error (rc.8+); a wrapped export is registered by value and is not a defect (an uncertifiable result where the facts do not show a function). The `clientWrappers` option is pinned by ownership cases (`valid-use-server/client-wrappers-*`).
