# leading-token-member-roots

**Claim (ADR 0376).** SC1007 and SC8015 classify a member chain by its root only when the root is an identifier (SC1007 also accepts an accessor call, `count().onSave`, whose callee is that identifier). `props.handlers().onSave` and `props.make().ready()` are rooted at a call: the leading token `props` and the first member's leaf made them reads of the reactive props `onSave` and `ready` (before: SC1007, SC8015); now clean. Controls `onClick={props.onSave}` and `props.ready() && …` stay violations. These gates are product narrowings, not eslint-plugin-solid 0.14.5 heuristics. Owners: `expected_function_got_expression` in `upstream_compat/shared_reactivity.rs`; `source_symbol_at`, `has_proven_read` in `upstream_compat/mod.rs`. Stub: `props-callers`'.
