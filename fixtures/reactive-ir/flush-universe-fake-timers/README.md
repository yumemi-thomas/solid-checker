# flush-universe-fake-timers

**Claim (the review of #213, F1; ADR 0967, third amendment; owner ruling).** A callback a reviewed scheduler runs from an empty stack (`setTimeout`, `setInterval`, `requestAnimationFrame`, `queueMicrotask`, `Promise.prototype.then`, the standard library's list in ADR 0966) ends all three flush codes on `FlushSafe::FreshStack` when it is written directly in the call (`flush-universe`). That reason is a statement about the host's stack, and a fake clock replaces it: a test that installs fake timers (`vi.useFakeTimers()`, `jest.useFakeTimers()`) and advances the clock (`vi.advanceTimersByTime`, `jest.runAllTimers`) runs the callbacks on the stack of whoever advances it, which may be an action's step or an effect's apply. So a program that installs fake timers gets no `FreshStack` reason: every flush a scheduler's callback holds keeps the uncertifiable row of each code (SC2006 `flush-in-action-unaccounted`, SC2008 `flush-in-effect-unaccounted`, SC3001 `leaf-operation-unaccounted`), never a violation. Only `FreshStack` is withheld: a test runner's callback is run by the runner whatever the clock is (`TestRunner`), the code past an `await` resumes from the promise job queue (`AwaitContinuation`), and module evaluation runs before any callback (`ModuleInitialization`).

The question is the program's, not the file's. The clock is global to the run, and a test file reaches it through a helper another file declares (`useClock()` in `clock.ts`) while the flush is written in the code under test (`Scheduler.ts`). The census is read once per build, only when a scheduler's callback would end a flush (`flush_accounting.rs`, `FakeTimers`), and it is the compiler's resolution that decides, never the spelling: a member's property that resolves to a declaration named `useFakeTimers` in a reviewed library's installed files (`vitest`, `@types/jest`, `@jest/environment`, `@jest/globals`, `bun-types/test.d.ts`, matched on path components as ADR 0438's runner list is), or the same name written as a member of, or destructured from, an object such a library declares (a value read of the property is not in the table: `const install = vi.useFakeTimers`, `vi.useFakeTimers.call(vi)`, `(vi as any).useFakeTimers()`, `const { useFakeTimers } = vi`).

`Scheduler.ts` is the code under test (three flushes, one per scheduler: nine rows); `clock.ts` installs the fake clock through vitest's `vi`; `App.test.tsx` calls it and holds the three flushes that stay silent whatever the clock is (module level, a test callback, past an `await`: no row). `Card.tsx` steps an action, runs an effect's apply and opens a leaf scope, so no program-wide reason holds either.

Variants, each its own project (the parent's `node_modules` serves `real` and `destructured`):

- `variants/real`: the same sources with `clock.ts` calling `vi.useRealTimers()` and `vi.advanceTimersByTime(10)`. Neither is the installer (the declaration's name decides, not the package), so nothing in the program installs a clock and the three flushes end on `FlushSafe::FreshStack`: no row (the negative twin).
- `variants/jest`: `@types/jest` declares `jest.useFakeTimers` as a function of the global `jest` namespace (`jest-types.d.ts` brings it into the program, as `test-runner-suites` does): three rows at the `setTimeout` callback's flush.
- `variants/bun`: `bun:test` exports a `jest` namespace (`bun-types/test.d.ts`) with the same function: three rows.
- `variants/destructured`: `const { useFakeTimers } = vi` (the entity a shorthand key names is the local binding, not the property): three rows.

Not recognized, named in `docs/open-work.md`: another library's installer (sinon's `useFakeTimers`, `@sinonjs/fake-timers`' `install`, jasmine's `clock().install()`, `node:test`'s `mock.timers.enable()`), a configuration that turns fake timers on without a call (jest's `fakeTimers: { enableGlobally: true }`), a value read through a handle no reviewed library declares (`const clock = vi; const install = clock.useFakeTimers`), a destructured parameter and a receiver the compiler types `any` that is not written as the reviewed object.
