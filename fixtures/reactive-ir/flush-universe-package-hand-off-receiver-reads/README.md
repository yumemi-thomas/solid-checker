# flush-universe-package-hand-off-receiver-reads

**Claim (the review of #229, B2; ADR 0967 amended).** A receiver (`this`, `super`) reaches members through no reference of the object that holds them, and the object does not have to be the literal that writes the receiver: a member assigned after the literal, written by a project function, stored on a derived literal, on an `Object.create` result or on a class's instance is read by the same `this.k`. So the key is followed: a function stored under a key (a property of an object literal, the target of an assignment) is handed when a use of a receiver reads the key in code a package may run. An installed package the build does not read as source (`steplib`, as in `flush-universe-package-hand-off-receivers`) may then run the function as an action's step, so a flush in it keeps its three uncertifiable rows (SC2006 `flush-in-action-unaccounted`, SC2008 `flush-in-effect-unaccounted`, SC3001 `leaf-operation-unaccounted`): never silence, never a violation. Chrome (rc.21) reports FLUSH_IN_ACTION at each; before this the checker certified them (`scripts/fuzz/patterns/pkghand/late-*-step`, `proto-class-step`, `proto-create-step`, `proto-receiver-step`).

**The cases.** Each stores its flushing function under a key of its own, and no use of a receiver in the program reads a key through a value (`this[key]`, `const self = this`: `flush-universe-package-hand-off-receiver-escapes`), so each row is the case's own. `lateAssign` (a member assigned after the literal), `lateSetter` (the read is a setter's, run by a write), `lateNested` (an object assigned after, the getter runs a method of it), `latePut` (a project function writes the member), `lateValue` (the member is handed on, not called: `runStep(this.m)`), `lateDestr` (`const { m } = this`), `lateStrKey` (`this["m"]`), `lateChain` (the member that is read calls another stored under a key the step does not name: the read is asked of the function that holds it), `protoReceiver` (the receiver on the prototype, the flushing member on a derived literal that writes none: G1 mirrored), `protoCreate` (`Object.create(base)`), `protoClass` (a class reads the member, an instance is given it).

**Twins, silent.** `twinOtherKey`: the receiver reads a key no function that flushes is stored under. `twinTimer`: the read runs in a closure on a timer's stack, which no package runs. `twinNoReader`: a member nothing reads through a receiver. The twins that read the same key on another object are in `flush-universe-package-hand-off-receivers`: a holder that provably cannot be a receiver (a plain literal bound by a `const`, every use of which keeps it so) is not handed whatever a receiver reads, and the two whose holder is a prototype keep their rows (the name net's known cost).

Published bytes: `node_modules/steplib` is synthetic, as in the causes fixture; `@solidjs/web/types/index.d.ts` is the same excerpt. `.solid-checker/runtime.json` closes the program boundary.
