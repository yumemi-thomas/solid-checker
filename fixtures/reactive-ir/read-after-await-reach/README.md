# read-after-await-reach

SC1002 reaches the code an async computation's continuation runs, not only the awaiting function's own body (ADR 0340). Positives: a callback an exact standard-library call invokes inline (`map`, `forEach`, `some`, `every`, `find`, `findIndex`, `flatMap`, `reduce`, `sort`, nested, under a `try`) and an immediately invoked function expression; a `.then`/`.catch`/`.finally` handler on a proven native `Promise` whose result is the computation's promise (returned, awaited, chained); an `async` project function the computation returns or awaits, directly, through a helper that awaits or returns it, or through `Promise.all`; a synchronous helper's straight-line read (a conditional read stays an uncertifiable through-call obligation). Negatives: a read before the await, a stored or deferred callback, a project `map`, a shadowed `Promise`, a `PromiseLike` or unknown receiver, a dropped `.then` result, a helper in an event handler or with an ignored promise or reading before its own first await, a source already tracked, `untrack`, a plain async function.

Stub: published `solid-js@2.0.0-rc.13` and `@solidjs/signals@2.0.0-rc.13` declarations, as in `await-continuation-reads`. The same shapes run in Chrome as `fixtures/runtime-oracle/after-await-*`.
