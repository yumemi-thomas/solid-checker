# read-after-await-reach

SC1002 reaches the code an async computation's continuation runs, not only the awaiting function's own body (ADR 0340). Positives: a callback an exact standard-library call invokes inline (`map`, `forEach`, `some`, `every`, `find`, `findIndex`, `flatMap`, `reduce`, `sort`, nested, under a `try`) and an immediately invoked function expression; a `.then`/`.catch`/`.finally` handler on a proven native `Promise` whose result is the computation's promise (returned, awaited, chained); an `async` project function the computation returns or awaits, directly, through a helper that awaits or returns it, or through `Promise.all`; a synchronous helper's straight-line read (a conditional read stays an uncertifiable through-call obligation). Uncertifiable, never a violation: a handler on a possibly settled receiver in a chain an `async` function returns without awaiting it (the runtime is silent there), a rejection handler (`.catch`, `.then`'s second argument, a fulfillment handler on `Promise.reject`), a fulfillment handler on a receiver that rejects or settles unknown, an `async` helper returned without `await` whose first await is on a settled value, a `sort` comparator, a `reduce` without an initial value, a `replace`/`replaceAll` replacer. A store key read before the first suspension is exempt (ADR 0195). Negatives: a read before the await, a stored or deferred callback, a project `map`, a shadowed `Promise`, a `PromiseLike` or unknown receiver, a dropped `.then` result, a helper in an event handler or with an ignored promise or reading before its own first await, a source already tracked, `untrack`, a plain async function.

Stub: published rc.13 `solid-js` and `@solidjs/signals` declarations, as in `await-continuation-reads`. The same shapes run in Chrome as `fixtures/runtime-oracle/after-await-*`.

Round 5, each group beside its controls and a runtime-oracle case: chain settlement (`after-await-settlement`: a handler returning a rejection, a throw, a timer resolving with a promise, `allSettled` over a never-settling promise, `finally` on one: uncertifiable), possibly tracked sources (`after-await-tracked`: a read through a helper, getter, inline callback or a store key another path may alias before the await: uncertifiable; the untouched variants stay violations), disposal (`after-await-disposed`: a `createRoot` whose `dispose` is mentioned: uncertifiable) and owners (`after-await-owner`: `untrack(() => helper())` and `runWithOwner(null, fn)` are violations, a captured owner and `for await` uncertifiable).

Round 6: a call before the first await to neither a visible project function nor an audited inert standard row (an ambient `declare function`, a global `dispatchEvent`, `fn.call()`) leaves the later read uncertifiable (`InertStandardCallsControl` keeps the violation); a disposed root reached by a named callback or an unresolved one; `undefined` shadowed by a binding; a handler calling a `never` function; reads inside and after `for await` by member, callback and helper; `untrack(load)` by reference and `runWithOwner(null, async ...)`. Runtime-oracle cases: `after-await-possible`, `after-await-resolved`, `after-await-suspended`. The ambient declarations here stand for package callees.
