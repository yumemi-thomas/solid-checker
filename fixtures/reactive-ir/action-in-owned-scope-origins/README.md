# action-in-owned-scope-origins

**Claim (ADR 0972, the review of #231).** The code a call into a package runs is where the callee's value came from, not where its signature type is declared, and every way a package's function reaches the program is an SC2002 site, not only a named-import call. Each case is Chrome-confirmed in the pattern lane (`patterns/pkgaction/*`): `ACTION_CALLED_IN_OWNED_SCOPE` at the call in a component body.

- **B1, the value's origin.** `TypedAlias`: `typedStep` is exported by `fz-typed` (its closure loads solid-js) and typed by `Runner`, declared in the clear `fz-types`. `StdMember`: `listener` is an `EventListenerObject` (the standard library's type) `fz-typed` made. `StoredVoid`, `StoredHandle`: a value `fz-typed`'s function made at module scope, called in a body: the callee's root is a binding of one initializer, followed to the import. All four are uncertifiable `package-may-call-action:reaches-solid`; the declaration of the signature no longer decides (it was the first path, so the clear package or the standard library answered for the code). Silent: `TypedFromHazardPackage` (`fz-pure` is clear; its function's type comes from `fz-env-types`, which reads `process`: the row used to blame the types package), `PureControl`, and `HostConstructors`: `new Float32Array(4)` and `Uint8Array.from(…)` stay the host's although `fz-augment` adds a construct signature to `Float32ArrayConstructor`, as babylonjs's declaration file does (about 270 of its corpus rows).
- **B2, a project barrel.** `re.ts` is `export { runStep as reRun } from "fz-step"`. `BarrelValue` (`[…].forEach(reRun)`) and `BarrelMemo` (`createMemo(reRun)`) hand the package's function on through the barrel, which the import loop skipped as the project's own module: the compiler's resolution of the re-export names the package's declaration. `AliasValue`: a binding that only names the function (`const alias = runStep`) handed on in a body. `BarrelValueInHandler` stays uncertifiable too: where a handed function runs is not followed (`createMemo(reRun)` in a handler runs it in the memo's compute).
- **B3, JavaScript beside a project declaration file.** `vendor/step.d.ts` declares `vendorStep` and `vendor/step.js` (which imports `action` from solid-js) is outside the program (`allowJs` is off, `tsc` is clean). `VendorCall` and `VendorValue` are `package-may-call-action:unanalyzed-project-js`; `VendorHandler` is silent (a handler is a legal action site).
- **S1, a member of a package's object handed on.** `MemberValue`: `[…].forEach(kernel.run)` with `kernel` the default export of `fz-obj`; the member loop took only namespace imports.
- **The re-check of #231 (R1 to R4).** R1: `AugWindow` and `AugConstructor` call a member `fz-aug` adds to `Window` and `Uint8ArrayConstructor` and installs (`window.fzRun = …`): the host answers only where the member's own declarations are all the standard library's, so the augmented member falls to its declaration; `ThroughFreeze`, `ThroughAssign`, `ThroughUntrack`, `UntrackedMember`, `ThroughMemo` read a package value through a host or runtime call (`Object.freeze`, `Object.assign`, `untrack`, `createMemo`), whose result is not followed, so the callee's declaration decides as before. R2: `NamespaceOfBarrel` hands `re.reRun` on through `import * as re from "./re"`. R3: `ArrayElement` (`fns[0]()` with `fns = [makeVoid()]`), `FunctionReturnsVoid`, `FunctionReturnsHandle` (a project function that returns a package's value, called at module scope) and `FunctionReturnsValue` (`[…].forEach(pick())`, the row at the call that receives the result). R4: `WildcardShim` imports `./step.vendor.js`, which `shims.d.ts`'s `declare module "*.vendor.js"` stands for: the JavaScript is outside the program (`unanalyzed-project-js`).
- **Silent twins** for a call: `TypedTimer`, `StoredHandler`, `VendorHandler`.

The row of a function handed on stands at the call that receives it (`[…].forEach(reRun)`), where a throw has its project frame.

`node_modules/fz-*` are **not** published bytes: each is written for this fixture, a manifest, a declaration file and the module the closure walk reads. `node_modules/solid-js` and `@solidjs/*` are the manifests of `action-in-owned-scope-unread-packages`; `.solid-checker/runtime.json` closes the program boundary.
