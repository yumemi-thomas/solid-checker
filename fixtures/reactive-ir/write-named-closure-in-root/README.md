# write-named-closure-in-root

**Claim (ADR 0471).** A closure bound to a name in a created root's body, inline or named by its binding, runs under the root where it is called, though a cleanup, an effect's cleanup or a handler around the root call gives the region a permissive role. Its calls decide, as in a root body written in a component. The same for a site a function runs in place (an IIFE) that `createRoot` names by its binding from an in-place layer (`(() => { createRoot(f1); })()`), which the by-name climb now crosses. Violations (rc.17 throws `ACTION_CALLED_IN_OWNED_SCOPE` once the button disposes the host, fast path): `CleanupRootNamedClosure`, `CleanupRootByNameNamedClosure`, `CleanupRootDeclaredClosure`, `CleanupRootByNameInNamedFunction`, `CleanupRootByNameInIife`, `MemoCleanupRootByNameInIife`, `EffectCleanupRootByName` (at teardown), `HandlerRootNamedClosure`, and `CleanupRootNamedClosureAlsoKept` (one run in place is enough). All were silent before.

Legal (rc.17 silent): a signal write in the disposal (`CleanupRootWriteNamedClosure`, `CleanupRootByNameWriteInIife`), a closure handed to a timer (`CleanupRootClosureOnTimer`), a closure in a handler with no root (`HandlerNamedClosure`), a local `createRoot` (`ShadowedCreateRoot`), and a reused name whose action closure only a handler calls (`ReusedClosureName`).

Uncertifiable: a closure the root stores or returns, which runs where its holder calls it (`CleanupRootClosureStored`, `CleanupRootClosureReturned`; legal at run time, silent before), A root call in a closure declared before the root body is a violation (`CleanupRootByNameInNestedFunction`, rc.17 throws): the closure has one call, after both declarators (ADR 0479). Stub: copied from `write-callback-by-name`.
