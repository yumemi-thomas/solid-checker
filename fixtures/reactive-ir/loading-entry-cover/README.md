# loading-entry-cover

**Claim (ADR 0978).** A read is covered by a boundary the program enters other than as a tag where Solid renders the layer inside it: a hand-called or `createComponent`-called `Loading`'s `children` getter, the first argument of `createLoadingBoundary`. The `fallback` (a JSX attribute, a getter, the second argument) renders outside the hold, so the walk goes on outward from the boundary. Every layer a call does not place (the other members of the props, an array element, a closure handed to a call the analysis does not resolve) is uncertifiable, never a violation. rc.21's `Loading(props)` is `createLoadingBoundary(() => props.children, () => props.fallback, ..)` (`solid-js/dist/solid.dev.js`).

`App.tsx` reads `slow()` where the boundary holds it and `other()` beside it (Chrome: quiet at the first, `ASYNC_OUTSIDE_LOADING_BOUNDARY` at the second). The snapshot pins the placement per site: a violation at `other()` and no violation at the covered `slow()` in every component of the first group (before ADR 0978 a hand-called boundary's getter was read as outside, a false positive; `JsxTag` is the control, clean at `slow()`; the getter's own run is placed by no call edge, so another producer's uncertifiable row `call-attributed-read` stands at `slow()`, never a violation); a violation at the `other()` read of each `fallback` component (before, the JSX `fallback` was read as covered); an uncertifiable row, no violation, at the `slow()` read of the second group; both reads violations in `NoBoundary`.
