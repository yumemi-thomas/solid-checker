# flush-universe-package-prop-arrow

**Claim (batch 11, B2 of the re-review of #220; the review of #225, F1; ADR 0971).** A flush's own row is not ended by another site's row that covers it. `steplib` is a package the build does not read as source (its manifest names no Solid package, as in `flush-universe-package-hand-off`) and `Pkg` runs its `render` prop in a `createTrackedEffect` callback, a leaf owner's: rc.21 throws FLUSH_IN_TRACKED_QUEUE_CALLBACK at the `flush()` the arrow holds, and the arrow is the only application frame. Only `leaf-owner-forbidden-call` (SC3001) claims that code, so the flush must keep its `leaf-operation-unaccounted` row (a flush in a function an unread package may run keeps one row of each code, ADR 0967). The first build of ADR 0971 ended it on the JSX element's own owner-call row (the element is a site of the universe: its component runs under `createRoot`), which covers the flush by span but is reported at the element's start, where the judge places a multi-line finding: no row stood at the flush, a false clean the base did not have. `flush_accounting.rs::row_at` ends a site only by a row that starts where the site starts.

| site | rows at the site | why |
|---|---|---|
| `flush()` in the multi-line arrow of `<Pkg render={…} />` (line 15) | SC2006 `flush-in-action-unaccounted`, SC2008 `flush-in-effect-unaccounted`, SC3001 `leaf-operation-unaccounted` | the unread package may run the arrow as a step, an apply or a leaf callback; Chrome: FLUSH_IN_TRACKED_QUEUE_CALLBACK. **The regression this fixes** (no SC3001 row stood at line 15 on the first build) |
| the element `<Pkg` itself (line 13) | SC3001 and SC6002 (uncertifiable) | the element's own JSX creation (ADR 0971), at the element's start |
| `flush()` in a one-line arrow, `<Pkg render={() => flush()} />` (line 23, column 29) | the same three rows at the flush | the flush is on the element's line at another column: the row at the element (23, column 10) is another position |

The first build had removed six SC3001 rows of this shape from the snapshots (`phase-handed-by-name` ×5, `rc9-heldout-execution-shapes`): they return with this fix. The Chrome oracle case is `fixtures/runtime-oracle/owner-call-flush-package-prop-arrow`. The fuzz generator's packages export functions that take a callback, not components that take props, so no generated program has this shape: `scripts/fuzz/rediscovery.json` records why (an `outside` entry), and the oracle case and this fixture hold it.
