# owner-call-jsx-sites

**Claim (batch 11, B2 of the re-review of #220; ADR 0971).** JSX is a creation as a call is. A component tag runs `createComponent`, which dev builds run under `createRoot`; a tracked expression, an attribute or a spread creates a render effect; a fragment creates a memo. Evaluated on an effect apply's stack with no owner set, each throws (rc.21 PRIMITIVE_IN_EFFECT_CALLBACK, SC6002), and under a leaf owner each is a forbidden creation (PRIMITIVE_IN_FORBIDDEN_SCOPE, SC3001). The owner-call universe (ADR 0969) listed creating **calls** only, so a tag a reference ran on an apply's stack (`pick = view`, `view` returning `<Inner />`, `pick!()` in an apply) was no site: the program certified with no row, though the direct call `view()` was already a violation (the effect-phase walk places JSX where a call edge reaches it, `check_jsx_in_effect_phase`, ADR 0883). Every JSX creation site (`owners::universe_jsx_sites`: the sites of `jsx_sites` minus a static child that may hold a function and a component getter's JSX) is now a site of the universe: it ends per code like a call does, by a row of its rule, an SC9012, the compiler's discard or a named silence (the role places it off every apply and every layer around it is entered the way the role says, B3, the owner graph's context, or an owner an exact primitive sets around it), else the code's own uncertifiable row (`effect-creation-unaccounted`, `leaf-operation-unaccounted`), never a violation.

| site | outcome | why |
|---|---|---|
| `<Inner />` in `view`, which `ByReference` assigns to `pick` and an apply calls through it | SC6002 `effect-creation-unaccounted` (and SC3001 `leaf-operation-unaccounted` where the project opens a leaf scope) | the function is entered by a reference, so its role (rendering) and its owned context are no proof of every run (Chrome rc.21: SC6002 at the tag). **The false clean this fixes** |
| `<Local />` in `outer`, where the component is declared inside the function a reference enters | the same | the same, the component nested |
| `<Inner />` in the handler `SavedHandler` also saves and calls from an apply | the same | an assignment is an expression, so the attribute still yields the arrow |
| `<Inner />` in `viewLeaf`, which a `createTrackedEffect` callback calls through a variable | the same codes | the leaf owner's callback reaches the tag the same way |
| `<Inner />` and `{memo()}` in `Rendered`, a component only a tag renders | silent | rendering runs it under the owner its render sets |
| `<Inner />` in `viewDirect`, called in an apply | SC6002 violation (the effect-phase walk's own row ends the site) | unchanged: the tag is proved on the apply's stack |

The Chrome oracle case (`fixtures/runtime-oracle/owner-call-jsx-sites`) writes each reference at **module scope** (the oracle's entry hands every export to `render` of the real `@solidjs/web`, so B3 keeps a row at every site written inside an exported component on every build; a function only a module-scope initializer names has no function around its reference): the head of #220 is `unproven-clean` at the tag the apply runs and B2 is `covered-uncertifiable` (the leaf one is covered on both builds by the SC9012 at the call). The fuzz cells are `er-view-apply` with the JSX variants (`erVariants`: `jsx-insert`, `jsx-attr`, `jsx-spread`, `jsx-fragment`, `jsx-component`) and their never-run twins: the JSX creation inside a function that returns JSX, held by a variable the apply calls.
