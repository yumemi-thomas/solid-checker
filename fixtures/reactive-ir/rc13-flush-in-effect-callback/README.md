# rc13-flush-in-effect-callback

SC2008 `flush-in-effect-callback` on the audited `2.0.0-rc.13` triple. `runEffect` raises the effect marker around exactly one call, the apply (`dist/dev.js:1876-1906`), and an effect's run is queued, so it always runs inside the flush that drains effects. `flush` in that state reports `FLUSH_IN_EFFECT_CALLBACK` (a warning) and returns without draining (`dist/dev-shared.js:2680-2698`); the production build returns at the same branch silently. The typings accept the call (`EffectFunction` returns `(() => void) | void`; `flush(): void`), so `tsc` is clean against the stub, which is byte-faithful for the signatures the claims rest on (see its header).

Violations: `flush` directly in a `createEffect` apply (also as `flush(fn)`, an alias, a namespace member, signals' own export); in a function declaration, a chain of const-bound arrows, an async helper before its first `await`, and a helper in another file, each called from an apply; in an IIFE, an `untrack`/`createRoot` callback and an array `forEach` callback written there.

Silent: the compute function (no marker), an event handler, a `setTimeout`/microtask/`.then` callback, a shadowed or member `flush`, `createRenderEffect` (its first run is synchronous at creation, outside any flush), a helper no effect calls, a helper only deferred from the effect, a helper reached through a member of a factory result, a generator helper, an async helper past its first `await`, a reassignable `let` helper, a cleanup the apply returns (the next run's cleanup runs inside the marker, disposal's does not), a stored closure, a named or bundle-form apply, a `defer: true` apply of a constant compute, and module scope. `fixtures/runtime-oracle/flush-in-effect-callback` runs the positives and the silent controls in Chrome against the real packages.
