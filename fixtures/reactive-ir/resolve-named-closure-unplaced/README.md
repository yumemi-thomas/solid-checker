# resolve-named-closure-unplaced

**Claim (ADR 0585).** A closure nested in a compute a memo names by its binding (directly, through a `const` alias, or at two memos) and handed by name to `[1].forEach`, to a function the file does not see, or run by an in-place local helper (`run2(hf)`), was placed `DeferredCallback`, which clears the observer, so `resolve()`/`until()` there (directly or through a module helper) was certified clean while rc.17 throws `RESOLVE_IN_REACTIVE_SCOPE` / `UNTIL_IN_REACTIVE_SCOPE` (mx-pairs `memo` × `handoff-*` × `cb-alias`/`cb-shared`, 216 programs). Now an unplaced closure there is `Unknown`, as the inline compute's nested closure is, and one an in-place layer runs at a call in the compute's body takes the compute's tracked role: SC2004 obligations in `SharedUnknownRun`, `SharedWrapperLocalHelper`. `NamedForEach` and `AliasForEachUntil` are violations since ADR 0857: `[1].forEach(hf)` provably runs `hf` in the compute a memo names (Chrome, rc.21, throws). `AliasDirect` stays a violation. Cost: `NamedReadLocalHelper`'s tracked read is an SC1001 obligation, as the same read in an inline compute already was. Clean: `untrack` in a named compute, a handler. Stubs: `solid-js` and `@solidjs/signals` rc.17 manifests (`until` is known from rc.5 on) and rc.17's `resolve`/`until` signatures.
