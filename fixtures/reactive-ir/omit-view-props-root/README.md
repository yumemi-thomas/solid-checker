# omit-view-props-root

**Claim.** A component's setup read of a prop that its callers prove reactive (`props.value`, called as `<C value={text()} />`) is a proven strict-read violation even when the body also hands the props object to an `omit` or `merge` view, aliases it with a `const`, or spreads it onto a DOM element. Those uses cannot write, delete from or alias the object, so the callers' getter is still what the read runs. Any other whole-object use keeps the read uncertifiable.

**Why each accepted use is inert** (`@solidjs/signals@2.0.0-rc.13` `dist/dev.js`, `@solidjs/web@2.0.0-rc.13`):

- `omit(props, ...keys)` always returns `new Proxy(new OmitView(..), omitTraps)` (no shortcut for zero keys or a predicate); `omitTraps` has `set: trueFn, deleteProperty: trueFn`.
- `merge(...sources)` returns the one non-falsy source itself (`if (count === 1 && typeof only !== "function") return only`), so `merge(props)` and `merge(props, maybeUndefined)` are aliases. With two non-falsy sources it returns `new Proxy(new MergeView(..), mergeTraps)`, which has the same no-op `set` and `deleteProperty`. The checker accepts a merge only when no argument is a spread and some argument is syntactically never falsy: an object literal, a function (a memo source), or a call that itself builds a view. The props may be any source, first or later.
- A `const` alias is the same root, judged by its own uses (member reads, view arguments, further aliases); it is never a separate witness, so a read through the alias stays uncertifiable.
- `@solidjs/web` `spread` and `ssrElement` only read the object (enumerate keys, read values; the only writes are to their own `newProps`/`prevProps` and the node, and a view's own `table` cache). A spread of several attributes compiles to a `merge` view first.

**Cases.** Violations: `OmitView`, `OmitNoKeys`, `MergeView`, `MergeLaterSource`, `MergeFunctionSource`, `NamespaceOmit` (`Solid.omit`), `NestedViews`, `AliasThenOmit`, `IntrinsicSpread`. Uncertifiable: `MergeSingleSource`, `MergeMaybeSource` and `MergeSpreadSource` (aliases), `AliasWrite`, `AliasEscape`, `Destructured` (a destructured rest is not a view), `ShadowedOmit` (Shadowed.tsx: a local `omit` that is not Solid's), `OmitThenWrite` and `IntrinsicSpreadWrite` (a direct write), `ComponentSpread` (a spread onto a component is not an intrinsic spread), `ReadThroughView` (`rest.value` maps keys through the view and stays unproven). `StaticOmit` is called only with a literal and reports nothing. The `SC2003` rows are the separate props-write rule on the write statements. `solid-js.d.ts` copies `merge`/`omit` and their types from `@solidjs/signals@2.0.0-rc.13` `dist/types/store/utils.d.ts`, and the fixture type-checks with `tsc --noEmit` against them.
