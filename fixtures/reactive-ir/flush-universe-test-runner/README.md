A flush in the suite body the runner runs inside the registration has the same class. A helper only the tests call is the census's `TestHelper`: a call to it may stand in an action's step inside a test, so no reason covers it, and its flush is an uncertifiable row of each of the three codes (three rows). The program (`Card.tsx`) steps an action, runs an effect's apply and opens a leaf scope, so no program-wide reason holds. A named test callback its own code calls again (`it("named", function again() { … again(true) })`, from an action's step) and a default value written in a test callback are not covered: three rows each (the default's SC2006 is the producers' own `parameter-initializer-unplaced`). Nine rows in all; ablating `flush_accounting.account.test-runner-callback` gives the two covered flushes their rows too (fifteen).
