# change-escaped-benign-strings

**Claim (ADR 1148, round 2 N1; the control of the family).** The `change` handler of a literal `<input type="checkbox">` is delivered by its click activation alone, so its body is an event callback with no owner, and escapes that spell no name the retype veto matches withdraw nothing: this program writes one, the string `"tab\there\u00e9"` (a tab and an accented letter), which is no word, and no identifier or word is written with an escape. The checker certifies it (no row). Chrome (runtime-oracle `change-escaped-benign`, pinned rc.21) is quiet: the control stays a checkbox, which `Grab`'s `textContent = ""` removes without delivering anything.

`change-escaped-benign` is this program with an accented identifier (`caf\u00e9`) and a template with an escaped letter (`` `a\u0042c` ``) as well. ADR 1152 reads both as names (an identifier written with an escape; a template whose whole value is one word), so that program is uncertifiable as a whole (SC9012 `escaped-name-unresolved`), where the proof of ADR 1148 alone would certify it. This program keeps the certified control of ADR 1148: a string that is no word is a plain value, and no veto reads it.
