# merge-omit-view-spread-handler

**Claim (ADR 1129), closed program.** The function a caller writes under a listener key reaches an intrinsic element's spread through a `merge`/`omit` view of the component's props, so it is that element's handler: the spread's SC4001 `handler-spread-unresolved` obligation closes and the function joins the owner graph as a handler target (ADR 0358). `Trigger`'s spread and `Defaulted`'s (the listener is the view literal's own arrow) are proved. Misuse twin: the second `Trigger` caller's handler creates a render effect when the event fires; it stays uncertifiable (SC4001 `owner-varies-by-caller`), and Chrome's NO_OWNER_EFFECT there is covered (`scripts/runtime-oracle.mjs`, verdict `covered-uncertifiable`). With ADR 1134: `DefaultedOff` (a `disabled` button) and `KeyedOff` (the view may own `disabled`) keep `handler-spread-unresolved`, since a delegated handler of a disabled control never runs; their enabled twin `DefaultedOn` is a violation. Chrome (rc.21): NO_OWNER_EFFECT at `DefaultedOn`'s effect (covered-violation), none at `DefaultedOff`'s or `KeyedOff`'s. Round 2 (N1): rc.21's compiled `spread` takes the element's sources as one array and skips a key a later source has (`undefined` included), so `LaterAttr` (`onClick={…}` after the spread), `LaterUndefined` (`onClick={undefined}`) and `LaterSpread` (another spread after it) attach none of the view's handlers: each keeps `handler-spread-unresolved`; their twin `EarlierAttr` (the attribute first, the view's key wins) is a violation. Chrome (rc.21): NO_OWNER_EFFECT at `EarlierAttr`'s effect only. `Spreaded` is refused: a caller spreads into it, so its keys are not read.

`.solid-checker/runtime.json` closes the program boundary, as `handler-placement-closed` does. Stubs and pinned sources as in `merge-omit-view-spread`.
