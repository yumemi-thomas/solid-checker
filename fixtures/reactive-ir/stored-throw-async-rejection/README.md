# stored-throw-async-rejection

**Claim (ADR 1008).** A plain throw (`useContext` with no owner here; the same walk serves a default-less context, a static `dynamic` source, `resolve`, `until` and `flush` in a tracked effect) that leaves an `async` function does not propagate on the caller's stack: it rejects the promise the call returned. Chrome reports it only when nothing holds that promise, as an unhandled rejection. So a violation needs the promise proven dropped: the call is an expression statement or under `void`, every link chained on it is a `then` with no rejection arm or a `finally` and the last result goes nowhere, or the call is awaited (the rejection is rethrown where the `await` is written, and the walk goes on from there).

Violations: `Discarded`, `Voided`, `SyncTwin` (no `async`: the throw propagates), `NamedDiscarded`, `BeforeAwaitDiscarded` (the code before the first `await` rejects the same promise), `ThenNoReject`, `AwaitedInDiscarded`, `ForEachDiscarded` (`forEach` drops what its callback returns), `UntrackDiscarded`, the module function `boom`, which `ModuleDiscarded` calls and drops (one entry that reports keeps the violation), `fromHandler` and `fromRef`, whose promise a handler and a `ref` return (the host drops what they return), and `HelperResolveDiscarded` (SC2004 at the helper call and at the `resolve`: a tracked effect calls an `async` helper and drops its promise).

Obligations (uncertifiable, `computation-error-unobserved`): `Caught`, `BeforeAwaitCaught`, `ThenRejectArm`, `Held`, `NamedCaught`, `AwaitedInCaught`, `AwaitedInTry` (as before: a `try` around the site), `Returned`, `InnerSyncCaught` (a synchronous function called in the async one), `UntrackCaught`, `UntrackHeld` (`untrack` returns what its callback returns), `MapCaught` (`map` returns the promises), `EffectCaught`, `MemoCaught`, `AwaitCatch` and `AwaitThenArms` (the `await` is of what `catch` or the two-armed `then` returns), `UntrackNamedCaught`, `UntrackAliasCaught`, and the leaf operations a tracked effect reaches through a call whose promise it catches: `HelperResolveCaught` (SC2004), `HelperUntilCaught` (SC2005), `HelperFlushCaught` (SC3001), `LiteralResolveCaught`, `DeepHelperCaught` (the `async` function is one call deeper). `HelperCaught` keeps its `function-run-unplaced` row, and `ModuleCaught` adds no entry that reports.

Runtime: rc.21 Chrome, oracle case `fixtures/runtime-oracle/stored-throw-async-rejection` (every violation fires its code, every obligation is silent) and the pattern lane `scripts/fuzz/patterns/asyncthrow`. Premises: the closed program is the `private` manifest.
