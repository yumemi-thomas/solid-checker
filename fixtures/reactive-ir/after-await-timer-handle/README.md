# after-await-timer-handle

**Claim (ADR 0984, the follow-up of ADR 0976).** A call into code outside the project, written after an async function's own suspension, ends in no row only where `library-runs-nothing` holds, and that needs every argument inert. `clearTimeout(timer)` coerces its argument, and a `let` no fact proves primitive was not inert (`proven_primitive` follows a `const` only), so the common timer handle kept an uncertifiable SC1002 `read-after-await-unaccounted` row. A `let` is now an inert argument when the program names the **browser** runtime target (a handle is a number there; in Node it is a `Timeout` object whose `Symbol.toPrimitive` is a library's, never a project's, but the proof is the browser's alone) and **every reference of it** is one of: the target of a plain `=` assignment whose value is a call of the standard `setTimeout` or `setInterval` the compiler resolves (an identifier callee, in a program that leaves every built-in alone) or the unshadowed `undefined`; or the sole argument of a standard `clearTimeout` or `clearInterval`. The binding is a `let` of one identifier, declared with no initializer (or such a value), unexported and no parameter. No type is asked: `ReturnType<typeof setTimeout>` proves nothing.

**Cleared (no row).** `Cleared`: the handle cleared in a promise handler and in a cleanup, written by `setTimeout` (the reproduction case `clean-copied-timer`'s shape); `ClearedInterval`: an interval cleared after the function's own `await`.

**Kept (an uncertifiable SC1002 row each).** `UnknownWrite` (a write by a call nothing resolves), `Copied` (the handle in an object literal: a reference that is no clear), `Handed` (passed to a function before the clear), `Compound` (a destructured write), `Member` (`window.setTimeout`: a member callee), `ConstCopy` (a `const` copy). Twins in their own projects: `after-await-timer-handle-patched` (the program writes `String.prototype.concat`, so no standard call is inert) and `after-await-timer-handle-node` (`--runtime-target node`).

`.solid-checker/runtime.json` selects `browser`, `development`, `csr`; `node_modules/solid-js/package.json` selects the dialect and `solid-js.d.ts` is `after-await-library`'s (an SC9014 row stands at the stub's manifest in every one of these projects, as in the others of this family).
