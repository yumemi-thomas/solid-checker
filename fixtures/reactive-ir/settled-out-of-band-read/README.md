# settled-out-of-band-read

**Claim.** `onSettled` is a leaf owner only under an owned call site; in a handler it queues a plain callback (`@solidjs/signals@2.0.0-rc.17` `dist/dev.js`, `globalQueue.enqueue(EFFECT_USER, fire)`). So a pending read in a handler's `onSettled` is no leaf-owner read, and rc.17 reports nothing on a source that has settled by the click (fuzzer contexts `settled-handler`, `settled-flush-root`). Read through a helper it was a proven SC5001 while the same read written in the callback was an obligation: `containing_leaf_owner` does not ask about the call site. The read now passes through the owner fixed point's call-site gate: `OwnedHelper` and `OwnedDirect` stay violations, every `Handler*` shape is uncertifiable. The stubs are `flush-veto-settled`'s.
