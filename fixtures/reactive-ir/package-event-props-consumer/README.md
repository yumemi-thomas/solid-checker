# package-event-props-consumer

Written (ADR 0207) to pin that a package component stating an event-handler-props item runs its `on...` props only at an external event, so a function literal written as such a prop takes `ExecutionRole::EventCallback`, while `as`, spread, merge and non-`on...` props stay uncertifiable. That item came from a package contract, which is removed (ADR 0312). Today every `count()` read in a `Root` prop is an `SC1001` `strict-read-untracked` uncertifiable result, the intended-clean `Direct`, `AnotherEvent` and `Wrapped` as much as `AsComponent`, `SpreadAtOrigin`, `MergeWrapped` and `NotAnEvent`, plus the SC9014 notice for the rc.0 stub. The event-role claim is therefore no longer pinned here. The `solid-reactivity.json` beside the stub is inert.
