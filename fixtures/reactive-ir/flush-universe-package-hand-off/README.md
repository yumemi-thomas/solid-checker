# flush-universe-package-hand-off

**Claim (batch 11, the B3 PR after #213, ADR 0967).** An installed package the build does not read as source can run a function the project hands it as an action's step, an effect's apply or a leaf callback: `steplib`'s `runStep(cb)` is `action(function* () { cb(); })()`. The flush accounting's program censuses (`NoSteppedAction`, `NoDeferringPrimitive`, `NoLeafScope`) read the primitives the build's own table names, and this program names none (`App.tsx` has no action, effect or leaf primitive), so on #213's head every flush below was certified silently while Chrome (rc.21) reports FLUSH_IN_ACTION at it. Owner ruling (option b, fail closed, no premise): a flush in a function such a package may run gets no census reason, so it keeps its uncertifiable row of each code (three rows: `flush-in-action-unaccounted`, `flush-in-effect-unaccounted`, `leaf-operation-unaccounted`), never silence.

`App.tsx` holds each route a function reaches the package, one component each: written as an argument (`Literal`); by reference (`Reference`: a declaration; `Copy`: through a `const` copy; `Assigned`: through an assignment; `Imported`: a function and a holder another file, `Shared.ts`, exports); an object's member, method, spread member, holder and a member by reference (`Member`, `Method`, `Spread`, `Holder`, `MemberByReference`); an array's element and a holder of one (`Element`, `ElementHolder`); a JSX prop, a prop by reference, a spread attribute and a child expression of a component of the package (`Prop`, `PropByReference`, `PropSpread`, `Children`); a project function's parameter that goes on to the package (`Wrapped`) and a helper the handed callback calls (`Caller`); the package named another way, through a namespace import and through an alias (`Namespace`, `Aliased`: the callee is resolved by its declaration, never by its spelling). `Shadowed` stays silent: a local function that shadows the package's name is a project function, analyzed (the spelling `runStep` names the declaration in scope). `Known` and `Called` stay silent on the census reasons: the standard library runs a callback as the program's own code (`forEach`, `Promise.then`; a dialect primitive is the same, probed with the real typings: `untrack`), a project function that only calls its parameter is analyzed (`call`), a DOM element's handler is the browser's, and a function only called (`plain`) or a handler written in a child element of a package's component is handed to nothing a package runs.

`Pkg.test.tsx`: a function handed to a reviewed runner's registration (`describe`, `it`) is the runner's own: silent on the census reasons, `drain` (a helper written in a suite body) included. The registration is known by its declaration (a reviewed runner's installed declaration file, a registration's name), not by what the project proves of when the runner runs a suite body: vitest's bytes do not show it in this fixture or in compass-ui, where `test_runner_callback` answers nothing for `describe`, and treating that as "not a registration" would have handed every function written in a `describe` body to a package (147 of the first prototype's 154 corpus rows were such sites in compass-ui's `store.test.ts`). `expect` is no registration: a callback handed to it is handed to a package the build does not read, uncertifiable (three rows; two such sites in compass-ui's `ChannelView.scroll.test.tsx`).

`Bun.test.tsx`: `bun:test` is native, no published JavaScript shows when it runs a suite body (`SuiteBodyRun::Unproven`), so `test_runner_callback` answers nothing for its `describe`; the registration is a reviewed runner's all the same (`bun-types/test.d.ts`, a registration's name), and `drain`, written in the suite body, is silent. (A first build that took `test_runner_callback`'s answer for the runner's identity gave it three rows.)
