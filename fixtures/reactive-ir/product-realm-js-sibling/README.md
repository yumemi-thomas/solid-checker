# product-realm-js-sibling

**The premise (ADR 1145, review round 1).** The closure follows TypeScript's attested resolution and the page is built by Vite's; the realm holds only where they agree, so each place they can differ ends the read. `main.tsx` imports `./util`, and `util.ts` (inert) and `util.js` (`import "fz-prealm-any"`) sit side by side (`allowJs` is off: a stale `tsc` emit has this layout). TypeScript resolves `./util` to `util.ts`; Vite's default `resolve.extensions` is `.mjs, .js, .mts, .ts, …`, so it loads `util.js`, and the page loads the writer. The realm probes each relative specifier the way Vite does and ends the read where its pick is not the attested file.
