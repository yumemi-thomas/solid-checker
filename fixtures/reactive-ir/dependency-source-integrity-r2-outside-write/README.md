# Package integrity review: outside-write

ADR 0300, the check of #229 (B3, a false positive): `mutation_holder_closed` read the receivers written inside a holder literal, and then accepted any `holder.change()` call. A method written outside the literal (`{ change: ch }`, `{ change }`) or stored by a later write (`holder.change = ch`) runs with the holder as `this` where it is called, so `this.slot = location` in it replaces the holder's own slot as `super.slot = location` does (`dependency-source-integrity-r2-super-write`): `holder.slot` is the package's `location`, the descriptor write through it (`Object.defineProperty(holder.slot, key, …)`, a key the program does not name) can replace `search`, and the read `createSignal(location.search)` was an SC1001 violation where Chrome rc.21 is quiet (the write turns `search` into a data property). A member of the holder that is called must now be a function written in the literal itself that nothing writes; the three components keep an SC9012 obligation at the read (`Outside`, `OutsideShorthand`, `Replaced`). The twins are in `dependency-source-integrity-r2-super-twins` (a method written in the literal, an arrow included, is the census of its own text: violations). `dep-router` is the package of the other `dependency-source-integrity-*` fixtures. Solid declarations are the published 2.0.0-rc.13 signatures.
