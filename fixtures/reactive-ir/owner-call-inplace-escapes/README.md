# owner-call-inplace-escapes

**Claim (batch 11, B2, the re-review of #225, B1-B4; ADR 0971).** A dialect control-flow element calls a function in place, under the owner of its own render, only in a position the dialect names: `For`'s and `Repeat`'s row function, `Show`'s and `Match`'s (under `Switch`) function child (called only with a parameter), `Errored`'s `fallback` (`Dialect::control_flow_prop_function_run`, read on rc.21's `solid.dev.js`). A tag written directly in the body of such a function throws nowhere and is no site. Anything else the in-place rule as first built took for run in place runs where it is called: stored and called by an effect's apply it creates with no owner set (rc.21 PRIMITIVE_IN_EFFECT_CALLBACK, SC6002), and the old build certified each one (Chrome: `fixtures/runtime-oracle/owner-call-inplace-escapes`, `unproven-clean` on it, `covered-uncertifiable` now). Each is a site like any other, which ends in the code's own uncertifiable row where nothing proves it: never a violation, never a silence.

| site | outcome | why |
|---|---|---|
| `<Inner />` in `{function row() { pickNamed = row; ... }}`, the row function of `For` (line 24), and in a named `fallback` of `Errored` that stores itself (line 35) | SC6002 `effect-creation-unaccounted` (uncertifiable) | **B1.** A function expression that uses its own name (or reads `arguments`) can hand itself on, so it runs where it is called, not only where the element calls it |
| `<Inner />` in a function written in `Show`'s `when`, keyed (line 50) and not keyed (line 65) | the same row | **B2.** `Show` hands its `when` value to the function child and never calls it; the child stores it (a function in any prop but the dialect's positions is a value handed on). The non-keyed twin's untracked read of the accessor at line 69 is the SC1001 violation of another rule, which claims another code |
| `<Inner />` in an instance field's initializer, in a component (line 81) and in a function a dialect element calls (line 94) | SC3001 `leaf-operation-unaccounted` and SC6002 `effect-creation-unaccounted` | **B3.** An initializer runs at each construction, which may be on any stack: it is no part of the function the class is written in, even with no dialect element around (a class in a plain component certified) |
| `<Match when={1}>` (line 117, a getter, as before) and the `<Inner />` in its children (line 118), `Match` a child of `Tabs` | SC3001 and SC6002 at both | **B4.** `Match` returns its props: outside a `Switch` a component like any other, whose getter runs where `Tabs` reads it |
| `NamedQuiet` (a named function expression that never uses its name), `SwitchQuiet` (`Match` as `Switch`'s direct child), `ShowQuiet` (a function child with its parameter), `ShowWithComment` (the same with a `{/* .. */}` comment before it) | silent | the element calls the function, or reads the getter, under its own owner; a comment is no child at run time (the corpus's kui `Show`s have them: the function is still the only child) |

`Show`'s function child with no parameter (`<Show when={1}>{() => <Inner />}</Show>`) is not called by `Show` (the dialect's `WithParameter`) and is rejected by tsc against the real typings (`NonZeroParams`), so it has no case. A generator handed to `For` (B5, the review's note: its body runs where the iterator is stepped, `runs_as_child`) type-checks only with a cast, so it has no fixture or cell either; the rule treats it as a site like any other.

The proof-log process test `a_getter_and_the_callee_of_a_call_in_one_are_declined_for_their_own_reasons` pins both sides on this fixture. The fuzz cells are `er-namedrow-apply`, `er-whenfn-apply`, `er-classfield-apply` and `er-matchout-apply` and their never-run twins, with the JSX variants.

`node_modules/solid-js/index.d.ts` reduces `solid-js@2.0.0-rc.21` `types/client/flow.d.ts` byte-faithfully for `For` (the first overload), `Show` (the four overloads and their helper types), `Switch`, `Match` (the non-keyed element-child overload) and `Errored`; `solid-js.d.ts` has the real `JSX.Element` shape (no function is an element), so `Show`'s function-child overloads are reached.
