# owner-call-inplace-escapes

**Claim (batch 11, B2, the re-review of #225, B1-B4; ADR 0971).** A dialect control-flow element calls a function in place, under the owner of its own render, only in a position the dialect names: `For`'s and `Repeat`'s row function, `Show`'s and `Match`'s (under `Switch`) function child (called only with a parameter), `Errored`'s `fallback` (`Dialect::control_flow_prop_function_run`, read on rc.21's `solid.dev.js`). A tag written directly in the body of such a function throws nowhere and is no site. Anything else the in-place rule as first built took for run in place runs where it is called: stored and called by an effect's apply it creates with no owner set (rc.21 PRIMITIVE_IN_EFFECT_CALLBACK, SC6002), and the old build certified each one (Chrome: `fixtures/runtime-oracle/owner-call-inplace-escapes`, `unproven-clean` on it, `covered-uncertifiable` now). Each is a site like any other, which ends in the code's own uncertifiable row where nothing proves it: never a violation, never a silence.

| site | outcome | why |
|---|---|---|
| `<Inner />` in `{function row() { pickNamed = row; ... }}`, the row function of `For` (line 24), and in a named `fallback` of `Errored` that stores itself (line 35) | SC6002 `effect-creation-unaccounted` (uncertifiable) | **B1.** A function expression that uses its own name (or reads `arguments`) can hand itself on, so it runs where it is called, not only where the element calls it |
| `<Inner />` in a function written in `Show`'s `when`, keyed (line 50) | the same row | **B2.** `Show` hands its `when` value to the function child and never calls it; the child stores it (a function in any prop but the dialect's positions is a value handed on). The not-keyed twin has no case here: its child reads an accessor untracked, which is the SC1001 violation of another rule (the oracle case has it) |
| `<Inner />` in an instance field's initializer, in a component (line 65) and in a function a dialect element calls (line 78) | SC3001 `leaf-operation-unaccounted` and SC6002 `effect-creation-unaccounted` | **B3.** An initializer runs at each construction, which may be on any stack: it is no part of the function the class is written in, even with no dialect element around (a class in a plain component certified) |
| `<Match when={1}>` (line 101, a getter, as before) and the `<Inner />` in its children (line 102), `Match` a child of `Tabs` | SC3001 and SC6002 at both | **B4.** `Match` returns its props: outside a `Switch` a component like any other, whose getter runs where `Tabs` reads it |
| `NamedQuiet` (a named function expression that never uses its name), `SwitchQuiet` (`Match` as `Switch`'s direct child), `ShowQuiet` (a function child with its parameter), `ShowWithComment` (the same with a `{/* .. */}` comment before it) | silent | the element calls the function, or reads the getter, under its own owner; a comment is no child at run time (the corpus's kui `Show`s have them: the function is still the only child) |

The cases below were added by the follow-ups of the re-check of #225 (its notes N1 and N2); they sit after the rows above, which keep their spans.

| site | outcome | why |
|---|---|---|
| `<Inner />` in an `accessor` field's initializer, in a component (line 114) | SC3001 and SC6002 (uncertifiable) | **B3, the `accessor` form.** An auto-accessor is a class field to the facts (`ClassElementKind::Field`), an own property of every instance, so its initializer runs at each construction like a plain field's |
| `<Inner />` in `Show`'s function child with a default parameter (line 144) and with a rest parameter (line 155), `Show` the child of `Late` | SC6002 `effect-creation-unaccounted` (uncertifiable) | **B2, a parameter that counts for none.** `Show` calls its function child only if `child.length > 0` (rc.21 `solid.dev.js`); a default or a rest parameter leaves `Function.length` at 0, so `Show` returns the function as its value and `Late`, on an effect's apply, calls it with no owner set (`Late` reads its children in the effect's compute, so `Show` itself is created under the compute's owner). Both forms are tsc-clean on the real typings (`NonZeroParams` takes `0 \| 1` and `number`; only the zero-parameter form is rejected) |
| the `<Show>` elements of the three cases above and of the control (lines 142, 153, 235) | SC3001 and SC6002 (uncertifiable) | not the claim: `Show` is a child of a component, a getter that runs where `Late` reads it (ADR 0971, F2: the named cost of the getter rule) |
| `ShowParamLate` (the same under `Late`, with a plain parameter, line 237) | no row at its `<Inner />` | the control: `Show` calls the child itself, in place, under its own owner, and `Late`'s apply finds its result, not a function |
| `ErroredReadsArguments`: an `Errored` `fallback` function expression that reads `arguments` (line 180) | SC6002 (uncertifiable) | **B1, what `arguments` does.** Reading `arguments` makes an inline function expression a site like any other (`can_hand_itself_on`), though `arguments.callee` throws in module code and nothing else of `arguments` is the function. `Errored`'s `fallback` is no control-flow child, so the entry walk does not close it and the site keeps its row: the precaution costs one uncertifiable row there, never a violation |
| `ErroredQuiet`: the same `fallback` that never reads `arguments` (line 192) | no row | the control: the dialect says `Errored` calls its `fallback` in place, so its tag is no site |
| `ForReadsArguments`: the same in `For`'s function child (line 170) | silent, a site that ends in a silence | the entry walk closes a control-flow child no reference names, so the precaution moves no row here (`jsx_sites.rs` `can_hand_itself_on` and `owner_emission.rs` `layer_entry_open`) |

`Show`'s function child with no parameter (`<Show when={1}>{() => <Inner />}</Show>`) is not called by `Show` (the dialect's `WithParameter`) and is rejected by tsc against the real typings (`NonZeroParams`), so it has no case; its two tsc-clean spellings, a default and a rest parameter, are the cases above. A generator handed to `For` (B5, the review's note: its body runs where the iterator is stepped, `runs_as_child`) type-checks only with a cast, so it has no fixture or cell either; the rule treats it as a site like any other.

The proof-log process test `a_getter_and_the_callee_of_a_call_in_one_are_declined_for_their_own_reasons` pins both sides on this fixture. The fuzz cells are `er-namedrow-apply`, `er-whenfn-apply`, `er-classfield-apply` and `er-matchout-apply` and their never-run twins, with the JSX variants; the follow-up cases have no fuzz cell and no Chrome case: they keep uncertifiable rows (never a silence), which the snapshot and the process test pin, and what rc.21 does with them (`Show`'s `child.length > 0`, an auto-accessor's initializer at each construction, `Errored`'s `f(err, reset)`) is read from its runtime source (`solid.dev.js`), not run.

`node_modules/solid-js/index.d.ts` reduces `solid-js@2.0.0-rc.21` `types/client/flow.d.ts` byte-faithfully for `For` (the first overload), `Show` (the four overloads and their helper types), `Switch`, `Match` (the non-keyed element-child overload) and `Errored`; `solid-js.d.ts` has the real `JSX.Element` shape (no function is an element), so `Show`'s function-child overloads are reached.
