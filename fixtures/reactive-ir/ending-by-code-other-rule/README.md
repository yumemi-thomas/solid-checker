# ending-by-code-other-rule

**Claim (batch 11, slice 4; ADR 0968).** A site of the independent universe ends for a Chrome code only by an ending that answers that code: a row of its own table, an SC9012, the compiler's discard, a finding of a rule the dialect says claims the code, or a named silence that names it. What stands at the site's span for another code ends none of its codes, so the code's own rule gets its uncertifiable row beside it (`strict-read-unaccounted`, `write-unaccounted`): never a violation. Before this, any row or finding at the span ended the site.

`CaughtRead` is a read ended before only by the async-read table's row: the row answers SC5003's code, not STRICT_READ_UNTRACKED (a `try` around the pending read swallows its throw wherever the carrier stands: `caught-handed-read`, ADR 0838). SC5003 and SC5008 stay uncertifiable at the read, and SC1001's `strict-read-unaccounted` stands beside them. Chrome (rc.21) reports CAUGHT_REACTIVE_READ only for this read, so SC1001's row is the cost of not having a proof that the other code cannot fire.

`OptimisticWrite` is a write ended before only by another rule's finding: the async optimistic setter's call before the first answer is SC2009's violation, which claims OPTIMISTIC_WRITE_BEFORE_LOAD, not REACTIVE_WRITE_IN_OWNED_SCOPE. SC2001's `write-unaccounted` stands beside the violation. rc.21 throws OPTIMISTIC_WRITE_BEFORE_LOAD ahead of any owned-scope guard (`rc21-optimistic-before-load`), so the row is again the cost of not knowing.

The twin, `ending-by-code-other-rule-crediting`, holds the sites whose own rule's finding stands: no row beside them. The five sites of this fixture and of `optimistic-write-site-code` that the proof gate now reports are listed in `fixtures/proof-log/candidates.json` (owner: batch 11 slice 4: masked site, the code's U row stands; the proof is its producer's own). `node_modules` holds the package manifests of the rc.21 triple only; `solid-js.d.ts` is the minimal form of the two primitives the cases call.
