# write-default-in-helper-closure

**Claim.** A callback handed to a project helper runs in the caller's memo only where a call in the helper's body (`BodyCall`, a violation) runs it; a call in the helper's own parameter list runs only when the caller omits the argument (`DefaultOmitted`, `DefaultSupplied`: uncertifiable, ADR 0452), and the summary rung (`interproc/graph.rs`) takes no inline row from one. The summary pipeline does not enumerate such a call at all (checked by instrumenting the rung on this shape and on a package analyzed with `--dependency-source`), so the guard there is defensive. `NestedDefaultNeverRuns` pins a known false positive as the current answer: the callback sits in the default of a closure the helper returns and nothing calls, but the lookups through `containing_ast_function` (`calls_parameter_in_body`, the every-completion table) place it in the helper's body, so SC2001 reports a write that never runs. The planned fix (docs/open-work.md) turns it uncertifiable and moves this snapshot. Stub: `createSignal`, `createMemo` of rc.17.
