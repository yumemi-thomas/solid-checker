# read-in-place-layers-summary

**Claim (ADR 0522).** A reactive read written in a function that runs in place on the stack of a call (an IIFE, a project helper's callback the helper calls in its own body, a closure bound to a name and called once; ADR 0469's layers, in this file or another module) is a read the function around that call performs when the call runs, so it is in that function's summary at the layer's call and is claimed where the function is called: a two-phase directive factory the JSX evaluates eagerly (`<p ref={dir1()} />`) or a statement call in the component body is `strict-read-untracked` (`RefFactoryBodyHelper`, `RefFactoryBodyIife`, `RefFactoryBodyWrapperModuleHelper`, `RefFactoryBodyWrapperClosureHelper`, `StatementCallHelper`, `HookHelperLayer`; rc.17 warns STRICT_READ_UNTRACKED while the element is created, `@solidjs/web` dist/web.dev.js:1016-1022 applies the ref under `runWithOwner(null)`, which keeps the body's strict-read window). Before, the read's only summary node was the anonymous layer, which nothing consumes, and the factory's call was certified clean (1,030 `mx-recall` false cleans, context `ref-factory-body`, layers `helper`, `iife`, `closure+helper`, `module-helper`). The direct-read proof (`DirectReadProof::holds`) accepts an origin in such layers when the layers' outermost call is written directly in the function's body, so the finding is a violation, not an attributed obligation.

Legal (rc.17 silent, certified): the same factory in a JSX attribute (`AttributeFactoryHelper`, a tracked render effect), a timer's callback (`TimerLayerInFactory`, a fresh stack), a stored callback (`StoredCallbackInFactory`), and an owner operation in the factory's body (`CleanupInFactoryBodyHelper`, the component's owner).

Uncertifiable: a helper or a hook's accessor called in a class member's body (`ClassCtorWrapper`, `ClassMethodHookResult`; ADR 0516: the construction or member call that runs it is followed by nothing, so the summary consumer makes the reads obligations as the direct-read path does; rc.17 warns, 264 `mx-recall` false cleans per class context); a read in a generator stepped at its own call in a function an intrinsic `ref` applies (`RefNamedGenerator`, `RefFactoryGenerator`, `RefRowGenerator`; ADR 0516's stepped generator through `ref_applied_read_role`, which climbed only through layers and left the deferred role; rc.17 warns, the step reaches the read). Stub: `write-stepped-generator-in-root`'s, reduced to the overloads called here.

ADRs 0528–0529: eager handler aliases and binding-dispatched layers owe findings; event twins stay clean. Existing stub exceptions apply.
