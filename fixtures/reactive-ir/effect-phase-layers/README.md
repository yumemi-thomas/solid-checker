# effect-phase-layers

**Claim (ADR 0484).** The effect-phase walk shared by SC2008 and SC6002 crosses a closure written in an exported component and called only in place (an export statement's span no longer makes the functions nested in it exported), and a project helper that calls its callback in its own body (`layer_run`'s `InPlace`). Violations: `flush` in such a closure and through such a helper (SC2008). Since ADR 0495 a memo created through a helper whose first call is its callback (SC6002 proves its throw only with no call before it, judged in each layer and in the helper's body); uncertifiable since ADR 0613, as the kept `flush` may drain the apply under an owner. Uncertifiable: `MemoAfterHelperCall` (the helper calls something first), `MemoAfterEarlierCall` (a call between the closure's declaration and its call), and from the ADR 0495 review `MemoAfterHelperArgument` (the helper call's argument), `MemoAfterParameterArgument` (the argument of the helper's call of its parameter), `MemoAfterDefaults` (a parameter default of the helper and of the callback) and `MemoAfterGetter` (a getter read first). Silent: a helper that keeps its callback. Stubs as in `primitive-in-effect-callback`, plus rc.17's `flush`.

Since the flip of ADR 0967's default (the review of #216) this fixture's program has an open boundary (no `.solid-checker/runtime.json`), so each `flush()` written in an exported function keeps an uncertifiable row of every code its program censuses ruled out (SC2006 `flush-in-action-unaccounted`, SC2008 `flush-in-effect-unaccounted`, SC3001 `leaf-operation-unaccounted`): an export may be entered by code this build cannot see, an action's step among it. The snapshot's additional rows are those; the claim above is unchanged.
