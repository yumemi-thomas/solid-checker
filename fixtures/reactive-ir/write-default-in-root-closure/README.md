# write-default-in-root-closure

**Claim.** A closure built in a `createRoot` or `untrack` callback runs nothing there, and a default value in its parameter list runs when a call omits the argument (ADR 0452, 0454). `write_region_adjustment` took such a site for the callback's own body, so the root-body rejection and `untrack`'s call-site role made `SC2001` report a write that a click runs legally. The arms now ask whether the callback's body runs the site (`direct_callback_runs`): `RootBuildsClosure`, `RootDestructuringDefault`, `RootIifeInDefault`, `UntrackBuildsClosure`, `UntrackChain` are uncertifiable, like the memo's (`MemoBuildsClosure`). Only `createRoot` and `untrack` are pinned; the same test serves `flush`, `dynamic` static, `dispatchAsInteraction`, a render effect's first run and render roots.

Costs: a closure called in the body with the argument omitted does throw in rc.17, but a closure with code in its parameter list has no call sites (ADR 0339): `RootCallsDefault`, `RootIifeDefault`, `UntrackIifeDefault` are uncertifiable. Controls (violations): `RootBodyClosureCall`, `RootBodyForEach`, `UntrackBodyWrite`; `RootBuildsBodyWrite` (closure stored, body writes) stays uncertifiable. Runtime evidence: `oracle-behaviour-root-untrack-default`. Stub: rc.17 shapes.
