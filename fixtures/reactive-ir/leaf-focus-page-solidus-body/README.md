# leaf-focus-page-solidus-body (ADR 1151 round 2, N1; the grammar is ADR 1154's)

**Claim.** an inline handler after a solidus on the body, `<body/onfocusin="hook()">` (the round-2 review's N1: HTML's tokenizer separates attributes by a `/` not followed by `>`, and Chrome 148 runs the handler as it runs one after a space). The first grammar read `/onfocusin` as the attribute's name and the proof fired: a false clean. The `focus()` in `onSettled` keeps ADR 0329's obligation unless the project's own HTML holds nothing but the program's module entries (`product_realm::page_may_run_code`: host discovery's grammar reads the page, every `<script>` is an entry, every entry is a file of the program, and no other page of the project can run code). Expected: the SC9012 at the call is **kept**.

On the build before the grammar fix (853e30b5c) the proof fired here (no SC9012 at the call): a false clean. A top-level fixture, not a variant: a project's HTML is read from its whole directory tree. The program itself (`App.tsx`) registers nothing.
