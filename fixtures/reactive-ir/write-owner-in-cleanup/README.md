# write-owner-in-cleanup

**Claim.** rc.17's write guards test `!disposalDepth` (`@solidjs/signals` `dist/dev-shared.js:5620-5626`), which `runDisposal` raises around every `onCleanup` callback (`:1314`). A signal write such a callback runs under a proven owner (`runWithOwner(getOwner(), …)`, `createOwner()`, `createRoot`), directly or in a `forEach`, lands: legal (`Cleanup*Owner*`, `CleanupCreateRoot`). A named function a cleanup hands on or calls is uncertifiable (`CleanupNamed*`, `CleanupCalls*`): its other callers are not read.

Controls (violations, rc.17 throws): an effect apply on a flush outside a cleanup (`EffectApplyUnderOwner`), a write the cleanup schedules or stores (`CleanupSchedulesWrite`; `CleanupStoresFunction` stores it in a memo cleanup, so a rerun then a click throws), a write in the body, a named root body in a body (`NamedRootBodyInComponent`), an action call (no `disposalDepth` test). Stub: rc.17 shapes.

Uncertifiable: an effect's returned cleanup (`EffectReturnedCleanup`, `RenderEffectReturnedCleanup`, `TrackedEffectReturnedCleanup`), since the cleanup also runs when the effect's owner is disposed, inside a disposal, and nothing orders that disposal against a rerun: a memo that tracks what its effect tracks disposes the effect first (`MemoHostTracksSame`, `MemoHostStoreSetterInRoot`), a `Show` turned off (`ShowHostNestedOwner`, `ShowHostRefreshInRoot`). The four fuzzer shapes are legal on rc.17 (Chrome and `@solidjs/signals` dev.js). A rerun that finds the owner alive does throw, and goes unreported (docs/open-work.md). Also uncertifiable: a function passed by name to `createRoot` in a cleanup (`CleanupNamedRootBody`, `CleanupConstRootBody`); an effect whose compute reads nothing, reads untracked, reads a signal nothing writes or only its own cleanup writes, so its cleanup may run only at teardown, in a disposal (`Effect*Cleanup*`, `TrackedEffectCleanupNoReads`); an effect created and flushed in a cleanup (`CleanupFlushesEffect`).

A write is legal only when the callback runs in the disposal and nothing else can run it: nothing else calls it (rc.17 returns the callback, so `const c = onCleanup(...); c()` and `onCleanup(...)()` in the body are violations, ADR 0456, `write-cleanup-handle-call`) and no await precedes the write (`AsyncCleanup*`, `AsyncForEachInCleanup`, `AsyncIifeInCleanup` throw: the owner is entered after the disposal ended). A fresh stack (`CleanupThen`, `CleanupMicrotask`) is a violation. A function a cleanup may run and no call site is read for (`HelperRegistersCleanup`, `AssignedThenCleanupCalls`, `ObjectMethodCalledByCleanup`, `DeclaredHelperFromCleanup`) is uncertifiable (`InlineHelperParameter` is legal: ADR 0457, a helper that calls its callback in its own body runs it in place); a stored function only an event handler calls (`CleanupStoresFunction`) is a violation. Other releases: `write-owner-in-cleanup-rc13` (violation) and `write-owner-in-cleanup-unread` (uncertifiable).
