# write-legality-proofs

**Claim.** A write past an await that dominates it (the rest of the await's block, `dominating_awaits`, ADR 0333) runs with no owner, so it is legal and reports nothing: the writes after `await` in a `try` block and in a branch's block. A read past a dominating await in a `createRoot` callback is past the strict-read window and silent, as the runtime is. Not proven, so SC2001 stays uncertifiable: a write in `catch`/`finally` (a synchronous throw reaches them unsuspended), after an await under a conditional expression, an instance field written past the await (it runs at construction), a JSX expression written past it (a compiler render effect runs it, owned), or a write in an async generator (a later `yield` lets the caller resume it under an owner; with or without `try`, the latter also fixing an older silence). Control: the write before the await is a violation. Stub declarations are copied from published rc.13.
