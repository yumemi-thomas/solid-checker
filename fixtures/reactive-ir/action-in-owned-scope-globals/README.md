# action-in-owned-scope-globals

**Claim (ADR 0973, the review of #231, B4).** A package whose closure names no Solid package is silent only when it reads no global the pinned libraries do not declare. The scan followed one member of the global object and stopped, and trusted a global-only declaration package by its manifest, so each way of reaching a global a Solid-reaching package provides was a false clean. Each uncertifiable case is Chrome-confirmed in the pattern lane (`patterns/pkgaction/win-self`, `win-doc`, `win-twice`, `types-global`, `types-global-project`, `window-aug`): `ACTION_CALLED_IN_OWNED_SCOPE` at the call in a component body, because `fz-pub` writes `window.__fzAct`.

- **The global object through its own members.** `WindowSelf` (`window.self.__fzAct`), `DocumentView` (`document.defaultView.__fzAct`) and `GlobalThisTwice` (`globalThis.globalThis.__fzAct`) are `package-may-call-action:unknown-global`, as `WindowDirect` (`window.__fzAct`) always was. `WindowSelfClear` stays silent: `window.self.setTimeout`, `window.self.document.defaultView.innerWidth` and `globalThis.globalThis.innerHeight` read only what the libraries declare.
- **A global a declaration file declares.** `TypesGlobal` (`@types/fz-glob`, a script of global declarations: `/// <reference types="fz-glob" />`), `ProjectGlobal` (`declare function` in `globals.d.ts`), `WindowMember` (`interface Window` adds `__fzAugAct`), `GlobalThisMember` (`globalThis.__fzProjectAct`), `ValueGlobal` (handed on as a value) and `AliasGlobal` (a binding that only names it) are `unknown-global`: the declaration does not say whether the host, a script or a package provides the global, and one here does. `HostMembers` stays silent: `matchMedia`, `body.append` and `setTimeout` are the standard library's. `TypesGlobalHandler` and `TypesGlobalTimer` are legal action sites.

- **A member the library declares too.** `OverloadByPackage` (`Uint8Array.from(() => {})` with `fz-over`'s overload in its declaration file, and code behind it that calls `action`) is `package-may-call-action:reaches-solid`: a member the standard library alone declares is the host's, one a package also declares is that package's (the re-check of #231 made the host a proof). `OverloadByProject` (`window.addEventListener("fz-ready", …)` with the project's own overload beside the library's) stays silent: no installed package holds code for it, and the host implements the member.

Not followed (`docs/open-work.md`): a sloppy `this`, a builtin prototype a package extends, the global object reached through a DOM object's typed member (`el.ownerDocument.defaultView`, `event.view`), a call of an `any` or untyped member of a global, a member a project declaration adds to a host global handed on as a value (`[…].forEach(window.__fzAugAct)`: no symbol is recorded for a property that is not called), and `declare global` written in a project source file.

`node_modules/fz-*` and `@types/fz-glob` are **not** published bytes: each is written for this fixture. `node_modules/solid-js` and `@solidjs/*` are the manifests of `action-in-owned-scope-unread-packages`; `.solid-checker/runtime.json` closes the program boundary.
