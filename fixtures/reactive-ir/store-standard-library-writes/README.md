# SC2003: standard-library writes and destructuring assignments of a store (ADR 0526)

`Object.assign(store, { v: 7 })`, `Reflect.set(store, "v", 7)`, `Object.defineProperty(store, "v", { value: 7 })` and a destructuring assignment whose leaf is a store member (`({ v: store.v } = { v: 7 })`, `[store.w] = [7]`) reach the proxy's `set` or `defineProperty` trap, which outside the store's setter warns `STORE_WRITE_OUTSIDE_SETTER` and stores nothing (`@solidjs/signals@2.0.0-rc.17` `dist/dev.js:5420-5451`, `:5691-5697`, `:5743-5749`; measured 2026-11-01 in every context outside the setter, no value committed). TypeScript accepts all of them. The callee must resolve, through Type Facts, to the standard library's `ObjectConstructor.assign`, `Reflect.set` or `ObjectConstructor.defineProperty`, and the first argument's root must be the store's bare identifier; a destructuring leaf is a write (no strict-read finding), its Get being the source object's.

Silent: the writes inside the store's own setter (through the original proxy or the draft), the store as a source rather than the target (`Object.assign({}, store, …)`), a write to a copy (`({ ...store }).v = 7`, `Reflect.set({ ...store }, …)`), a project object shadowing `Object` or `Reflect`, a project `assign` (handing the store to an unresolved member callee is another rule's obligation), and a shadowing parameter of a plain function. Uncertifiable: a target past the root (`Object.assign(store.o, …)`), whose link no fact proves wrapped (ADR 0465). Another store's setter does not write-enable this proxy: a violation.

The stubs are reduced byte-faithfully from `solid-js@2.0.0-rc.17` and `@solidjs/signals@2.0.0-rc.17` (`Store<T> = T`, the plain `createStore` overload), with `@solidjs/web@2.0.0-rc.17`'s manifest, so the dialect sees the audited release and the root write is this rule's (not TS2540).
