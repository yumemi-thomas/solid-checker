# flush-universe-package-hand-off-package-computed-key

**Claim (the second re-check of #232; ADR 0967 amended).** A package the program loads is asked, file by file to the end of its closure, what the analysis asks of the program's own files: does it name `Object.prototype`, build code as a string, read under a key nothing proves is none of the keys that hand out a prototype (`constructor`, `__proto__`, `prototype`, `Object`, `Reflect`, `Function`, `eval`)? `steplib` here is the original synthetic stub of the hand-off fixtures, whose `runNs` is `for (const k in ns) ns[k]()`: a `for in` variable holds whatever key `ns` has, so the read may hand out the prototype. The package then runs code the build does not see, so no holder of the program is confined (a package may give the prototype an accessor that reads any key through `this`) and every key may be read: `plainHolder`, a plain literal no use of which gives it a receiver, is asked of the name net, and the flush in it keeps its three uncertifiable rows (SC2006 `flush-in-action-unaccounted`, SC2008 `flush-in-effect-unaccounted`, SC3001 `leaf-operation-unaccounted`), never silence, never a violation. Chrome is quiet at the flush (the holder is plain and nothing reads `m`): that is the stated cost of failing closed on a package's own text.

**Twins.** The same plain holders against the stub the other hand-off fixtures ship are silent: `flush-universe-package-hand-off-receiver-confinement` (`twinHasOwn` and the plain holders above it), `…-receiver-reads-twins` and the others. That stub's `runNs` was rewritten to `Object.values(ns).forEach((f) => f())`, which reads no computed key, because those fixtures test hand-offs and the prototype rule, not a package's own text; this fixture keeps the original so the conservative behaviour stays tested (the coordinator's ruling, 2026-11-14).

Published bytes: `node_modules/steplib` is synthetic (the hand-off fixtures' stub as it was before that rewrite); `@solidjs/web/types/index.d.ts` is the same excerpt as theirs. `.solid-checker/runtime.json` closes the program boundary.
