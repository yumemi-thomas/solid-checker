# flush-universe-package-hand-off-accessors

**Claim (the review of #222's check 3, R1 and R2; ADR 0967 amended).** An accessor runs where it is read, not where its value goes. A flush that an installed package the build does not read as source (`steplib`, as in `flush-universe-package-hand-off-causes`) may run as an action's step keeps its three uncertifiable rows (SC2006 `flush-in-action-unaccounted`, SC2008 `flush-in-effect-unaccounted`, SC3001 `leaf-operation-unaccounted`): never silence, never a violation.

**R1.** The compiler makes a component's child or prop expression a getter of its props object. A project component that reads the prop in a step the package runs (`runStep(() => { void props.children; })`, from its own timer) runs the expression there, whatever it does with the value. `stepChildCall`, `StepChildElement`, `destructuredChild` (`const { children } = props` in the step), the flush written in `DirectReader`'s child expression, and `renderProp` (a `render` callback handed to `steplib`'s `Pkg`) keep three rows each. Before this, a project component's first parameter was followed by value only, and a read whose value goes nowhere is inert there.

**R2.** An object literal's getter runs where a member of the object is read: `getterObject.g` read through `readsInStep`'s parameter in a step keeps three rows. Before this, the getter was followed as a function value, which a member read does not move.

**Twins, silent.** `twinBodyChild`: `BodyReader` reads its children in its own body, which runs where its element is created (a timer's callback). `twinTimerChild`: `TimerReader` reads them in a timer's callback. `twinGetterObject`: the getter is read through a parameter in a timer's callback.

Published bytes: `node_modules/steplib` is synthetic, as in the causes fixture; `@solidjs/web/types/index.d.ts` is the same excerpt. `.solid-checker/runtime.json` closes the program boundary.

**The review of #226.** B1: `selfNamed` (a getter that names its own object, read in a step: three rows) and `Tree` (a component that renders itself, passing a prop on inside a nested arrow; it never reads `x`, so `treeHelper` is silent) each made the accessor walk re-enter itself until the stack overflowed (exit 134, no report); the walk is now one, and both end (the process test `accessor_walks_end_on_self_reference_and_keep_their_rows` runs this fixture). B2: `typeofChild` (`return <Frame>{typeof props.children}</Frame>`: the package's component evaluates the expression in its step) and `classFieldChild` (a props read in a class field initializer, run when the class is made in a step) keep three rows each. B3: `thisReader` (a getter read through `this` in its own literal's method, in a step) keeps three rows.

**The re-check of #226.** N1: a method call on an object of accessors binds `this` to it. `outerShorthand` (`m: fn` written outside the literal), `outerProperty` (a function expression bound to a const), `assignedMethod` (`o.m = fn` after the literal) and `propsMethodChild` (a component calling `props.pick()` with `pick={fn}`) read a getter, or a prop, through `this` in a step the package runs: three rows each. N2: `pickHelper` (one callback returns the flushing function or the object of accessors, read in a step) keeps three rows. Twins, silent: `inlineFree` (an inline method that never names `this`, and a data member; the getter is read in a timer), `twinPickHelper` (the picked object read in a timer).

**The re-check 2 of #226 (`super`).** `super.x` reads the prototype's member with the object as `this`: `superBase`'s getter `x` reads `this.g`. `superAccessor` (a getter holding `super` in a closure a package runs, read in a timer: no member call, silent before), `superMethod` (a called method holding it: P570) and `superSibling` (an uncalled sibling holding it beside a called method that never names it: P593) keep three rows each: a literal that holds `super` is handed as one that holds `this` is.

**ADR 0971 (B2).** The `<StepChildElement />` written in `StepElementReader`'s children (line 39) is a JSX creation in a component's getter, a site of the owner-call universe: it also keeps an SC3001 `leaf-operation-unaccounted` and an SC6002 `effect-creation-unaccounted` uncertifiable row (decline `getter-runs-where-read`: the checker does not prove where `StepElementReader` reads its children), beside the flush rows; no violation.
