# flush-universe-package-hand-off-holder-param

**Claim (ADR 0967 amended; the neighbours of the review of #229, B2).** A function stored through a parameter's member (`target.m = function () { flush(); }`) is stored into the object the callers pass. The walk followed the reads of the parameter inside the function and never the caller's argument, so the later read of the holder by the caller's own name (`o.m()`, in a closure an installed package runs) was invisible: the flush was certified with no row, and Chrome (rc.21) reports FLUSH_IN_ACTION (`scripts/fuzz/patterns/pkghand/put-param-step`, `put-param-any-step`, `put-chain-step`). No receiver (`this`, `super`) is written in this program. When every use of the function is a direct call the build resolves, the holder is each call's argument, followed like a store into it (a name: the reads of its binding, through the parameter of an outer function and a copy of the name too; a fresh object literal: nothing else reaches it). Any other use of the function (a copy, an argument, a tag), an export a program may enter, a function no binding names, a parameter that is a pattern or a rest: the callers are not known, and the store is handed. `steplib` (its source is not read: its manifest names no Solid package, as in `flush-universe-package-hand-off-receivers`) runs the closure as an action's step, so each flush keeps its three uncertifiable rows (SC2006 `flush-in-action-unaccounted`, SC2008 `flush-in-effect-unaccounted`, SC3001 `leaf-operation-unaccounted`): never silence, never a violation.

**The cases.** `putTyped` and `putAny` (the one call, a typed and an `any` holder), `putChain` (the argument is the parameter of an outer function), `putCopy` (the holder passed by a copy of its name), `putArrow` (an arrow bound to a `const`, a rest parameter after the holder), `putPattern` (the parameter is a pattern: the callers are unknown to this walk, so the store is handed).

**Twins, silent.** `twinFresh`: the argument is a fresh literal, nothing reads it. `twinTimer`: the holder is read on a timer's stack by a member nothing calls (a call of a member nothing resolves to one function is handed: the stored function may name a receiver).

Published bytes: `node_modules/steplib` is synthetic, as in the causes fixture; `@solidjs/web/types/index.d.ts` is the same excerpt. `.solid-checker/runtime.json` closes the program boundary.
