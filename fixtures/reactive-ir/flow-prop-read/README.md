# flow-prop-read

Claim (ADR 0892, review D20): on rc.21, a read written in `Show`'s or `Match`'s `when` or `For`'s `each` is held by the component's own computation, which rules out SC5001 only; SC5003 keeps its claim. No SC5001 row: `ShowWhen`, `ForEach`, `MatchWhen`, `Covered`, and `OpenMemoShow`, the one read no producer has a row for, which keeps its SC5003 `async-read-unaccounted`. Not held: `StaticMarker` (a comment: the compiler passes the value raw, SC5001 violation), `MatchAlone` (no `Switch`: `async-read-unaccounted`), `FunctionBetween`, `LabelledUntrack` (review R40: an argument of a call). `ElementBetween` and `SpreadOnTag` are not held either; they keep the rows they had, an SC5003 uncertifiable. `DroppedElement`: a flow element that is no JSX child and no component's return may never render (Chrome rc.21 is silent), so SC5003 is uncertifiable, not a violation. The full rc.21 triple is stubbed: the question is rc.21's.
