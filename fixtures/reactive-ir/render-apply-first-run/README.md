# render-apply-first-run

**Claim (ADR 0503).** On rc.17, `createRenderEffect(compute, apply)` runs its first `apply` during the call under the caller's owner unless `defer` or `schedule` is set, the first pass is staged or lane-seated, the compute errors or goes pending, or a boundary above shows its fallback (`@solidjs/signals@2.0.0-rc.17` `dist/dev.js:1851-1869`). A component rendered by a module-scope `render(() => <C />, …)` (`@solidjs/web` `dist/web.dev.js:542-568`) runs its body outside every flush, lane, transition and boundary, so with no options and a compute that settles on its first pass (no call, read or reference), a write in the apply throws `REACTIVE_WRITE_IN_OWNED_SCOPE`: `no-write-in-pure-computation` is a violation. Violations: `FirstRunWrite`, `FirstRunWriteLayered` (a closure the apply calls). Uncertifiable (ADR 0460 unchanged): `Unmounted`, `Scheduled` (ADR 0502), `OptionsVariable`, `ComputeReads`, `ConditionalEffect`, `Hydrated` (`hydrate`), `RenderedLater` (`render` inside a function), and from the ADR 0503 review `ComputeImports`, `ComputeThenable`, `ComputeDestructures` (a compute that is no single primitive literal: a promise, a thenable, a throwing parameter), `Replaced` (a `let` reassigned before the render), `InClassField` and `UnderCondition` (a render not on every module run).

Stubs: `@solidjs/signals` and `solid-js` as in `primitive-in-effect-callback` (rc.17 published declarations), `@solidjs/web` and `jsx.d.ts` as in `setter-in-render-root`.
