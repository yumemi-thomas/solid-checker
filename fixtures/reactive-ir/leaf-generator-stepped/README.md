# leaf-generator-stepped

**Claim (ADR 0961, batch-10 addendum 12 group B).** Calling a generator runs none of its body: the body runs where an iterator of it is stepped. A leaf callback (`onSettled`, `createTrackedEffect`) that keeps the iterator a call returns (`.next()`, a `for…of`, a spread, `Array.from`, a stored loop, `yield*` through another generator, an async generator's `.next()`) may run the body in the leaf scope, where Chrome (rc.21) throws `[PRIMITIVE_IN_FORBIDDEN_SCOPE]` at a creation in it. The leaf walk treated a generator call as complete with nothing in it, so the program was certified clean; no walk follows the stepping, so the call is an uncertifiable row of SC3001 (`generator-stepped`, the premise SC1002 names for the same shape, ADR 0820), never a violation and never silence.

`App.tsx`: `Next`, `ForOf`, `Spread`, `FromArray`, `StoredLoop`, `Delegated`, `AsyncNext` (rows). `Plain` (the plain function: a violation). Silent: `Discarded` (a call a statement discards runs none of the body), `Quiet` (a generator with no call in its body has nothing to run), `InHandler` (stepped outside a leaf scope). The creation in `makes` is also an SC6002 uncertifiable row (`function-run-unplaced`, ADR 0961's generator net: an effect's apply may step the generator too).
