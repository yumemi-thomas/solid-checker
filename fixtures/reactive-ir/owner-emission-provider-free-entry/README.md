# owner-emission-provider-free-entry

**Claim (ADR 1142).** A read of a provider-free context (`createContext<T>()`, no provider in the program) in a function the owner graph shows an owned context for is SC4002's claim for that run: the owned run throws `ContextNotFoundError`. The owned context is the edges the graph holds (ADR 0868). A function entered by a route none shows (a reference carried on by `[f].forEach((g) => g())`, stored, handed to a project call, a member of an object, imported and carried in another file) may also run the read with no owner, where Solid throws `NO_OWNER_CONTEXT` before it looks for a provider. That run is SC4001's, and it is an obligation beside the claim (`owner-callers-unenumerated`). The arm that decides a read of a context WITH a default asked this entry test already (`root-owned-entry-open`, `named-layer-entry-open`); the provider-free arm took the owned context for every run and answered SC4002 alone, so Chrome's second code had no row at all (a certified false clean, found by the fuzz context `barm-carried-handler`, mx-census CONTEXT_NOT_FOUND).

| site | rows | why |
|---|---|---|
| `CarriedHandler`: the effect's compute is `f1`, the click's `forEach` carries `f1` on | SC4002 violation + SC4001 uncertifiable | the effect's owned run throws `ContextNotFoundError`; the click calls `f1` with no owner (`NO_OWNER_CONTEXT`, Chrome rc.21). **The false clean this fixes**: main had the SC4002 row alone |
| `CarriedBody`: the same carrier in the body | same | the owner pass does not follow a call through the carrier's parameter, so it cannot say where the call runs (the named cost: Chrome reports `ContextNotFoundError` alone, the body's owner is current at the carried call) |
| `Stored`: `kept = f3`, the handler calls `kept?.()` | same | the stored value's calls are not followed (Chrome: `NO_OWNER_CONTEXT` at the click). **False clean on main** |
| `Helper`: `run(f4)`, a project helper that calls its parameter | same | a project call's parameter holds no edge (Chrome: `NO_OWNER_CONTEXT`). **False clean on main** |
| `Member`: `{ run: f6 }`, the handler calls `box.run()` | same | an object member holds no edge (Chrome: `NO_OWNER_CONTEXT`). **False clean on main** |
| `OwnedCallCarried`: the body calls `f7` and a handler carries it on, no effect and no providing region | same | the owned context comes from the call edge alone (arm `named-layer-entry-open`); the body's call throws before the button exists, so Chrome reports `ContextNotFoundError` alone |
| `ImportedHook` (`Hook.tsx`): `useHookValue` is the effect's compute and a handler carries it on | SC4002 violation + SC4001 uncertifiable at the read in `Hook.tsx` | the reference that escapes is in another file than the read (Chrome: `NO_OWNER_CONTEXT`). **False clean on main** |
| `Timer`: `setTimeout(f5)` | SC4002 violation + SC4001 uncertifiable (`owner-unproven`) | the graph holds an edge for a timer's call (a fresh stack, no owner): the obligation stood on main already |
| `EntryOnly`: the effect is the function's only entry | SC4002 violation | nothing else references `f8`: the effect's owner is current at every run |
| `InlineBody`: `[1].forEach(f9)` | SC4002 violation | an inline run on the body's stack, under the body's owner (not a carried one) |
| `Probed`: the read is under `if (getOwner())` | SC4002 violation | the handler's run, with no owner, skips the read: the probe proves the owned run alone |
| `Defaulted`: a context WITH a default, carried the same way | SC4001 uncertifiable | the other arm: the owned run returns the default, so no SC4002; its obligation stood on main already |

The program is closed (the `private` manifest), so SC4002 is a violation. In an open program it is the provider-open obligation, and the SC4001 obligation stands beside it the same way. Not claimed: where the carried call runs (a proof of the carrier's call would turn the `forEach` pair's rows into the one that is right for each place: a violation in a handler, none in the body), and the ADR 0577 pair (`context-default-undefined`, `HandlerMixed.tsx`: a direct call in a handler, where the graph holds the edge). Chrome (rc.21, the pattern lane's host and the fuzz grids' judge): `scripts/fuzz/patterns/owner-entry/{carried-handler,stored,helper,member,imported}` (the click's `NO_OWNER_CONTEXT`; main: false clean at `carried-handler`, `stored` and `helper`, the other two covered through an application frame of the stack; this build: none) and mx-census CONTEXT_NOT_FOUND `barm-carried-handler` (ADR 1124 round 2's context: main `secondary-false-clean`, this build `recall-gap`). The oracle runner (`fixtures/runtime-oracle`) has no case: it reads a logged `ContextNotFoundError` as no diagnostic, so it would call the effect compute's SC4002 violation static-only.
