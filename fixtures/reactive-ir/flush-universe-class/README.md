# flush-universe-class

**Claim (batch 11, slice 5, the review of #213: B1 and B2).** The census class of the code around a flush (`FreshStack`, `AwaitContinuation`, `TestRunner`) says where the function around it runs, and ends all three codes only when it is a statement about the flush's own stack: the flush is written in the *body* of its function (a default value in a parameter list runs wherever the function is called, which the class of the code around it does not say: B2), and, for a scheduler's or a runner's callback, no function around it is a named function expression its own code uses (`setTimeout(function tick() { flush(); … tick(true) })` enters `tick` again on the stack of whatever calls the name, an action's step or an effect's apply: B1). Chrome (rc.21) reported FLUSH_IN_ACTION and FLUSH_IN_EFFECT_CALLBACK at those flushes while the checker certified them with a typed reason `FlushSafe::FreshStack` (and on main with no accounting at all); the fuzz cells `fc-*` (`scripts/fuzz/fc-shapes.mjs`) and `scripts/fuzz/patterns/flushclass` hold the shapes.

`App.tsx`: the program steps an action, runs an effect's apply and opens a leaf scope, so no program-wide reason holds. `Again`, `Each` (a carrier's named callback), `Default` (a default run in an apply) and `Awaited` (a default written after an `await`) each have an uncertifiable row of each code (twelve rows: `flush-in-action-unaccounted`, `flush-in-effect-unaccounted`, `leaf-operation-unaccounted`; at a default the SC2006 row is the producers' own `parameter-initializer-unplaced`, ADR 0961, so ten of the twelve are the accounting's), never a violation (nothing here proves the second run happens). Silent: `Once` (a named expression whose name nothing uses), `Direct` (the flush directly in the timer's callback) and `After` (past the await), each on a typed reason (`FreshStack`, `AwaitContinuation`). A reviewed test runner's callback has the same two conditions: `flush-universe-test-runner`.
