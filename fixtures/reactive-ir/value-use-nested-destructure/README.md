# value-use-nested-destructure

ADR 1218 (facts schema 111): a pattern nested in a `const` declarator's object pattern (`const { a: { useIt } } = { a: { useIt: count } }`) takes the value at its key of the declarator's closed literal, as a one-level destructure does: the value-use census follows `useIt` as the accessor, with no SC9012 `value-in-carrier` row. Negative: `NestedMemo` (no SC9012 row; its SC3001, SC6002 and SC4001 rows are the open program's creations, as in every fixture of this shape). Positive: `NestedBody` (the untracked call in the body keeps an SC9012 row). A store's holder stays escaped (`NestedStoreMemo`: its carrier rows as before; followed as a root alias, its Get in the memo would take a row). Controls that stay carriers (`value-in-carrier` rows, as before): `SpreadLiteral`, `RepeatedKey` (a computed key in the literal that may repeat `a`), `RestPattern`, `LetDeclarator`, `TwoLevels` (only one level of nesting is a destructure site).
