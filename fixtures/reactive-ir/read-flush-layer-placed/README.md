# read-flush-layer-placed

Claim (ADR 0859): a read in a layer that runs in place inside `flush(fn)` (an IIFE) is placed as a read directly in `fn`: where the `flush` call runs. Chrome (rc.21) is silent in `InJsxEach`, `InJsxCall`, `InJsxDirect` and `InMemo`. `InJsxEach` and `InJsxCall` were SC1001 false positives: uncertifiable now, as `InJsxDirect` always was, since the helper's run is not placed. `InMemo` has no row. `HelperInBody` warns in Chrome; a helper's call is not the proof that the IIFE runs in the body: uncertifiable, was a violation. `InBody` stays a violation. `RunAndKept` (review R15): the in-place run is tracked, the kept run is in the body, Chrome warns; the in-place run clears nothing: uncertifiable. Stubs: rc.21's `solid-js`, `@solidjs/signals` and `@solidjs/web` versions; `solid-js.d.ts` as strict as the published typings for what it calls.
