# action-plain-yield-layers

**Claim (ADR 1047).** An action's stepped generator goes on at once, on the same stack, after a `yield` of a value that is not a thenable: `@solidjs/signals@2.0.0-rc.21`'s `run` steps again with `inTransaction(t, q, () => step(r.value))` (`dist/dev.js:2365`), and `isThenable` holds only for an object (`dist/dev-shared.js:3727`). So a call written after such a `yield` runs on every completion of the step as one before it does, and a function it calls in place (an IIFE, a closure) runs under the action's caller's owner. Each action here is called from an effect's apply (no owner): the effect created in the IIFE or closure is NO_OWNER_EFFECT, a proved SC4001 (uncertifiable, `function-run-unplaced`, before).

Proved: `IifeAfterNumber` (`yield 1`), `ClosureAfterString` (`yield "step"`), `AfterBareAndLiterals` (`yield;`, `yield null`, `yield true`). Uncertifiable as before: `ConditionalAfterYield` (the call after `yield 1` is under a branch, so its edge proves no run) and `NotAnAction` (a generator no action steps, stepped by hand). Proved on main already, by another route: `AfterBinding` (`yield p`), `AfterDelegate` (`yield*`) and `AsyncGenerator` (an `async function*`) may resume from a continuation, which has no owner, as the apply has none: unowned either way. `ShadowedName` (`yield NaN` with a local `NaN` bound to a promise) joins them: main took the name for the number and the step for a synchronous one (`function-run-unplaced`); it is now a possible thenable like `yield p`. Chrome rc.21: oracle case `action-plain-yield-layers`.

Stubs: rc.21 package versions (`node_modules`, as `dead-literal-rows`); `solid-js.d.ts` as `owner-invoked-literal`.

ADR 1051: each action here is called from a `createEffect` apply, and those whose first statement is a plain `yield` (`a1`, `a2`, `a3`, `a8`: lines 16, 31, 47, 124) also carry SC2008 at the call: the resumed step flushes inside the running queue, and Chrome rc.21 warns FLUSH_IN_EFFECT_CALLBACK there.
