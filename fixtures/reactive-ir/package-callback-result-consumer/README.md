# Callback-result provenance consumer

Written to pin an authored contract's result-use census: fresh primitive results and getter-free literal objects would close only the described result uses (`PrimitiveNegative`), `ProducerViolation` and `ExactReturnedArrowViolation` be write violations, `ExactReturnedArrowClean` stay tracked, and dynamic values, proxies, getters, spreads, escapes and wrappers (`OpenResults`, `WrapperOpen`) stay SC9012. Package contracts are removed (ADR 0312), so none of that is read. Today the snapshot holds an `SC1001` `strict-read-untracked` uncertifiable result at each of `ExactReturnedArrowViolation` and `ExactReturnedArrowClean` (the read inside the returned arrow), plus the SC9014 notice for the rc.0 stub; every other component is silent. The fixture no longer separates the cases it was written for. The `solid-reactivity.json` beside the stub is inert.
