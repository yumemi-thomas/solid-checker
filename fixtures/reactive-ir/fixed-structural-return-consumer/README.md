# Fixed structural return consumer controls

Written (ADR 0172, 0282) as controls over stable tuple and object constructors under carrier contracts: bad reads would report, good object reads in JSX stay clean, and replaced, rebound or deleted members or an unknown mutator drop the reactive identity. Package contracts are removed (ADR 0312), so the carriers are not read. Today the stub is rc.9 `solid-js` with the SC9014 notice, and each component that passes a `createOptimistic` accessor to `pair` or `record` gets an `SC9011` `reactive-source-uncaptured` uncertifiable result at that argument, including `GoodObject`; `ReplacedTupleMember` and `DeletedBrandedMember` also get `SC9012`. The good/bad distinction is no longer pinned. The stub preserves rc.9's branded `Refreshable<Accessor<T>>` first slot; `App.tsx` has no diagnostics against published rc.9. The `solid-reactivity.json` beside the stub is inert.
