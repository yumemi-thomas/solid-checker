# flush-holder-put

**Claim (ADR 0980; the review of #232's B6).** A store through a parameter's member (`function put(t) { t.m = function () { flush(); }; }`) is stored into the object the callers pass, and is followed to each caller's argument (ADR 0967 amended, `flush-universe-package-hand-off-holder-param`). It was followed under the name written at the call, and the callers were taken from a list that was no census. Now the store is followed only when all three hold, and handed otherwise: the parameter is sole-named inside the function (a plain identifier no assignment reassigns, every use the object of a member access or an operand nothing takes: no `const s = t`); the callers are all known (`package_hand_off/callers.rs`: every reference of the function's binding, in every file, is a direct call, and a binding a method, an expression nothing names, a reassigned binding or an export the program may enter has no list); and each caller writes the argument (no default value, omitted argument or spread at or before the index carries the holder) as the name of a binding that is sole-named except for that call (`flush-holder-alias`). Any other store is handed: `steplib` runs the closure as an action's step, so the flush keeps its three uncertifiable rows (SC2006, SC2008, SC3001), never silence and never a violation.

**Positives (9 sites silent on main).** B6(a): an alias passed as the argument, a parameter of the caller that holds a copy, a class instance passed by another name; B6(b): `const s = t` inside the function, the parameter reassigned to another parameter (the store goes into the second argument); B6(c): a default value receives the store (`put()` with `t = shared`), a spread stands before the index; B6(d): a method of an object literal; a member of another object as the argument.

**On main too (6).** The argument is a call's result (a project function, a package's `id`), the function is a function expression nothing names, one caller is an argument (`forEach(put)`), the holder is sole-named and the step reads the member, the argument is the parameter of an outer function (`putChain`; the ratchet).

**Negatives, silent (4).** The argument is sole-named and the step never reads the member (a chain of two functions too), no package step at all, a fresh object literal is the argument.

Published bytes: as in `flush-holder-alias`.
