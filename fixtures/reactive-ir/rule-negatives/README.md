# rule-negatives

**Claim.** The correct-code examples of six rule pages report nothing for their rule: `reactive-read-after-await` (SC1002, reads before the first await; the post-await dependency in its own memo), `no-destructure` (SC1003, props read through the object, `omit`/`merge`, destructuring inside a memo), `components-return-once` (SC1004, one JSX tree with `<Show>`), `jsx-no-duplicate-props` (SC8003, one content mechanism; `innerHTML` as a component prop), `reactive-source-uncaptured` (SC9011, a package function given a value, the accessor given to a project function or a timer) and `valid-use-server` (SC7006, a `"use server"` module exporting functions directly). A `filter` callback in a memo is placed by the compiler's resolved standard-library signature, even when the receiver is a memo's result (`posts().filter(…)`), so its read is tracked and silent. No rule reports a violation here. SC5003's negative needs a `render` root, which this stub (`@solidjs/web` is a `jsx-runtime.d.ts` stub, hence SC9014) does not declare. Published rc.13 declarations copied from `standard-runtime-configuration`; `plain-log` is a package naming no Solid dependency.
