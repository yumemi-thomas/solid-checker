# context-package-hop

**Claim (ADR 0949).** A compiled package renders its subcomponents with `createComponent(Inner, props)`: the call names `Inner` as an argument, not as a callee, so no call edge and no tag enters `Inner`, and the project's call of the package's exported component reached the read only through that hop. Before ADR 0949 the package finding in `Inner` (SC4001 `function-run-unplaced`, a `useContext` read of a context created with no default) was dropped and the project call got no row: certified clean, while Solid threw `ContextNotFoundError`. Chrome (rc.21 development build): `CONTEXT_NOT_FOUND` for `Hop`, quiet for `ProvidedHop`.

`App.tsx` (package `node_modules/dep-hop`, a synthetic package of this fixture): `Hop` calls `Panel({})`; `ProvidedHop` calls `Provided({})`, which provides the context itself before it renders `Inner`.

Rows, all uncertifiable and none a violation: an SC9012 obligation at each call (`Panel({})`, `Provided({})`: the package's `props` argument reaches code the analysis does not follow), and an SC4001 `package-finding-at-entry:SC4001` at the project's import of the package. The import row is the project-level fallback: no project site is proven to enter `Inner`, because the call that reaches it is `createComponent(Inner, …)` inside the package, which names `Inner` as an argument, no callee. The provider above the hop in `Provided` is not followed, so the quiet twin is not certified clean either: precision is traded for the zero false clean (docs/open-work.md). The build before ADR 0949 certified both clean (0 rows).
