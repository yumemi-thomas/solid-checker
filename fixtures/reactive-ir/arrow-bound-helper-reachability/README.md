# arrow-bound-helper-reachability

**Claim.** An arrow or function expression bound to a single-identifier `const` is reached by calling that binding, as a declaration is by its name (`let`/`var` are not exact bindings), so its body runs wherever its callers run. Reachability grants no owner and no role: a declaration's classification judges it.

Violations (declarations `declaredAction` and `bumpDeclared` are same-finding controls): `SC2002` for an action called in an arrow, expression, named-expression and chained helper run in a component body; `SC2001` for a setter, `SC1001` for a read, in an arrow helper. Silent: a helper whose only caller is an event handler, a helper nothing calls, a same-named `const` or local arrow shadowing the module helper, and a reassigned `let` helper (a call through it may reach either function).

Temporal dead zone (ADR 0339). A reference proves execution only where it follows the declarator: in the same body after it, in a function expression or arrow created after it, in a module-level declaration when nothing running ahead of the declarator can call that declaration and the module is on no import cycle, or from a module that imports the declaring one and the declaring one cannot import back. `Tdz.tsx` pins the rest as silent or uncertifiable: a call from a hoisted declaration run by `createRoot` at module init, a nested arrow called before its declarator (write and action), a `var`, a conditional initializer, a destructured binding and a call-result initializer; `cycle-a.ts`/`cycle-b.tsx` pin the import cycle. Positive controls: a hoisted nested declaration, an arrow created after the declarator, an arrow or nested declaration written before it whose every mention follows it, a module-level declaration calling an earlier arrow, and `provider.ts`/`consumer.tsx` across a one-way import.

Stubs: published solid-js rc.13 typings; `SC9014` is the missing `@solidjs/signals` install.

Round two: `SwitchScope.tsx` and `ModuleSwitch.tsx` (a declarator written directly in a `switch` case is withheld, from the facts' `in_switch_case`, not from source text), `Wrapped.tsx` (mentions come from the compiler's reference index: `go!()`, `(go as F)()`, `(go satisfies F)()`), and `barrel-b.ts`/`barrel-c.tsx`/`barrel-d.ts` (an importer on an import cycle is not ordered after the declaring module, though the declaring module imports nothing). `arrow-bound-helper-module-loads` pins loads the graph must order.

Round four: a direct `eval` in a file withholds every mention of its bindings and makes every function-valued binding's value unproven (`EvalCaught.tsx`, `EvalRoot.tsx`: `eval("App()")` runs a component before `late` exists; `EvalReassigned.tsx`: `eval("go = () => {}")` rebinds the callee). `App.tsx` and `Tdz.tsx` are the eval-free controls with the same shapes. `arrow-bound-helper-module-loads` adds a JS bridge with no declaration file, loads written after their use (`early-main.ts` against the `early-control.ts` positive), and wrapped `require` callees.

Round five (ADR 0339 as an allowlist): only a hoisted declaration whose binding is never written, a `const` or `let` (by source position), and an import ordered by module evaluation are credited; everything else is withheld. `EvalReassignedComponent.tsx` withholds a component or exported root whose binding may be written (a direct `eval` in the file included; `ExportedComponentControl.tsx` is the positive). `ArrowDefault.tsx`: a default parameter initializer that is more than a literal runs before the body and may throw, so mentions of the function are withheld (facts schema 70, `parameters_inert`; `Control` with a literal default is the positive). `VarSkipped.tsx`: a `var` is initialized only if its initializer executed (loop, branch, caught throw), so it is never credited.

ADR 0506: `Tdz.tsx`'s `WrappedInitializer` arrow (`wrap(() => setCount(8))` at module scope) is now reached (an argument of a call), and its write is uncertifiable: `wrapped()` holds the call's result, so it places no write.
