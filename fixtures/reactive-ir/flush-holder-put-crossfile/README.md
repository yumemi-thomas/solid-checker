# flush-holder-put-crossfile

**Claim (ADR 0980; the review of #232's B6(e), a false clean on main under `--program-boundary closed`).** `exact_callers` listed the callers of a function from `foreign_reference_hand_offs`, which skips a reference the call graph holds (a direct call from another file), returns an empty list on a missing name or symbol and skips a reference whose file is missing; the walk read each of these as "no other caller". A store through a parameter (`export function putN1(t) { t.n1 = function () { flush(); }; }`) called from another file (`putN1(o)`, then `runStep(() => { o.n1(); })`) was certified with no row, and Chrome reports FLUSH_IN_ACTION. `exact_callers` (`package_hand_off/callers.rs`) now lists every reference of the binding in every file or has no list: a direct call is a caller, an import's uses are followed under its local name, and a use that is no call (a re-export from another module, an export specifier, a tag, an argument), a missing symbol, reference list or file, a method, a reassigned binding, an export a program may enter and a namespace that hands the function out by name give none. A store with no caller list is handed: `steplib` runs the closure as an action's step, so each flush keeps its three uncertifiable rows (SC2006, SC2008, SC3001).

**The cases (closed boundary, every flush uncertifiable).** N1 a named import; N3 `export { putN3 } from`; N4 `export *`; N5 a default export; N6 `await import()`'s destructuring; N8 the call in a third file (`relayN8(holder)` calls `putN8(holder)`; the import chain is followed through the third file's parameter).

**Twins, silent.** `twin` (a named import, the holder sole-named, the step never reads the member) and `twin2` (the same through a third file): the callers are all known, so the store is followed, and nothing a package runs reads it. `flush-holder-put-crossfile-open` is the same program with `--program-boundary open`: the exported function may be entered by code this build cannot see, so both the case and its twin stay uncertifiable (as on main).

`n6-put.ts` also gets an SC2003 row at the declaration on every build (the dynamic import hands the module's namespace out). Published bytes: as in `flush-holder-alias`.
